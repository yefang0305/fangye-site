我最近越来越明显地感觉到一件事。

很多人说自己已经在用 AI 了，但其实还停在一个很浅的阶段。

遇到问题，打开豆包、DeepSeek、ChatGPT，问一句“这个怎么做”。AI 回你一段步骤，你照着做。不会写方案，就让它列个大纲。不会做表格，就让它说一下字段。想了解一个行业，就让它总结几段。

你说这有没有用？

当然有。

我一点都不反对这种用法。对很多普通人来说，这已经比过去满世界搜网页、翻教程、拼答案强太多了。

但问题是，如果你对 AI 的理解一直停在这里，它其实还只是一个更聪明的搜索框，或者一个坐在旁边给建议的顾问。

顾问会告诉你怎么做。

但真正复制文件、整理资料、改表格、跑命令、检查结果的人，还是你自己。

Agent 不一样。

Agent 的核心变化在于，AI 已经不止停在给你建议这一步，它开始进入你的工作现场。它能读你的文件，调用工具，执行步骤，遇到问题再调整，最后把一个结果交付给你。

![Chatbot 和 Agent 的区别](/images/agent-beginner-tutorial/01-comparison-chatbot-agent.png)

这也是我觉得普通人接下来一定要搞懂 Agent 的原因。

这跟它听起来高不高级没关系，也不是说所有人都要马上变成程序员。我真正看重的是：这是 AI 从“聊天工具”变成“数字员工”的关键一步。

这篇文章就从零开始讲。

你不需要有编程基础。看不懂的名词，先不用慌，截图丢给豆包问也行。真正重要的是，你要把这条主线想清楚：

> Chatbot 是会聊天的 AI。
>
> Agent 是会干活的 AI。

后面所有内容，本质上都围绕一个问题展开：

怎么让 AI 真的帮你把事情往前推，别永远停在给你一堆建议上。

## 第一部分 看懂 Agent

### 第 1 章 Agent 到底是什么

#### 1.1 一句话定义

先给一个最简单的区分：

```text
Chatbot（聊天机器人）= 能说，不能做
Agent（智能体）      = 能说，也能做
```

你跟 ChatGPT 说：“帮我订一张明天去上海的机票。”

普通聊天机器人会怎么回？

它大概率会告诉你：

> 你可以打开携程、飞猪或者航司官网，输入出发地、目的地和日期，然后对比航班价格。

这当然没错。

但它说完就结束了。

真正打开网页、查航班、对比价格、填乘机人信息、停在付款前等你确认的人，还是你。

Agent 的差别就在这里。

如果是一个真正的旅行 Agent，它会自己打开浏览器，搜索航班，筛选时间，比较价格，甚至把可选方案整理好。到了付款这种不可逆操作前，再停下来问你一句：“这班可以吗？要不要确认？”

你看，前者是在回答问题，后者是在推进任务。

这就是 Agent 和 Chatbot 最核心的区别：

> 一个只会告诉你答案。
>
> 一个会替你把事情往前做。

#### 1.2 用合同再讲一遍

比如你手里有一份合同模板，里面有很多空白字段。

你问普通 AI：

> “这份合同应该怎么填？”

它会告诉你：

> “甲方这里填公司名，乙方这里填个人或公司名，日期这里填签署日期……”

它说得都对，但你还是要自己打开文档、复制粘贴、检查格式。

如果是 Agent，它可以直接读取合同模板，识别哪些字段是空的，再根据你给的资料填进去，最后生成一份新合同，让你检查。

这就不是“告诉你答案”了。

这是“帮你把事情做完”。

#### 1.3 一个关键认知：AI 自己其实啥都干不了

很多人一听 Agent，就以为它是“更聪明的 AI”。

这句话不能说完全错，但容易误导。

Agent 很多时候用的还是同一个模型。Claude、GPT、Gemini、豆包、DeepSeek，本质上都是大语言模型。真正的区别在于它有没有手脚。大脑还是那个大脑，并没有突然变成神。

更准确地说：

> AI 大脑本身只能处理文字、输出文字。
>
> 所谓“调用工具”，本质是 AI 输出一段特殊格式的指令，说“我要用某个工具”。
>
> 外部程序读到这段指令，真的去执行操作，再把结果返回给 AI。

所以 Agent 的真实工作流程其实是这样的：

```text
1. AI 大脑收到你的任务，先判断“第一步该干什么”
2. AI 输出：“我要用读文件工具，读取 合同模板.docx”
3. 外部程序看到这条指令，真的打开文件
4. 程序把读取结果返回给 AI：“发现 5 个空白字段”
5. AI 拿到结果，继续判断：“好，现在先填第一个字段”
6. 外部程序继续执行
7. 这个循环一直跑，直到任务完成
```

理解这一点很重要。

因为你后面就不会再问：“为什么 Agent 不能直接帮我做某某事？”

答案通常很简单：

> 它没有那个工具，或者你没有给它那个权限。

这就像你雇了一个很聪明的实习生，但你不让他碰电脑、不让他看文件、不让他进系统。那他再聪明，也只能坐在那里跟你聊天。

#### 1.4 不是有工具就叫 Agent

还有一个误区也很常见。

有些产品给 AI 配了一堆工具，就开始说自己是 Agent。

但光有工具不够。

真正让 AI 从聊天框变成 Agent 的，是三样东西一起工作：

![Agent 三件套](/images/agent-beginner-tutorial/02-framework-agent-three-parts.png)

```text
Agent = AI 大脑 + 工具箱 + 自主决定

       （思考）   （能做事）   （不用你一步步指挥）
```

**大脑**：负责理解你的话，判断目标，规划步骤。

**工具箱**：负责读文件、写文件、跑命令、访问网页、发邮件、控制浏览器。

**自主决定**：你只说“把这 10 份合同都填好”，它自己决定先做哪一份、卡住了怎么换方案、做完后怎么验证。

少了第三样，它只是“能调用工具的聊天框”。

真正的 Agent，是你告诉它一个目标，它自己把过程拆出来，用不着你说一步它动一步。

#### 1.5 一句话总结

Chatbot 是会聊天的 AI。

Agent 是会干活的 AI。

你把 AI 当搜索框，它就只能给你答案。

你把 AI 带进工作现场，给它工具、规则和边界，它才有机会变成你的数字员工。

### 第 2 章 Agent 都有哪些

市面上叫 Agent 的东西太多了。

有的是聊天产品换个名字，有的是工作流平台包装一下，有的确实已经能做复杂任务。

所以先把分类捋清楚。你后面挑工具的时候，就不会一看到“智能体”“数字员工”“AI Agent”这些词就被绕进去。

#### 2.1 按自主程度分

这是最贴近普通用户感受的分法。

你的话越模糊，它越需要自己拿主意，Agent 等级就越高。

可以粗略理解成 L0 到 L5：

```text
L0：只回答问题，不执行
L1：能帮你写内容、生成方案，但主要还是对话
L2：能调用少量工具，但步骤基本靠你指挥
L3：能根据目标拆任务、调用工具、验证结果
L4：能长时间处理复杂项目，并在边界内自主推进
L5：高度自主的通用数字员工
```

这里要说实话。

**L5 现在还没有真正可靠的实现。**

谁说自己已经有完全自主、完全可靠、什么都能干的 Agent，你都可以先打个问号。

绝大多数普通用户现在日常接触到的，还是 L0 到 L1。

这套教程想带你摸到的是 L3 到 L4，也就是 Claude Code 这类工具能做到的程度：

> 你给目标，它能读项目、改文件、跑命令、查结果、继续调整。

这已经足够改变很多人的工作方式了。

#### 2.2 按界面形态分

同一个 Agent 内核，包装成不同界面，给人的感觉完全不一样。

**第一类：命令行型**

```text
命令行 Agent
├── Claude Code   —— Anthropic 出品，本教程主角
└── Codex CLI     —— OpenAI 出品，开源
```

这种工具看起来最吓人。

没有漂亮界面，没有按钮，全靠打字。

但它的能力上限也最高，因为它可以直接在你电脑里的项目目录工作，读文件、写文件、跑命令。

说白了，它就是一个坐在终端里的数字员工，早就超出了漂亮聊天框的范畴。

**第二类：图形界面型**

```text
图形 Agent
├── Claude Cowork —— Anthropic 出品，面向非技术用户
├── Trae Solo     —— 字节出品，国产工具
├── WorkBuddy     —— 腾讯出品，面向职场场景
└── Kiro          —— AWS 出品
```

这类工具更像普通软件。

界面友好，门槛低，适合不想碰命令行的人。

缺点是自由度一般会被产品设计限制住。你用起来舒服，但它不一定能像命令行工具那样深入你的系统。

**第三类：工作流编排型**

```text
工作流平台
├── Coze（扣子）—— 字节出品
├── Dify       —— 开源
├── n8n        —— 老牌自动化平台
└── Make / Zapier —— 海外自动化平台
```

这类东西更像“搭积木”。

你把流程拖出来，设置好每一步，AI 在某些节点参与判断。

它不一定是严格意义上的自主 Agent，更像 AI 工作流。

优点是稳定、可视化、好交接。

缺点是遇到你没有预设过的情况，它就容易卡住。

**第四类：自主运行型**

```text
持续运行 Agent
├── OpenClaw —— 开源，可远程控制电脑
└── 各种“虚拟员工”产品
```

这类 Agent 可以一直挂在后台等你派活，用完也不用关。

听起来很诱人，但风险也高。

因为它权限大、运行时间长，一旦规则没写清楚，就可能做出你不想要的事。

新手可以了解，但不要一上来就把核心账号、财务权限、客户系统都交给它。

![Agent 工具类型地图](/images/agent-beginner-tutorial/03-comparison-agent-types.png)

#### 2.3 按实现方式分

从技术视角看，大概也可以分成两种：

**工作流型**：流程主要由人提前设计好。适合重复、稳定、规则明确的任务。

**自主型**：人给目标，AI 自己拆步骤。适合复杂、多变、需要判断的任务。

生产环境里，两种都很有用。

简单重复的事，交给工作流。

复杂多变的事，交给自主型 Agent。

这套教程主要讲后者。

#### 2.4 哪些东西不算 Agent

为了不被营销话术带着走，你先记住几类不算 Agent 的东西。

**纯聊天对话**：豆包网页、DeepSeek 网页、ChatGPT 网页。它们是 Chatbot，不是完整 Agent。

**传统语音助手**：Siri、小爱、小度。多数是“意图识别 + 预设动作”，不是自主决策。

**推荐系统和搜索引擎**：百度、抖音推荐。它们是在数据库里排序，不是在替你执行任务。

判断一个产品是不是 Agent，看两点就行：

```text
1. 它能不能真的执行操作，而不只是给建议？
2. 它能不能自己决定下一步，而不只是按固定流程走？
```

两点都满足，才更接近真正的 Agent。

#### 2.5 为什么这套教程用 Claude Code

后面第 5 章会展开讲，这里先给结论。

Claude Code 适合作为第一个 Agent，是因为它有几个明显优势：

- 免费起步，门槛相对低
- 装在你自己的电脑里，能直接操作本地文件
- 默认工具箱够用，扩展能力也强
- Skills、MCP、Subagent 这些机制都能围绕它展开
- 很多开发者和团队在真实工作里就靠它干活，它不是拿来演示的玩具

当然，它也不是最简单的。

但我觉得普通人学 AI 工具，工具难一点其实不可怕，真正可怕的是一直在浅水区换来换去。

一个工具如果真的能让你理解 Agent 的底层工作方式，这个学习成本就是值得的。

### 第 3 章 Agent 的四个零件

不管哪家的 Agent，拆开看基本都是这四样东西：

```text
Agent = 大脑 + 手脚 + 记忆 + 主见

       (LLM)  (Tools) (Memory) (Autonomy)
```

![Agent 的五个关键组件](/images/agent-beginner-tutorial/04-framework-agent-components.png)

你可以把它想成一个实习生。

实习生得有脑子，能听懂你的话，这是大脑。

实习生得有手，能真的去做事，这是工具。

实习生得记得住事，不能每次都问“你刚才让我干嘛”，这是记忆。

实习生得自己拿点主意，不能你说一个字他动一下，这是自主性。

少一样，都不是一个好用的数字员工。

#### 3.1 大脑：LLM

LLM 是 Large Language Model，也就是大语言模型。

Claude、GPT、Gemini、豆包、DeepSeek、Kimi、GLM、通义千问，这些都是 LLM。

它的工作机制可以先粗暴理解成一句话：

> 接收一段文字，预测最合适的下一段文字。

听起来很简单，但这种预测能力强到一定程度，就能写代码、做分析、改文章、拆任务、通过考试。

这里有三个关键点：

**第一，同一个模型放在不同工具里，能力天差地别。**

Claude 模型放在网页里，主要就是聊天。

Claude 模型放在 Claude Code 里，就能读你电脑里的文件、改项目、跑命令。

不是大脑变了，是身体变了。

**第二，模型只能输出文字，不能直接操作东西。**

所有“动手”的事，都是工具做的。

**第三，模型本身没有永久记忆。**

每次开新对话，它都像一个刚来的新人。你不给它背景，它就只能现猜。

#### 3.2 手脚：Tools

工具就是让 AI 真正能动手的能力。

比如：

- 读文件
- 写文件
- 搜索文件
- 运行命令
- 打开网页
- 调用接口
- 发送邮件
- 操作浏览器

这里有一个反直觉的点：

> 工具不是越多越好。

很多人刚开始玩 Agent，就喜欢给它装一堆 MCP、一堆插件、一堆 Skill。

看起来很强。

但工具一多，AI 每次做事前都要判断“这次该用哪个工具”。判断空间越大，选错工具的概率反而越高。

所以新手阶段，先用 Claude Code 默认工具就够了。

真的遇到默认工具做不了的事，再去装 MCP。

#### 3.3 记忆：Memory

AI 模型本身没有长期记忆。

这句话很多人听过，但没有真正理解。

你今天跟它聊了半天，明天开一个新窗口，它不知道你是谁，也不知道你昨天说过什么。

Agent 的记忆一般分两层。

**短期记忆：当前对话上下文**

你这一轮对话里说过的话、它输出过的内容、工具调用结果，它都能看到。

但换一个新窗口，新对话，基本就没了。

这里有一个指标叫上下文窗口，意思是 AI 一次能“看见”的最大文字量。窗口越大，它能同时参考的材料越多。

**长期记忆：跨会话保存的信息**

长期记忆通常不在模型脑子里，而在文件、数据库、知识库里。

AI 需要时主动去读。

Claude Code 里的 CLAUDE.md，就是最典型的一种长期记忆。

你把你的偏好、项目规则、输出格式写进去，它每次启动时就能先读一遍。

#### 3.4 主见：Autonomy

这是 Agent 和“配了工具的 Chatbot”最根本的区别。

你说：

> “研究一下字节跳动，写份报告。”

普通 Chatbot 可能会丢给你一段它知道的旧信息。

Agent 会怎么做？

它会自己拆任务：

- 查公司背景
- 查主要产品
- 查竞品
- 查公开财务或新闻
- 汇总信息
- 写报告
- 检查有没有遗漏

中间如果发现资料不够，它会自己再搜一遍。

这背后就是一个循环：

```text
思考 → 行动 → 看结果 → 再思考 → 再行动 → 再看结果 → 完成
```

这就是 Agent Loop。

后面第 8 章会专门讲。

#### 3.5 真实生产环境里还有第五样：护栏

如果只有前面四样，Agent 会很能干，也会很危险。

它像一个聪明但刚入职的实习生。你不可能第一天就把公司财务账号、客户数据库、官网发布权限都给他。

所以生产环境里还要有第五样：

> 护栏。

![配图 2060192178593562624](/images/agent-beginner-tutorial/02-2060192178593562624.jpg)

护栏包括：

- 权限边界
- 预算限制
- 人工审批
- 操作日志
- 沙箱环境
- 回滚方案

新手阶段不用一下子搞得很复杂，但心里一定要有这根弦：

> Agent 越自主，越要给它划边界。

#### 3.6 一张图记住

```text
你（人）
  ↓ 用自然语言下指令
Agent
├── 大脑（模型）—— 思考
├── 手脚（工具）—— 执行
├── 记忆（上下文 + 文件）—— 记住
└── 主见（循环逻辑）—— 自己拿主意
  ↑
  护栏（权限 / 预算 / 审批 / 沙箱）—— 防止闯祸
```

后面所有章节，你都可以用这张图对号入座。

### 第 4 章 什么活适合丢给 Agent

Agent 很强，但不是万能。

我觉得新手最容易犯的错，就是刚学会一个工具，就什么都想丢给它。

最后事情没见它做完，你反倒花了更多时间给它擦屁股。

所以在上手之前，先建立一个判断：

> Agent 适合处理“可描述、可验证、可分步骤”的任务。
>
> 不适合处理“目标模糊、风险极高、没有验收标准”的任务。

![适合交给 Agent 的任务和新手慎用场景](/images/agent-beginner-tutorial/05-comparison-agent-task-fit.png)

#### 4.1 适合 Agent 的 5 个特征

![配图 2060192188974481409](/images/agent-beginner-tutorial/03-2060192188974481409.jpg)

大致可以记成五类：

- 重复发生
- 输入明确
- 规则能说清
- 结果能检查
- 出错代价可控

比如整理文件、汇总资料、生成报告、改文案、批量处理表格、检查代码、监控网页变化。

这些任务都很适合。

因为你可以告诉它：

> 输入是什么。
>
> 要做哪些动作。
>
> 输出什么结果。
>
> 怎么判断做得对不对。

#### 4.2 千万别一上来就用 Agent 的 6 个场景

![配图 2060192197174341632](/images/agent-beginner-tutorial/04-2060192197174341632.jpg)

新手尤其要避开这几类：

- 直接付款
- 自动删除重要文件
- 自动发布正式内容
- 自动群发邮件
- 自动修改生产系统数据
- 自动做法律、医疗、财务最终判断

不是说 Agent 永远不能参与这些事。

只是这些场景必须有人确认，必须有日志，必须有回滚方案。

你不能一上来就把方向盘全交出去。

#### 4.3 不可逆操作要单独说

不可逆操作，就是做完很难收回来的事。

比如：

- 付款
- 发布
- 删除
- 群发
- 改生产数据
- 提交正式审批

这些事情默认都应该加人工确认。

让 Agent 干 99 步都可以，但最后一步最好由人按下确认。

这不是不信任 AI。

这是正常的工作设计。

一个新人再聪明，你也不会让他第一天就独立发全公司公告。

#### 4.4 一个简单判断方法

如果一个任务，你能用文字清清楚楚教会一个刚入职的实习生怎么做，那它大概率适合 Agent。

如果你自己都说不清“怎么算做好了”，Agent 也很难搞定。

举几个例子：

![配图 2060192351503691776](/images/agent-beginner-tutorial/05-2060192351503691776.jpg)

比如“帮我整理这个文件夹，把图片、文档、视频分开”，适合。

比如“帮我做一个让我爆火的账号”，不适合。

前者有输入、动作和验收标准。

后者只是愿望。

Agent 可以帮你推进任务，但不能替你承担模糊目标。

#### 4.5 小结

记住一句话：

> Agent 是增强工具，不是替代品。

目标得你定。

边界得你画。

过程得你看。

结果得你验。

你交给 AI 的，是重复执行、资料处理、步骤推进这些中间过程，脑子始终还在你自己手里。

下一部分开始上手 Claude Code，把这些概念变成你电脑里真的能动的东西。

## 第二部分 上手 Claude Code

### 第 5 章 为什么第一个 Agent 选 Claude Code

市面上 Agent 工具有很多。

如果你是第一次真正理解“数字员工”这件事，我建议先从 Claude Code 开始。

这跟它漂不漂亮、适不适合所有人都没关系。

我真正看重的，是它能让你最快摸到 Agent 的本质：

> AI 进入你的本地工作目录，读取真实文件，执行真实任务，交付真实结果。

#### 5.1 它装在你电脑里，能动你的文件

绝大多数 AI 产品，还是网页里聊天。

再聪明，也主要是在给建议。

Claude Code 不一样。

它装在你自己的电脑里，从启动那一刻起，就可以在你指定的项目目录里工作：

- 看文件
- 改文件
- 新建文件
- 跑命令
- 启动脚本
- 整理资料
- 检查结果

这一步很关键。

因为 AI 真正变成生产力的那一刻，往往是它开始碰到你真实材料的时候。说得漂不漂亮，反倒没那么要紧。

真实文件。

真实目录。

真实项目。

真实结果。

#### 5.2 它把 Agent 该有的零件配齐了

回到第 3 章那四件套：

- 大脑
- 手脚
- 记忆
- 主见

Claude Code 基本都具备。

![配图 2060192362438287360](/images/agent-beginner-tutorial/06-2060192362438287360.jpg)

它有模型做判断。

它有工具读写文件、搜索内容、运行命令。

它能在任务里反复“看结果，再调整”。

对新手来说，这比自己拼一堆工具友好得多。

#### 5.3 它的扩展能力很强

Claude Code 后面可以通过四套机制扩展：

![配图 2060192371447672832](/images/agent-beginner-tutorial/07-2060192371447672832.jpg)

先记住：

#### 5.4 它是工业级工具，不是玩具

Claude Code 不是那种只能演示一下的玩具。

它是很多开发者、创业团队和 AI 公司内部在真工作里用的工具。

### 第 6 章 装好 Claude Code

这一章原始素材里留得比较简略，我这里按小白视角补一版。

具体安装方式会随官方版本变化，所以你真正安装时，要以 Claude Code 官方文档为准。

但安装前，你先搞清楚三件事：

#### 6.1 你需要准备什么

一般来说，你需要：

- 一台能正常联网的电脑
- 一个终端工具
- Node.js 或官方要求的运行环境
- Claude 账号或对应订阅权限
- 一个用于练习的本地文件夹

如果你看到这些词有点慌，很正常。

第一次接触命令行的人，都会觉得自己像走进了一个黑窗口。

但你不用把自己当程序员。

你只要把终端理解成：

> 一个你用文字指挥电脑做事的地方。

Claude Code 就是在这个地方运行的。

#### 6.2 安装时不要急着追求“全局最强配置”

很多新手学工具有个习惯：

一上来就搜“最强配置”“必装插件”“完整 MCP 列表”。

这反而容易把自己搞乱。

安装 Claude Code 的第一目标很简单，就是先跑通最小流程，别一上来想着把能力拉满：

```text
能启动 → 能看到当前文件夹 → 能执行一个简单任务 → 能输出结果
```

先做到这个，就够了。

#### 6.3 建议先建一个练习目录

不要第一次就让 Claude Code 进入你的工作资料库。

先在电脑上建一个空文件夹，比如：

```text
agent-练习
```

里面放几个无关紧要的测试文件：

- 一张图片
- 一个 txt
- 一个 PDF
- 一个 zip

后面第 7 章，我们就用它来做第一个任务。

这一步看起来很笨，但很重要。

普通人用 Agent，第一课其实是“学会给它划边界”。至于“让它多能干”，是后面的事。

### 第 7 章 第一个任务

装好不算上手。

真正上手，是你让它完成一个任务，然后你亲眼看到：

> 原来它真的可以自己读文件、建文件夹、移动文件、输出报告。

这一章我们做一个最简单的练手项目：

> 让 Agent 帮你整理一个文件夹。

#### 7.1 任务设定：整理桌面模拟文件

桌面文件乱，是很多人的常态。

但我们不要直接动真实桌面。

先在练习目录里模拟一个“乱糟糟的桌面”，让 Claude Code 帮你：

- 扫描当前目录所有文件
- 按类型分到不同文件夹
- 给你一份整理报告

这件事特别适合新手，因为它有三个好处：

第一，任务很具体。

第二，结果很好检查。

第三，风险很低。

#### 7.2 在 VS Code 里建一个工作目录

如果你使用 VS Code，可以这样做：

```text
打开 VS Code
→ 文件
→ 打开文件夹
→ 新建一个文件夹，比如 agent-练习
→ 打开
```

如果弹出“是否信任作者”，你可以点信任。

然后在这个文件夹里，手动放几个测试文件：

- 一张图
- 一个 PDF
- 一个 zip
- 一个 txt
- 一个 md

注意，只放测试文件。

不要把重要资料、客户文件、财务文件放进去。

#### 7.3 启动 Claude Code

在 VS Code 顶部点：

```text
终端 → 新终端
```

或者按快捷键：

```text
Ctrl + `
```

然后在终端里输入：

```bash
claude --dangerously-skip-permissions
```

这里要解释一下。

`--dangerously-skip-permissions` 可以理解成“狂飙模式”：AI 改文件、跑命令时，不会每一步都问你确认。

第一次在练习目录里用，它能让体验更顺。

但你一定要记住：

> 真实工作目录里，不要随便开这个模式。

新手最容易出事的地方，往往是人一开始就给了太大权限，跟 AI 笨不笨没什么关系。

#### 7.4 把任务给它

启动后，把下面这段指令发给 Claude Code：

```text
请扫描当前目录下的所有文件，按类型分类：
- 图片（.jpg .png .gif .webp）放到 images/
- 文档（.pdf .doc .docx .txt .md）放到 documents/
- 视频（.mp4 .mov .avi）放到 videos/
- 压缩包（.zip .rar .7z）放到 archives/
- 其他放到 others/

子文件夹不存在就先建好。整理完给我一份报告：
- 总共处理了多少文件
- 每个分类下有多少个
- 有没有遇到处理不了的情况
```

然后回车，看它跑。

#### 7.5 它会做什么

你会看到 Claude Code 一步步执行：

![第一个 Agent 任务流程](/images/agent-beginner-tutorial/06-flowchart-first-agent-task.png)

- 先查看当前目录有哪些文件
- 再创建 images、documents、videos 等文件夹
- 再把不同类型的文件移动过去
- 再统计数量
- 最后输出一份报告

整个过程里，你只说了一句话。

剩下的是它自己拆步骤、自己调用工具、自己检查结果。

这就是 Agent 的体感。

它没有停在嘴上告诉你“你应该新建几个文件夹”。

它真的动手帮你建好了。

#### 7.6 验证结果

跑完之后，你要自己检查。

不要因为 AI 说“完成了”，你就默认完成。

打开 VS Code 左侧资源管理器，看几个点：

- images/、documents/ 等文件夹是不是出现了
- 文件是不是按类型分对了
- 终端最后的报告和实际数量是否一致
- 有没有文件被误分

这一步很重要。

以后你用 Agent 做任何事，都要建立这个习惯：

> AI 负责执行，人负责验收。

#### 7.7 这个任务做对了什么

我们回头看这个任务，它为什么适合作为第一课？

**目标明确**：整理当前目录。

**动作明确**：扫描、分类、移动、统计。

**边界明确**：只处理练习目录。

**验收明确**：看文件夹结构和统计报告。

你以后所有交给 Agent 的任务，都尽量按这个模板组织。

别再用“帮我优化一下”这种含糊说法。

试着这样交代：

> 你要处理什么？
>
> 按什么规则处理？
>
> 输出什么结果？
>
> 做完怎么验证？
>
> 哪些地方不能动？

这几句话，比所谓万能提示词有用得多。

#### 7.8 你可能踩的坑

![配图 2060192388870750208](/images/agent-beginner-tutorial/09-2060192388870750208.jpg)

常见坑有几个：

- 工作目录选错，Agent 跑到不该动的地方
- 没有先放测试文件，结果不知道它有没有成功
- 指令太含糊，比如只说“帮我整理一下”
- 开了狂飙模式，却在重要目录里操作
- 做完不验收，完全相信它的报告

新手阶段，你不用追求复杂。

先把一个小任务跑通，比收藏 100 个教程都重要。

### 第 8 章 Agent 怎么“想”和“做”

第 7 章你已经看到了 Claude Code 跑完整任务。

这时候很多人会有一个感觉：

> 它好像真的在自己想办法。

那它到底是怎么“想”和“做”的？

核心就是一个循环：

```text
收集上下文 → 采取行动 → 验证结果 → 重复
```

#### 8.1 Agent 的核心循环

![Agent Loop 循环](/images/agent-beginner-tutorial/07-flowchart-agent-loop.png)

翻成大白话就是：

**先看一眼现在的状况。**

比如读文件、看目录、查资料。

**再干一件事。**

比如写文件、移动文件、运行命令。

**再看干得对不对。**

比如有没有报错、结果是不是符合预期。

**然后决定下一步。**

继续、调整、重试，或者宣布完成。

这就是 Agent Loop。

#### 8.2 用整理文件的例子拆解

回到第 7 章那个任务，它实际可能是这样跑的：

![配图 2060192397775261696](/images/agent-beginner-tutorial/10-2060192397775261696.jpg)

第一轮：看当前目录有哪些文件。

第二轮：发现没有分类文件夹，于是新建。

第三轮：按后缀移动文件。

第四轮：检查文件是否移动成功。

第五轮：统计数量，输出报告。

每一轮都是“看一眼、做一步、查一下”。

这就是 Agent 和 Chatbot 的根本差别。

Chatbot 一次性回答你。

Agent 在循环里反复推进。

#### 8.3 这个循环为什么强大

第一，它能自我纠错。

比如 Claude Code 想移动一个文件，结果文件名里有空格，命令失败了。

如果它能看到报错，下一轮就可能换一种写法，比如给文件名加引号。

它给完答案不会就此结束，还会根据结果继续调整。

第二，它能处理一点点意外情况。

比如你目录里有一个 `.xlsx` 文件，但你没有在分类规则里写 Excel。

它可能会判断这是文档类，放到 documents。

当然，它也可能判断错。

所以你要验收。

#### 8.4 你能影响循环的三个地方

知道循环以后，你就知道自己该从哪里提高成功率了。

![配图 2060192406692298752](/images/agent-beginner-tutorial/11-2060192406692298752.jpg)

你能影响它的地方主要有三个：

**第一，给清楚目标。**

不要只说“帮我弄一下”，要说“把当前目录文件按类型分类，并输出报告”。

**第二，给清楚规则。**

比如哪些后缀归图片，哪些归文档，不确定的放 others。

**第三，给清楚边界。**

比如只处理当前目录，不要递归子文件夹，不要删除任何文件。

很多人以为用 AI 的关键是问得花哨。

其实不是。

关键是你能不能把真实工作拆成它能执行、能验证的步骤。

#### 8.5 一个反复出现的提醒

Agent 不是一次性回答你的。

它是在持续推进任务。

所以你的指令越明确，规则越清晰，工具越合适，循环跑得越稳。

后面我们继续看它的手脚，也就是工具调用。

### 第 9 章 工具调用：Agent 的手脚

Agent 能干活，是因为它有工具。

不写代码的人也要懂一点工具调用。

因为你要知道两件事：

> 它能做什么。
>
> 它做这些事有什么风险。

#### 9.1 Claude Code 默认带的核心工具

![配图 2060192414699261952](/images/agent-beginner-tutorial/12-2060192414699261952.jpg)

你可以先按风险分三类：

**绿色工具：只读。**

比如查看文件、搜索内容、列目录。

这类工具风险低，因为它只是看，不会改东西。

**黄色工具：会改文件。**

比如写入文件、修改内容、移动文件。

这类就要注意，因为它会改变你的项目。

**红色工具：能运行命令。**

比如 Bash、PowerShell、安装依赖、删除文件、启动程序。

这类能力最强，风险也最大。

#### 9.2 一个具体例子

你说：

```text
帮我看看 project/ 目录里有哪些 markdown 文件，统计一下总字数。
```

Claude Code 可能会这样做：

```text
1. 调用搜索工具，找到 project/ 下所有 .md 文件
2. 调用读取工具，逐个读取这些文件
3. 内部统计字数
4. 输出结果：共 12 个文件，总字数 35,427
```

这个过程没有改任何文件。

所以它是比较安全的。

但如果你说：

```text
帮我把这些 markdown 文件重新命名并移动到 drafts/ 里。
```

那它就会动文件。

这时你就要确认目录、规则和备份。

#### 9.3 工具的权限模式

Claude Code 默认在使用一些会改动系统的工具前，会问你是否允许。

这其实是好事。

![配图 2060192422282567680](/images/agent-beginner-tutorial/13-2060192422282567680.jpg)

你可以粗略这样选：

- 第一次跑新任务：普通模式或 Plan 模式
- 你已经很熟悉的低风险任务：Auto-Accept
- 一次性练习目录：可以临时用狂飙模式
- 真实项目和重要文件：不要随便跳过权限确认

很多时候，慢一点不是坏事。

尤其是 Agent 第一次接触一个新目录时，让它先看、先计划、再动手，比直接开干稳得多。

#### 9.4 工具是按需配的

Claude Code 默认工具已经能覆盖很多场景。

如果你需要让它连接外部服务，比如飞书、Notion、浏览器、数据库、GitHub，那就可能需要 MCP。

![配图 2060192430784421888](/images/agent-beginner-tutorial/14-2060192430784421888.jpg)

但还是那句话：

> 工具不是越多越好。

装一个，用一个。

长期不用的，就删掉。

否则 Agent 每次都要在一堆工具里判断该用哪个，反而容易乱。

#### 9.5 一句话总结

工具是 Agent 的手脚。

手脚越合适越好用，不是越多越好。

新手阶段，先学会让它安全地读文件、改文件、跑小命令。

这已经足够做很多事。

### 第 10 章 给 Agent 写说明书：CLAUDE.md

到这里，你已经知道 Agent 有大脑、有工具、有循环。

但还有一个问题：

每次开新对话，它都像刚认识你。

你又要重新解释：

- 我是谁
- 我喜欢什么风格
- 这个项目是什么
- 输出文件放哪里
- 哪些事不能做

CLAUDE.md 就是解决这个问题的。

#### 10.1 CLAUDE.md 是什么

一句话：

> CLAUDE.md 是给 Claude Code 看的长期说明书。

它就是一个普通的 markdown 文件。

你把它放在特定位置，Claude Code 每次启动时会自动读一遍，把里面的内容当成工作规则。

这件事很像你给实习生写了一份入职手册。

以后他每次做事前，先看一眼：

- 这个项目是什么
- 你的偏好是什么
- 输出格式是什么
- 哪些红线不能碰

这就比你每次口头重复强多了。

#### 10.2 两种 CLAUDE.md：全局和项目

![配图 2060192439873536000](/images/agent-beginner-tutorial/15-2060192439873536000.jpg)

可以这样理解：

**全局 CLAUDE.md**：写“你是谁”和“你长期偏好什么”。

比如：

- 用中文回复
- 不要写太多术语
- 重大操作先确认
- 输出文件放到指定目录

**项目级 CLAUDE.md**：写“这个项目是什么”和“这个项目的规则”。

比如：

- 这是公众号文章项目
- drafts 放草稿
- published 放成稿
- 文章风格是什么
- 文件名怎么命名

#### 10.3 怎么创建全局 CLAUDE.md

Mac/Linux 在终端输入：

```bash
mkdir -p ~/.claude
open ~/.claude
```

Windows 输入：

```powershell
mkdir $env:USERPROFILE\.claude
explorer $env:USERPROFILE\.claude
```

在弹出的文件夹里，新建一个文件：

```text
CLAUDE.md
```

然后用 VS Code 打开编辑。

#### 10.4 一份小白可直接抄的全局 CLAUDE.md

```markdown
# 全局规则

## 沟通
- 中文回复
- 称呼我为“你”
- 我不是程序员，所有解释尽量用大白话
- 必须用专业术语时，先给一句大白话解释

## 工作方式
- 收到需求后，先理解背景，再给方案
- 不明确的需求，先问我，不要乱猜
- 执行前先说明你准备怎么做
- 简单优先，不要过度设计

## 输出
- 所有生成文件统一放到 outputs/ 文件夹
- 文件名用中文，简短可读
- 不要在文件里写 emoji
- 不要在文件结尾加客套话

## 危险操作
- 删除文件前必须先问我
- 改别的项目文件前必须先问我
- 发布、付款、群发邮件前必须先问我
- 不可逆操作一律先确认
```

你可以直接复制，然后按自己的情况改。

不用追求一次写完美。

CLAUDE.md 是慢慢养出来的。

你用得越多，越知道自己应该补哪些规则。

#### 10.5 怎么创建项目级 CLAUDE.md

在某个项目目录下，新建一个 `CLAUDE.md`。

比如你有一个“公众号文章”项目，可以这样写：

```markdown
# 项目：公众号文章

## 这个项目是什么
我用来写公众号文章的工作区。

## 目录结构
- drafts/ 草稿
- published/ 已发布
- images/ 配图
- references/ 参考资料

## 写作风格
- 标题不超过 18 字
- 开头要有真实触发点
- 段落短，一段最多 3 句
- 不写夸张营销话术
- 不写“如有侵权请联系删除”这类废话

## 工作流程
1. 我说选题，你先列大纲
2. 我确认后，你再写初稿
3. 初稿放 drafts/
4. 我说“定稿”，你再整理到 published/
```

下次你在这个项目里启动 Claude Code，它就会先读这份说明书。

这就是把 AI 从“通用工具”训练成“你的工具”的开始。

#### 10.6 写 CLAUDE.md 的几个坑

![配图 2060192448526344192](/images/agent-beginner-tutorial/16-2060192448526344192.jpg)

常见坑有三个：

**第一，写得太长。**

规则不是越多越好。太长了，它抓不住重点。

**第二，写得太虚。**

比如“输出要高级”“风格要好”。这类话没用。

你要写具体标准，比如“段落短，一段不超过 3 句”“标题不要用震惊、炸裂、封神”。

**第三，规则互相矛盾。**

一边说“尽量简短”，一边说“每个点都详细解释 1000 字”，它就会混乱。

#### 10.7 一个偷懒办法

不知道写什么，可以让 Claude Code 先帮你起草。

你可以对它说：

```text
请根据我们这几次对话，帮我起草一份全局 CLAUDE.md。
要包含：我的身份、我的工作偏好、我容易踩的坑、不可逆操作的红线。
草稿出来后给我确认，不要直接保存到文件。
```

它出草稿后，你再改。

别让它直接替你决定所有规则。

因为真正知道你怎么工作的人，是你自己。

#### 10.8 一句话总结

CLAUDE.md 是写一次、长期用的偏好说明书。

没有它，Claude Code 是一个通用 Agent。

有了它，它才开始变成你的 Agent。

### 第 11 章 Skills：给 Agent 装专业技能包

如果说 CLAUDE.md 是“长期说明书”，那 Skills 更像“专业操作手册”。

你可以把它理解成：

> 当某类任务反复出现时，把你希望 Agent 怎么做，写成一个可复用的技能包。

#### 11.1 为什么需要 Skills

很多人用 AI 会遇到一个问题：

同一件事，每次都要重新教。

比如你经常让它写公众号文章。

你每次都要说：

- 我的风格是什么
- 开头怎么写
- 不要写成媒体腔
- 标题不要太夸张
- 结尾要落到普通人行动

说一次还行。

说十次就烦了。

Skills 的价值就在这里：

> 把反复说的话，沉淀成一份技能说明。

以后遇到同类任务，Agent 自己读 Skill，按规则做。

#### 11.2 Skill 和 CLAUDE.md 有什么区别

可以这么分：

```text
CLAUDE.md：长期、通用、全局偏好
Skill：某一类任务的专业流程
```

比如：

- CLAUDE.md 写“你喜欢中文、简洁、先计划再执行”
- 写作 Skill 写“公众号文章怎么选题、怎么开头、怎么结尾”
- 数据分析 Skill 写“先看字段、再清洗、再统计、最后输出报告”
- 封面 Skill 写“封面比例、配色、字体、构图偏好”

CLAUDE.md 像公司文化。

Skill 像岗位 SOP。

#### 11.3 一个公众号写作 Skill 可以长什么样

比如你可以写：

```markdown
# 公众号写作 Skill

## 适用场景
当用户要求写 AI 行业公众号文章、改稿、二创、选题分析时使用。

## 写作风格
- 从真实观察或聊天切入
- 口述感强，不写科技媒体腔
- 先承认反对者有道理，再提出更深判断
- 多用普通人能理解的例子
- 结尾落到行动，不喊口号

## 工作流程
1. 先读原始材料
2. 提炼核心观点
3. 判断适合哪种结构
4. 给出标题备选
5. 写完整初稿
6. 自检是否像人在讲话
```

这就是一个简单 Skill。

不神秘。

它本质上就是把你的经验写下来，让 Agent 下次照着做。

#### 11.4 新手什么时候该写 Skill

不要一开始就写一堆 Skill。

我建议满足三个条件再写：

```text
1. 这个任务你重复做了至少 3 次
2. 每次你都要重复解释很多规则
3. 你已经知道什么结果算好，什么算不好
```

比如你只是偶尔让 AI 帮你查一次资料，就没必要写 Skill。

但你每周都写公众号、每周都做选题、每周都生成封面，那就值得沉淀。

#### 11.5 Skill 的坑

Skill 写不好，也会让 Agent 变笨。

常见问题：

- 写太长，重点被淹没
- 什么任务都想覆盖，最后没有边界
- 规则互相矛盾
- 没有说明什么时候用，什么时候不用
- 只写风格，不写流程

好 Skill 应该像一个靠谱的工作说明：

> 什么情况下用它。
>
> 输入是什么。
>
> 步骤是什么。
>
> 输出是什么。
>
> 怎么判断好坏。

#### 11.6 一句话总结

Skills 是把你的经验变成可复用流程。

普通人真正用好 Agent，靠的是慢慢把自己的工作方法沉淀下来。每次都想憋一个神奇提示词，反而走不远。

这才是越用越顺手的关键。

## 第三部分 进阶玩法

### 第 12 章 MCP：让 Agent 连上外面的世界

前面讲的工具，多数是在你本地电脑里工作。

但真实工作里，很多东西不在本地。

你的资料可能在飞书。

你的任务可能在 Notion。

你的代码可能在 GitHub。

你的数据可能在数据库。

你的客户消息可能在微信、Slack、邮箱。

这时候，就需要 MCP。

#### 12.1 MCP 是什么

你可以先把 MCP 理解成：

> 给 Agent 接外部工具的标准接口。

它让 Agent 可以通过一套统一方式，连接各种外部服务。

比如：

- 查 GitHub issue
- 读 Notion 文档
- 搜飞书知识库
- 操作浏览器
- 查询数据库
- 读取本地特殊文件

Agent 这时候已经不只在本地文件夹里干活，它还能连上外面的系统。

#### 12.2 MCP 为什么强

因为它会让 Agent 的能力指数级扩展。

没有 MCP，它可能只能读你给它的文件。

有了 MCP，它可以去外部系统拿资料，更新任务状态，查询历史记录，甚至操作业务工具。

这就很接近真实数字员工了。

#### 12.3 MCP 为什么危险

但也正因为它强，所以危险。

每装一个 MCP，本质上都是给 Agent 多开一道门。

你要问自己：

> 这道门通向哪里？
>
> 它能读什么？
>
> 它能写什么？
>
> 它能不能删除？
>
> 它能不能对外发布？

不要只看“能不能用”，还要看“出错会怎样”。

#### 12.4 新手怎么用 MCP

建议遵守三个原则：

```text
1. 只装你马上要用的
2. 优先装只读权限的
3. 涉及写入、删除、发布的 MCP，一定加人工确认
```

比如你只是让 Agent 查资料，那就尽量给只读权限。

如果你让它能写入数据库、发消息、改线上内容，那就必须谨慎。

#### 12.5 一句话总结

MCP 让 Agent 连上外部世界。

但每多连一个系统，能力变强，责任也变大。

新手不要一上来追求“全能数字员工”。

先让它在一个小场景里稳定工作，再慢慢扩展。

### 第 13 章 Subagent：让 Agent 雇 Agent

到目前为止，你的 Claude Code 更像是一个人在干活。

但复杂任务里，一个人从头干到尾，很容易乱。

比如你说：

> “帮我分析过去 30 天公众号数据，找出最受欢迎的内容方向，再给我 5 个新选题。”

如果一个 Agent 全包，它要同时处理数据、分类、分析、总结、选题。

上下文会很长。

出错也不好定位。

更好的方式是拆成几个子任务。

这就是 Subagent。

#### 13.1 为什么需要 Subagent

可以把主 Agent 想成总指挥，把子 Agent 想成临时专家。

```text
主 Agent（总指挥）
├── 子 Agent 1：拉过去 30 天数据
├── 子 Agent 2：按主题分类、统计阅读量
├── 子 Agent 3：找出 Top 10 文章共同特征
└── 子 Agent 4：基于特征生成 5 个新选题
```

每个子 Agent 只处理自己那一块。

最后主 Agent 汇总。

这会让复杂任务更清楚。

#### 13.2 Subagent 的好处

![配图 2060192458785595392](/images/agent-beginner-tutorial/17-2060192458785595392.jpg)

主要有三个好处：

**第一，任务更容易拆清楚。**

每个子 Agent 只做一件事。

**第二，可以并行。**

互不依赖的任务可以同时跑，节省时间。

**第三，专业视角更明确。**

比如数据分析、文案审稿、代码检查，可以交给不同角色。

#### 13.3 怎么用 Subagent

Claude Code 内置了 Subagent 机制。

你不需要自己写代码。

最简单的方式，是直接告诉它：

```text
这个任务比较复杂，请用 subagent 并行处理：
- subagent 1 负责 A
- subagent 2 负责 B
- subagent 3 负责 C
全部完成后，请汇总成一份报告给我。
```

另一种方式，是预定义专门的 Subagent。

比如在 `~/.claude/agents/` 目录下建一个“数据分析师.md”：

```markdown
---
name: 数据分析师
description: 专门处理数据统计、趋势分析、报表生成。当任务涉及大量数据处理时调用。
---

你是一个数据分析师。

工作流程：
1. 先看数据结构，搞清楚有哪些字段
2. 用脚本做统计，不要手动算
3. 输出结构化报告：核心发现 + 数据明细
4. 不要瞎下结论，只说数据能支持的判断
```

之后遇到数据分析任务，主 Agent 就可以把这部分派给它。

#### 13.4 Subagent 用得好的关键

![配图 2060192466540855297](/images/agent-beginner-tutorial/18-2060192466540855297.jpg)

关键是边界清楚。

你要说明：

- 每个子 Agent 负责什么
- 不负责什么
- 输入是什么
- 输出什么格式
- 最后由谁汇总

不要把一堆模糊任务丢出去。

否则你只是把一个混乱任务拆成多个混乱任务。

#### 13.5 一个反直觉的事

不是所有任务都该用 Subagent。

简单任务用 Subagent，反而会变慢、变贵。

因为拆任务、传上下文、汇总结果，本身都有成本。

判断标准很简单：

```text
任务能并行跑 → 适合 Subagent
任务需要不同专家视角 → 适合 Subagent
任务简单线性 → 主 Agent 自己干就好
```

整理一个文件夹，不需要 Subagent。

分析一批数据、写一份复杂报告、做一次多角度审稿，可以考虑。

#### 13.6 一句话总结

Subagent 是从“一个人干”升级到“团队作战”。

复杂任务用它。

简单任务别硬用。

### 第 14 章 记忆与上下文

很多新手用 Claude Code 用着用着，会问一个问题：

> 为什么它刚才还记得，开个新窗口就忘了？

这不是它突然变笨。

这是机制。

#### 14.1 三种记忆

![配图 2060192478331076608](/images/agent-beginner-tutorial/19-2060192478331076608.jpg)

你可以先理解三类：

**第一，当前对话里的短期记忆。**

这就是上下文。

**第二，文件里的长期记忆。**

比如 CLAUDE.md、项目文档、历史记录。

**第三，外部系统里的可检索记忆。**

比如知识库、数据库、笔记软件。

新手最常困惑的是前两种。

#### 14.2 短期记忆：上下文窗口

几个词先搞懂：

**上下文**：当前对话里所有内容，包括你的输入、AI 的输出、工具调用结果。

**上下文窗口**：AI 一次能看到的最大文字量。

**Token**：AI 理解文字的最小单位。一个中文大概 1 到 2 个 token，一个英文单词大概 1 个 token。

主流模型的上下文窗口越来越大：

![配图 2060192487608844288](/images/agent-beginner-tutorial/20-2060192487608844288.jpg)

但窗口再大，也不是无限的。

上下文太长后，会出现几个问题：

- AI 开始忘前面的细节
- 输出质量下降
- 自动进入压缩模式
- 新旧要求混在一起

所以一个实操建议：

> 一个窗口尽量只聊一件事。

切话题，就开新窗口。

#### 14.3 跨会话记忆：靠文件

模型不会自动把你说过的话永久记住。

所以重要信息要落到文件里。

![配图 2060192496651821056](/images/agent-beginner-tutorial/21-2060192496651821056.jpg)

比如：

- 项目规则写到 CLAUDE.md
- 写作风格写到 Skill
- 任务计划写到 plan.md
- 输出结果保存成报告
- 复盘经验沉淀到文档

这就像工作中一样。

你不能只在会议里说，最后什么都不记录。

AI 也是一样。

#### 14.4 上下文管理的三个技巧

**技巧 1：不要一上来塞 100 个文件。**

很多人以为资料越多越好。

其实不一定。

资料太多，AI 要花很多精力判断哪个相关，反而容易乱。

精选 3 到 5 个核心文件，经常比一次塞一堆更好。

**技巧 2：定期 /compact。**

对话聊久了，会有很多试错过程、废弃方案、报错信息。

输入 `/compact`，Claude Code 会压缩上下文，保留核心结论。

**技巧 3：复杂任务先用 Plan 模式。**

让它先计划，再执行。

你先看方案有没有跑偏，再让它动手。

这比直接开干稳很多。

#### 14.5 一个常见误解

“AI 没记住我之前讲的话”，不等于“AI 笨”。

很多时候，它就是没有被提供那段信息。

解决办法是把重要信息写进文件、规则和流程里。一味抱怨它不记得，没有用。

这也是普通人用 Agent 很重要的一课：

> 不要把经验只留在聊天窗口。
>
> 要把经验沉淀成文件。

### 第 15 章 避坑清单

![新手安全使用 Agent 清单](/images/agent-beginner-tutorial/08-infographic-agent-safety-checklist.png)

最后这一章，把新手最容易踩的坑集中讲一下。

Agent 好用，但它不是魔法。

你越早知道它会在哪里出问题，就越不容易被它吓退。

#### 15.1 烧 Token 烧到肉疼

怎么烧的？

- 一个窗口聊几个小时不清理
- 跑大任务不设边界
- 把一堆无关文件都塞进去
- 用昂贵模型干简单任务
- 让 Agent 反复试错却不收敛

怎么防？

![配图 2060192507380850688](/images/agent-beginner-tutorial/22-2060192507380850688.jpg)

简单说：

- 小任务用小范围
- 大任务先拆计划
- 定期 compact
- 不要把所有资料一次性丢进去
- 跑之前问一句“这个任务怎么验收”

#### 15.2 Agent 跑飞，改坏文件

怎么坏的？

- 工作目录选错
- 开了狂飙模式
- 提示词没写边界
- 没有备份
- 让它处理重要目录

怎么防？

![配图 2060192515014451200](/images/agent-beginner-tutorial/23-2060192515014451200.jpg)

建议：

- 第一次任务放练习目录
- 重要文件先备份
- 明确写“不要删除文件”
- 明确写“只处理当前目录”
- 复杂任务先 Plan，再执行

用 Agent，边界感比技巧更重要。

#### 15.3 装了一堆 Skill / MCP，反而变笨

为什么？

因为每个 Skill、每个 MCP，都会进入 Agent 的判断范围。

它要想：

> 这次该用哪个？
>
> 那个要不要用？
>
> 这个工具和那个工具有什么区别？

工具越多，判断成本越高。

![配图 2060192523491094528](/images/agent-beginner-tutorial/24-2060192523491094528.jpg)

怎么防？

- 只装当前要用的
- 不用的先删
- Skill 要有明确适用场景
- MCP 优先只读
- 不要追求“全家桶”

很多时候，少一点工具，Agent 反而更稳定。

#### 15.4 指令太像愿望，不像任务

这是我觉得普通人最常见的问题。

比如：

```text
帮我做一个很厉害的公众号方案。
```

这不是任务。

这是愿望。

更好的写法是：

```text
请根据 references/ 里的 3 篇参考文章，帮我整理一个公众号选题方案。
要求：
1. 输出 10 个选题
2. 每个选题包含标题、核心观点、适合人群
3. 不要写夸张营销标题
4. 最后按推荐优先级排序
5. 输出到 outputs/选题方案.md
```

这才是任务。

Agent 不是不能处理复杂事。

但你要把复杂事讲成它能执行的样子。

### 写在最后

Agent 不是魔法。

它也不是一个你买回来就自动赚钱的机器。

它更像一个永远在线、知识很杂、很能干，但需要你带一带的数字员工。

你要告诉它目标。

你要给它工具。

你要给它边界。

你要验收它的结果。

这听起来好像还是有点麻烦。

但我觉得，这正是普通人真正值得练的地方。

未来人与人之间的差距，可能不会只看“谁更会提问”。

更大的差距在于：谁更早学会把自己的真实工作拆成流程，把流程交给 AI 执行，把好的经验沉淀成规则，再一轮轮复用。

有人还在问 AI：

> “我应该怎么做？”

有人已经开始对 Agent 说：

> “这是我的资料，这是我的目标，这是边界，你先看一遍，给我计划，确认后开始执行。”

这两种用法，短期看只是工具不同。

时间一长，差距会很明显。

因为前者得到的是建议。

后者训练的是一个工作系统。

所以别急着追所有新工具。

先从一个很小的任务开始。

建一个练习目录，让 Claude Code 帮你整理几个文件。

跑通之后，再让它处理你的资料、你的文章、你的项目、你的重复工作。

普通人真正进入 AI 时代，不一定是从一个宏大的决定开始。

很多时候，就是从第一次把 AI 从聊天框里请出来，让它真的替你干一件小事开始。
