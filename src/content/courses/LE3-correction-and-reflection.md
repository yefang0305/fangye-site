# LE3 · 纠错与反思

> 本章目标：拧第三个旋钮——**让循环从错误里学习**。好的循环不怕出错，它把"失败"变成"下一圈的输入"。这里有被动（错误回灌）和主动（反思自纠）两挡。
> 拧的旋钮：③ 纠错与反思（error feedback & reflection）。

---

## 0. 先讲一个画面

工人刷错了一块，墙面留了一道明显的刷痕。有两种"改"的机制：

- **被动**：你把"这块刷歪了"的照片直接塞回给他，他下一轮一看，自己补上。你只负责"把错误摆回他眼前"，纠正动作还是他做。
- **主动**：不用你提醒，他每刷完一段，自己退后两步审视全局——"这道有点歪、那处颜色偏深"，挑完毛病，带着这份自我批评重刷一遍。

第一种叫**错误回灌**，第二种叫**反思（Reflexion）**。这一章教你两挡都拧好，让循环既能"被纠"也能"自纠"。

> 关系说明：Harness L3 提过一句"工具失败时把错误当结果喂回去，循环继续"——那就是被动那挡。本章把它讲透，并加上主动反思这挡。

---

## 1. 核心概念：被动回灌 + 主动反思

| 机制 | 大白话 | 谁触发 | 代价 |
|---|---|---|---|
| **错误回灌**（error feedback） | 工具失败时把报错当结果 append 回 messages，循环照常继续，模型读到自己换路子 | 自动（工具一失败就回灌） | 几乎免费，但只能纠"明显报错"的问题 |
| **反思**（Reflexion） | 让模型对自己刚才的轨迹做批判、总结"哪步不对、下次怎么改"，带着这份反思重试 | 主动（按节奏或失败后触发） | 多花 token/步数，但能跳出"局部正确、全局错"的坑 |
| **actor/critic 分离** | 干活的（actor）和挑错的（critic）用两个角色/两次调用，挑错的更狠 | 设计选择 | 更贵，但批判质量更高 |

术语注释：
- **错误回灌（error feedback）**：把工具执行的失败信息（报错文本）当作一条普通"工具结果"追加进 messages，让下一圈的模型能读到它。这是 agent "看起来会自我纠错"的真相。
- **Reflexion（反思）**：让模型显式地对自己已经走过的步骤做一段"复盘批判"，产出"我哪里错了、下一次该怎么改"，再把这段反思塞进上下文重试。和"回灌"的区别：回灌喂的是**环境给的错误**，反思喂的是**模型对自己的批评**。
- **actor / critic**：把"执行者"和"批评者"分开——同一个模型扮两个角色，或干脆两次独立调用，让批评那次专门挑刺，避免"自己夸自己"。

## 2. 原理"为什么"：循环之所以强，是因为它能消化失败

LE0 说循环是发动机；这一章揭示发动机为什么"耐造"——**它把失败变成下一圈的输入**，而不是让失败终止整台机器。

这里有一条贯穿全章的铁律：

> **错误终止循环是灾难，错误回灌循环是进化。** 接 LE2：撞上缰绳才该停；普通的工具失败**不该**让循环崩溃，而该被当成结果喂回去，让循环再转一圈。

但被动和主动深浅不同：

- **被动回灌只能纠"环境会报错"的问题。** 文件少个逗号、命令返回非零——这些有明确报错，喂回去模型就能改。可如果模型在做一件"不报错但方向错"的事（比如认认真真实现了一个根本不该要的功能），环境不会报错，回灌救不了它。
- **主动反思才能纠"局部正确、全局错"的问题。** 它强迫模型跳出"埋头走下一步"，退后看整条轨迹，问自己"我是不是从一开始就理解错了"。这正是它能跳出被动机制盲区的原因。

还有一个常被忽略的杠杆：**纠错质量 ≈ 你喂回去的信息质量。**"失败了"这种报错毫无用处；"失败：`config.py` 第 12 行缺少逗号"才能让模型精准自纠。设计工具时让它**吐出好错误信息**，是纠错能力的隐形地基。

> 原理一句话：**循环的纠错力，本质是"把失败转写成有用的下一圈输入"的能力。被动回灌喂环境的报错，主动反思喂模型的自我批评，而两者的上限都被"喂回去的信息有多具体"卡住。**

## 3. 结构图：失败不是出口，是回路

```
        模型走一步（开工具单）
                │
                ▼
         执行工具 ── 成功 → 结果回填 → 下一圈
                │
              失败
                │
        ┌───────┴─────────┐
        ▼                 ▼
  被动：把报错当结果      主动：触发一段"反思"
  append 回 messages      （复盘哪步错、怎么改）
        │                 │
        └────────┬────────┘
                 ▼
         带着新信息回到圈开头，再转一圈
        （注意：这不是 break！失败留在循环内）
```

## 4. Claude Code 锚点：拆穿"它会自己纠错好智能"

| 你看到 Claude Code | 背后的平凡机制 |
|---|---|
| 跑测试报错后，它"看了一眼"又自己改对了 | **被动回灌**：报错被当结果 append 回 messages，下一圈模型读到后开一张修正过的工具单 |
| 它干到一半停下来说"我重新想一下思路，刚才的方向不对" | **主动反思**：它对自己的轨迹做了一次复盘批判 |
| 你用 Superpowers 的 systematic-debugging 让它结构化地查 bug | 一套被规范化的反思流程（先立假设→验证→再改，而不是瞎试） |

观察练习：下次它报错后自己改对，别急着惊叹"好智能"——用 LE2+LE3 拆穿它：**没有神秘的智能，只有"错误信息被喂回 + 循环再转一圈"**。然后留意：当报错信息很具体时它一次就改对，报错含糊时它要试好几轮——这就印证了"纠错质量取决于喂回去什么"。

## 5. 小练习 / 思考题

1. 用 LE2+LE3 拆穿"Claude Code 会自己纠错，好智能"这句话背后的机制。
2. 被动回灌和主动反思各适合纠哪一类错误？举例说明被动救不了、必须靠反思的情形。
3. 为什么说"纠错质量 ≈ 喂回去的信息质量"？这对你设计工具有什么启发？
4. 为什么普通的工具失败**不该** break 循环？什么样的失败才该 break（提示：回看 LE2）？

<details>
<summary>参考答案</summary>

1. "纠错"= 错误回灌 + 循环继续：工具报错被当结果 append 回 messages，循环转到下一圈，模型读到报错、开一张修正过的工具单。没有"智能纠错"，只有"错误信息被喂回 + 循环再转一圈"。
2. 被动回灌适合"环境会明确报错"的问题（语法错、命令失败）；主动反思适合"不报错但全局方向错"的问题。例：模型一丝不苟地实现了一个**根本不该做**的功能——环境不报错，回灌救不了，只有反思（退后问"我是不是理解错了需求"）能纠。
3. 因为模型只能基于喂回去的信息纠错。"失败了"无信息量，"失败：X 文件第 12 行缺逗号"才可精准定位。启发：设计工具时让它**吐出具体、可操作的错误信息**，这是纠错能力的隐形地基。
4. 普通工具失败是"可消化的信息"，喂回去循环能自纠，break 会浪费掉这个自我纠正的机会。只有撞上缰绳（max_steps/预算/超时/高风险升级，见 LE2）才该 break——那是"不可继续"，不是"暂时出错"。

</details>

## 一句话带走

> **第三个旋钮是把失败变成燃料：被动回灌喂环境的报错（免费但浅），主动反思喂模型的自我批评（贵但能跳出全局性错误）。错误终止循环是灾难，错误回灌循环是进化；而纠错的上限，被"你喂回去的信息有多具体"死死卡住。**

下一章 **LE4 嵌套循环**：到这里我们一直在调"一个"循环。但当任务太大，一个循环会又长又乱、撑爆窗口。下一个旋钮是把大循环拆成"循环里再开循环"——让一个工头调度一队工人。
