# CE0 · 导论：上下文才是真正的瓶颈

> 本章目标：建立全课的总心智模型——把"上下文窗口"看成 agent 的**一张办公桌**，并立下本课的核心主张：**桌面管理（而非模型脑力）才是 agent 智力的真正瓶颈**。本章接续姊妹课 Harness Engineering 的 **L4「上下文工程」**，把那一章的"办公桌 + 四把刀"从入门讲义放大成一门可上手的手艺课。
> 拧的旋钮：暂无——本章只摊开"全景图"，从 CE1 起一把刀一把刀地磨。

---

## 0. 先讲一个画面

L4 给过你一个画面：把模型的上下文窗口（context window，模型这一次能"看见"的全部文字，有 token 上限）想成一张**有限大小的办公桌**——它只能看见摊在桌上的东西。

现在，把镜头拉近，近到能看清桌面上的每一张纸。

你会发现一件反直觉的事：决定这个 agent 聪不聪明的，**往往不是它脑子有多好，而是这张桌子被收拾得有多干净**。

- 同一个模型，桌上摊着精准的三页关键资料 → 它思路清晰、一击即中。
- 同一个模型，桌上堆着两百页"可能有用"的资料 → 它翻不动、抓不住重点、把关键那张压在了纸山底下——**看起来像变笨了**。

脑子没变，变的是桌面。

> **本课的核心主张：在模型足够强的今天，agent 的智力瓶颈，主要不在"模型够不够聪明"，而在"它的桌面被管得够不够好"。** 桌面管理，就是上下文工程（context engineering）。

L4 把这张桌子和管它的四把刀**介绍**给了你。这门课只做一件事：**把每一把刀从"听说过"磨成"用得动"**——磨成手术刀。

## 1. 一个被忽略的事实：你能换的不是脑子，是桌面

新手最大的错觉是：agent 答得不好，是因为"模型不够聪明，得换个更强的模型"。

但绝大多数时候，你**根本换不了模型的脑子**——它是一个固定的、训练好的大脑。你真正能动手改的，是**这一轮你往它桌上摊了什么、怎么摆**。

这就引出全课最该钉死的一句话——它同时也是本课和 prompt engineering 的关系：

> **模型越强，"怎么说"越不重要，"给它看什么、在哪儿看"越重要——prompt engineering 没死，它升维了。**

这话值得拆开讲，因为它是很多人这两年最大的认知误区。

### 死掉的那一半：咒语式技巧

早期 prompt engineering（提示工程，"怎么对模型说话"的技巧）里，有一大批靠"话术"哄模型的招式。模型变强之后，它们正在**批量失效**：

- "你是一位有 20 年经验的资深专家……"——给模型贴身份标签。强模型本就具备该能力，贴不贴帮助甚微。
- "请深呼吸，一步一步地想。"——情绪/仪式咒语。早期对弱模型有点用，今天基本是安慰剂。
- 全大写 + 三个感叹号"**你必须！！！**"——靠语气吓唬模型。强模型不吃这一套。

这些是**咒语**：它们假设"用对暗号就能解锁隐藏能力"。模型越强，隐藏能力越少需要解锁，咒语就越没用。

### 没死、反而升维的那一半：精确规约 + 供给信息

但 prompt engineering 里有**另一半**，不但没死，反而成了今天最值钱的手艺：

- **精确地规约意图（specification）**：把"你到底要它干什么、交付什么、什么算对"说清楚。这不是话术，是把需求写成规格。
- **供给它需要的信息（context）**：把它完成任务所必需的事实、约束、资料，准确地放进它够得着的地方。

注意：这两件事的关键词，已经从"**怎么对模型说话**"，变成了"**给它什么信息、放在哪里**"。

> 当"怎么说"的边际收益趋近于零，"给什么、放哪儿"的边际收益却在飙升。于是 prompt engineering 没有消失——它**升维**成了上下文工程：从"打磨一句咒语"，升级成"经营模型这一整张桌面"。

这就是为什么这门课不叫《高级提示词技巧》，而叫《上下文工程》。

## 2. 核心矛盾：桌子太空 vs 桌子太满

既然手艺的核心是"往桌上摊什么、怎么摆"，那它的全部难度，浓缩成一道**取舍题**——夹在两个相反的失败之间：

| | 信息**太少**（桌子太空） | 信息**太多**（桌子太满） |
|---|---|---|
| 现象 | 它不知道关键事实 | 关键信息被淹没 / 装不下 |
| 后果 | **瞎猜、幻觉**（hallucination，模型一本正经编出不存在的事实） | ① **溢出**（overflow，超过 token 上限直接报错或被截断）<br>② **变慢变贵**（每个 token 都要算钱、都要时间）<br>③ **中间遗忘**（lost in the middle，模型对窗口中段的信息易视而不见，像读长文档只记得头尾） |
| 一句话 | 它没看到，所以不懂 | 它看到太多，所以抓不住 |

把这两端各起一个名字，就是本课要反复诊断的**两大失败模式**：

> **失败模式 A：窗口太空**——该给的信息没给够，模型被迫瞎猜。
> **失败模式 B：窗口太满**——塞得太多太杂，模型溢出、变慢、或在噪声里丢了重点。

注意失败模式 B 里那个最阴险的家伙——**中间遗忘**：它不像"溢出"会报错提醒你，而是**悄无声息**地让模型漏看关键信息。这正是"把资料给全反而更糟"这一反直觉现象的根源，也是 CE6 要专门拆解的诊断难题。

> 上下文工程的全部手艺，就是**在这两端之间走钢丝**：不多不少，把"正好够用"的信息，放在"模型最容易看到"的位置。

## 3. 回收四把刀，并补上欠你的两把

L4 给过你四把刀——管理桌面的四个动作。本课的任务，是把每一把都**磨成手术刀**（即每把刀各占一章，讲透原理、时机、代价、怎么落地）：

| 刀 | 一句话作用 | 直觉 | 本课哪章磨它 |
|---|---|---|---|
| 刀一 **裁剪 / 筛选** | 只放相关的，扔掉无关的 | 工具吐了 500 行日志，只把报错那 3 行摊上桌 | CE2 |
| 刀二 **压缩 / 总结** | 把长历史总结成短摘要替换原文 | 前 40 轮对话压成一段"我们做了 X、定了 Y、还差 Z" | CE3 |
| 刀三 **检索注入（RAG）** | 海量知识放窗口外，用到哪段捞哪段 | 不搬整座图书馆上桌，按需抽出那一页 | CE4 |
| 刀四 **外部记忆 / 卸载** | 信息写进文件，桌上只留指针，要用再读回 | 桌上一张便利贴："详情见 plan.md" | CE5 |

> 把四刀串成一句口诀：每一轮，对每一块信息问三遍——**它现在用得上吗？（裁剪）它能更短吗？（压缩）它能先收起来、要用再取吗？（检索 / 外部记忆）**

但 L4 作为入门母章，**欠了你两把刀**——它们不在"四把刀"里，却同样决定成败。本课补上：

- **位置与注意力布局（CE1）**：四把刀决定"放什么"，但**"放在桌子的哪个位置"同样是手艺**。模型对开头、结尾敏感，对中段易视而不见（中间遗忘）。所以"把最重要的指令放开头、把当前最关键的信息放结尾"本身就是一种控制手段——**位置即权重**。这是你磨任何一把刀之前，都要先懂的底层规律，所以排在第一章。
- **上下文失败模式与诊断（CE6）**：当 agent 突然变笨、跑偏、幻觉，怎么**反推**是桌面的哪个环节出了问题？是窗口太空，还是太满？是中间遗忘，还是被压缩弄丢了关键细节？这是把前面所有刀法**串起来当医生用**的一章。

加上导论（CE0）和把全部整合成一张解剖图的总图（Capstone），构成本课的完整版图。

## 4. 结构图：一张办公桌的分区

把"上下文窗口"这张桌子摊开，它不是一块平整的桌面，而是**有分区、分区还自带权重**的（ASCII 版，阶段二会转成 HTML）：

```
┌──────────────────────────────────────────────────────────────┐
│  上下文窗口 = 一张办公桌（总容量有 token 上限）                  │
│                                                                │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ ① SYSTEM 区（桌子最上沿 · 高权重）                       │  │
│  │   长期规则、角色、约束、工具说明                          │  │
│  │   ← CLAUDE.md / 系统提示词钉在这里（开头=模型最敏感）     │  │
│  ├────────────────────────────────────────────────────────┤  │
│  │ ② 历史消息区（桌子中段 · 最危险）                        │  │
│  │   前面几十轮的对话与工具往返                              │  │
│  │   ⚠ 中间遗忘高发区：堆越满，关键信息越容易被漏看          │  │
│  │   → 这一段最该"压缩成摘要"或"卸载到文件"（CE3 / CE5）     │  │
│  ├────────────────────────────────────────────────────────┤  │
│  │ ③ 最近消息区（靠近你这一端 · 高权重）                    │  │
│  │   当前任务、最新指令、刚到手的关键信息                    │  │
│  │   ← 把"现在最要紧的"放这儿（结尾=模型同样敏感）           │  │
│  ├────────────────────────────────────────────────────────┤  │
│  │ ④ 工具返回区（随时往桌上拍下的新纸）                     │  │
│  │   Read 的文件、检索回来的片段、命令输出                  │  │
│  │   ← 进桌前先裁剪：500 行只留报错那 3 行（CE2）            │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                                │
│  权重示意：  开头 ███  中段 ░░░（易遗忘）  结尾 ███             │
└──────────────────────────────────────────────────────────────┘
```

读图要点：桌面**不均质**——上沿（system）和近端（最近消息）是模型的"目光焦点"，中段是注意力的盲区。所以上下文工程不只是"装多少"，更是"把哪块放在焦点上、把哪块塞进盲区、把哪块干脆请下桌"。这张图就是后面六章共同要操作的对象。

## 5. Claude Code 锚点：它无时无刻不在管这张桌子

你"把 Claude Code 用到极致"的最大杠杆就在这门课。它每一轮都在替你做上下文工程——把日常现象翻译成动作，你就能看懂它在干什么、对应哪把刀：

| 你看到 / 做的 | 背后的上下文工程动作 | 对应 |
|---|---|---|
| "Compacting conversation…" | 把变长的历史**总结压缩**成短摘要，给窗口腾地方 | 刀二 压缩（CE3） |
| 它**不**把整个项目读进来，而是"按需" `Read` 某个文件 | 代码库放窗口外，**用到才捞** | 刀四 外部记忆（CE5） |
| `CLAUDE.md` / memory 文件被注入开头 | 把长期规则钉在 **system 区（开头=高权重位）** | 位置即权重（CE1） |
| 工具返回超长输出时它只引用关键几行 | 回填前**截断 / 筛选**，不把整坨塞回 | 刀一 裁剪（CE2） |
| 你主动 `/clear` 开新会话 | 清空堆积的上下文，从**干净的桌子**重新开始 | 你手动行使裁剪（CE2） |
| 用久了它"变笨 / 跑偏 / 串味" | 桌面太满、中间遗忘、上下文被旧任务污染 | 失败模式诊断（CE6） |

下次用它干活，试着透视一层：你看到的每一个动作，背后都是一次"往桌上摊什么、收什么、压什么"的取舍。本课就是把这些你已经在被动经历、却没看懂的事，变成你能主动设计的工程。

## 小练习 / 思考题

1. 用"办公桌"比喻，解释本课的核心主张："桌面管理才是 agent 智力的真正瓶颈"——为什么同一个模型会因为桌面不同而像"忽聪明忽变笨"？
2. **prompt engineering 死了吗？** 请分别说出：哪一半死了、哪一半升维成了上下文工程，并各举一个例子。
3. 默写上下文工程的**核心矛盾**（一句话），以及它两端的两大失败模式各叫什么、各有什么后果。
4. 看那张办公桌分区图：为什么"把最重要的指令放开头、把当前最要紧的信息放结尾"是一种控制手段？哪一区最危险，为什么？
5. 四把刀里，"压缩"和"外部记忆"都能给窗口省地方，它们的关键区别是什么？（提示：信息还在不在上下文里、细节丢不丢。）

<details>
<summary>参考答案</summary>

1. 模型的"脑子"是固定的，但它每一轮只能看见摊在桌上的东西。桌面干净精准 → 它思路清晰；桌面堆满杂物 → 关键信息被淹没在中段、被漏看，它看起来就变笨了。变的从来不是脑子，是桌面——所以桌面管理（上下文工程）才是你真正能动、且决定成败的瓶颈。
2. **死掉的一半**：咒语式技巧——给模型贴"20 年专家"身份、"深呼吸一步步想"、全大写感叹号吓唬模型。它们假设"用对暗号解锁隐藏能力"，模型越强越没用。**升维的一半**：精确规约意图（把要什么、什么算对说成规格）+ 供给信息（把必需的事实/资料放进它够得着的地方）。关键词从"怎么对模型说话"变成了"给它什么信息、放在哪里"——这正是上下文工程。一句话：模型越强，"怎么说"越不重要，"给它看什么、在哪儿看"越重要。
3. 核心矛盾：**信息太少则瞎猜/幻觉，太多则溢出/变慢变贵/中间遗忘**，手艺就是把"正好够用"的信息放在"模型最容易看到"的位置。两端：**窗口太空**（该给的没给，被迫瞎猜）、**窗口太满**（溢出、变慢变贵、关键信息在噪声里被漏看）。
4. 因为模型对窗口的开头和结尾最敏感、对中段易"视而不见"（中间遗忘）。开头放长期规则、结尾放当前最关键信息，就是把它们放进模型的"目光焦点"——这就是"位置即权重"。最危险的是**历史消息区（中段）**：它既是注意力盲区，又最容易堆满，关键信息常被漏看，且不会像溢出那样报错提醒你。
5. **压缩**：把历史总结成摘要替换原文，信息**仍在上下文里但丢了细节**，适合"大意要留、细节可弃"的长对话。**外部记忆**：把信息移出上下文存到文件，细节**完整保留**，桌上只留指针、要用再读回，适合"细节不能丢、但不必时刻在眼前"的大块资料。

## 一句话带走

> **上下文窗口是一张有分区、分区带权重的办公桌，而 agent 的智力瓶颈，主要不在模型脑力，而在这张桌子被管得多好。prompt engineering 没死——当"怎么说"贬值、"给什么、放哪儿"升值，它升维成了上下文工程。本课把 L4 介绍的四把刀（裁剪、压缩、检索、外部记忆）逐把磨成手术刀，并补上"位置布局"与"失败诊断"两把，教你在"太空"与"太满"之间走好钢丝。**

下一章 **CE1 位置与注意力布局**：在你磨任何一把刀之前，得先懂这张桌子的"地形"——为什么开头和结尾是模型的目光焦点，中段是盲区？"位置即权重"到底怎么用来排座位？这是你要立的第一条、也是最底层的规律。
