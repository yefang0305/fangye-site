# L1 · 一次模型调用的解剖

> 本层目标：把"和模型对话"这件事的**最底层协议**看清楚。所有 harness，无论多复杂，
> 最终都归结为一次次这样的调用。看懂这一层，你就拿到了理解后面所有层的"显微镜"。
> 对应修补的缺陷：**① 无状态（健忘）** 的第一块拼图——历史是怎么被"重新递回去"的。

---

## 0. 先讲一个画面

回到 L0 那间白房间。你想象的"对话"，其实更像**寄信**：

你每次都要把**一整叠纸**从门缝塞进去——最上面一张写着"你是谁、按什么规矩答"，中间夹着"我们之前聊过的所有信件复印件"，最下面才是你这次的新问题。顾问读完**整叠**，在最后写一段回信塞出来。然后他失忆。下次你再寄，又得把**整叠（包括上次的回信）重新复印一份**塞进去。

这"一整叠纸"，就是一次模型调用的全部输入。它有个正式名字叫 **prompt（提示词，其实就是"这次喂给模型的全部文字"）**。本层就来拆解这叠纸长什么样。

---

## 1. 模型缺了什么：它没有"记忆"，只有"这次的输入"

L0 说过模型无状态。具体到一次调用，意味着：**模型能用的信息，100% 来自你这次塞给它的那叠纸，多一个字都没有。** 它不会"想起"昨天，不会"知道"你是谁，除非你把这些**写在纸上一起塞进去**。

所以 harness 的第一个、也是最基础的工作就是：**每次调用前，把该让模型知道的一切，组装成一叠结构正确的纸。** 这个组装动作，是后面所有花活（上下文工程、记忆、工具）的共同地基。

---

## 2. 这层怎么补：messages 三件套

现代模型的"那叠纸"不是一团乱文字，而是一个**有角色标签的消息列表**（messages）。每条消息标明"谁说的"。主要三种角色：

| 角色 | 中文 | 作用 | 谁来写 |
|---|---|---|---|
| **system** | 系统指令 | 定调子：模型的身份、规则、口吻、能力边界。整段对话的"宪法" | 开发者（harness）|
| **user** | 用户 | 用户说的话 / 提的问题 | 用户，或 harness 代填 |
| **assistant** | 助手 | 模型自己之前说过的话 | 模型（上一轮的输出）|

一次调用的输入，就是这样一个**按时间排好序的列表**，例如：

```
[
  { role: "system",    content: "你是一个简洁的编程助手，回答用中文。" },
  { role: "user",      content: "什么是递归？" },
  { role: "assistant", content: "递归就是函数自己调用自己……" },   ← 这是上一轮模型的回答
  { role: "user",      content: "举个生活里的例子" }              ← 这是本轮新问题
]
```

模型读完**整个列表**，生成下一条 `assistant` 消息。

> **关键洞察：所谓"多轮对话"，根本不是模型在记忆，而是 harness 每轮都把这个 list 不断变长后整段重发。**
> 第 10 轮时，前 9 轮的所有 user 和 assistant 消息，都被原样塞在列表里重发一遍。模型每次都是"第一次"读到这一整段，临时表现得好像"记得"。
> 这就解释了 L0 那道判断题：**记忆在 harness 的这个 list 里，不在模型里。** 也预告了 L4 的矛盾——list 越长，越贵、越慢、越容易溢出。

### system 提示词：harness 最重要的一把旋钮

`system` 是开发者专属的"定调"通道。Claude Code 那一长串"你是 Claude Code……"的行为规范，就是塞在 system 里的。它决定了模型的人格、规矩和能力边界——**改 system，等于换一个 agent 的"操作系统"**。这是 harness 工程师手里最有力、最廉价的控制杆。

---

## 3. 底层原理：token、上下文窗口、和那几个旋钮

要真懂这层，得认识模型"读"和"写"的计量单位，以及你能拧的几个旋钮。

### token（令牌）——模型的"字"

模型不按汉字/字母计数，而按 **token**（令牌，模型处理文字的最小单位，约等于 0.75 个英文单词、或半个~1 个汉字）切分文字。一句"你好世界"大约是 2–4 个 token。**为什么你要在乎它？** 因为：

- **你按 token 付费**（输入 token + 输出 token 分别计费）；
- **上下文窗口按 token 算上限**；
- 所以"省 token"≈"省钱 + 提速 + 不溢出"，这是 harness 工程的核心约束之一。

### 上下文窗口（context window）——工作台大小

模型一次能"摊开"的 token 总量上限（输入 + 输出共用这个预算）。比如某模型 20 万 token，意味着你那叠纸（messages 全部内容）加上它要写的回答，**加起来不能超过 20 万 token**，超了就报错或被截断。L4 整层都在和这个上限搏斗。

### 几个常用旋钮（采样参数）

模型生成是"挑下一个最可能的 token"，这几个旋钮调它怎么挑：

| 旋钮 | 中文 | 作用 | 直觉 |
|---|---|---|---|
| **temperature** | 温度 | 控制随机性/创造性。0=最确定保守，高=更发散 | 写代码调低、写诗调高 |
| **max_tokens** | 最大输出长度 | 限制这次最多写多少 token | 防它啰嗦/失控，也控成本 |
| **stop** | 停止序列 | 遇到某串字就停笔 | 让输出在你要的地方截断 |

> 原理一句话：**一次调用 = 把一个 messages 列表喂进去，模型在上下文窗口的预算内、按采样旋钮，逐个 token 续写出下一条 assistant 消息。** 整门课所有复杂系统，拆到底都是这个动作的反复。

### 流式输出（streaming）——为什么是一个字一个字蹦出来

你看 Claude Code/ChatGPT 回答是逐字"打字机"效果，这叫 **streaming（流式）**：模型每生成一个 token 就立刻发回来，不等整段写完。这纯粹是 harness 的体验优化（让你早点看到、可随时打断），不改变模型本质。

---

## 4. Claude Code 锚点：你每条消息背后那叠纸

在 Claude Code 里，你看到的是一个干净聊天框；背后每次你回车，harness 都在悄悄组装那个 messages 列表：

| 你看到的 | 背后 harness 在 messages 里放了什么 |
|---|---|
| 那一长串内置行为规范 | 一条巨大的 **system** 消息（身份、规则、工具说明、安全约束）|
| `CLAUDE.md`、memory 文件 | 作为 system 或开头 user 消息**注入**进去（L4/L5 细讲）|
| 你打的字 | 一条 **user** 消息 |
| 它上一轮的回答、调用过的工具结果 | 一条条 **assistant** 消息和工具结果消息（L2 讲）|
| 对话太长时"压缩了历史" | harness 把前面一堆 messages **总结成一条短消息**替换掉，给窗口腾地方（L4）|

下次用 Claude Code，心里默想："我这一句，被它包进了一个多大的 messages 列表里？" ——你就拥有了 token 视角。这也是为什么"开新会话"能让它变快变省：list 被清空，重新从短开始。

## 5. 小练习 / 思考题

1. 你和模型聊到第 5 轮。请描述这一轮 harness 喂进去的 messages 列表大致包含哪些消息（按角色和顺序）。
2. **判断对错**：把 `temperature` 调到 0，模型就不会再说错话/产生幻觉了。
3. 为什么"开一个新会话"往往比"在超长的老会话里继续问"更快、更省钱？用 token 和上下文窗口解释。
4. system 消息和 user 消息，哪个更适合放"你必须始终用中文回答"这条规则？为什么？
5. 自检：不看上文，说出一次模型调用的输入是什么结构（含三种角色各自的作用），以及 token 和上下文窗口的关系。

<details>
<summary>参考答案</summary>

1. 大致：1 条 system（定调）+ 交替的 user/assistant 历史（第1~4轮的问与答，共约 8 条）+ 本轮 1 条新的 user。模型读完这整串再生成第 5 轮的 assistant 回答。
2. **错。** temperature 控制的是"随机性/发散度"，调到 0 只是让输出更确定、更可复现，但模型照样可能**确定地编造**一个错误事实。幻觉是模型本质问题（L0 缺陷⑤），靠采样旋钮治不了，得靠 L7 的验证手段。
3. 老会话里，前面所有轮次的 messages 每轮都被重新整段塞回去，token 越堆越多——越贵、越慢、还可能逼近窗口上限触发压缩。新会话把 list 清空，从极短重新开始。
4. 放 **system**。system 是整段对话的"宪法"，优先级和稳定性最高，规则放这里最不容易被后面的对话冲淡；放在某条 user 里则容易随对话推进被"淹没"。
5. （对照正文：messages 列表，system 定调/user 提问/assistant 历史回答；token 是计费与计量单位，上下文窗口是 token 总量上限，输入+输出共用。）

</details>

## 一句话带走

> **和模型的每一次交互，本质都是"组装一个带角色标签的 messages 列表、塞进上下文窗口、按旋钮续写出下一条消息"。所谓记忆、对话、人格，全是 harness 在这叠纸上做文章——而 token 是这一切的计价器和容量表。**

下一层 **L2**，我们装上第一件让模型能"碰到真实世界"的设备：**工具调用**。你会看到模型其实从不亲自动手——它只会"写一张申请单"。
