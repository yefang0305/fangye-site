# LE2 · 停止与预算：循环的缰绳

> 本章目标：拧第二个旋钮——**循环转多久、花多少、什么时候该停下问人**。自主循环是放权，而放权必须配硬边界，否则发动机会空转到烧光一切。
> 拧的旋钮：② 停止条件与预算（stopping & budget）。

---

## 0. 先讲一个画面

你雇的装修工不会自己喊停。给他一面墙，他可能：

- 为了一个肉眼几乎看不见的色差，**无限返工**，刷到天荒地老；
- 或者陷进"补一道→发现又有瑕疵→再补→又有瑕疵"的**死循环**，停不下来。

所以正常雇人，你一定会先约法三章："**最多干 8 小时**、**材料费别超 500**、**拿不准的地方先打电话问我**、**刷完整面白了就停下报告**。" 这几条规矩，就是循环的**缰绳**。agent loop 一模一样——它本身只会一圈圈转下去，是你必须在外面给它套上多重上限。

> 关系说明：Harness L3 提过一句"循环要有 `max_steps` 硬刹车"。本章把这一句展开成一整套缰绳——步数只是其中一根。

---

## 1. 核心概念：四种缰绳 + 一个完成判定

| 缰绳 | 大白话 | 防的是 |
|---|---|---|
| **max_steps**（最大步数） | 走够 N 步就强制停 | 死循环（无限申请→失败→再申请） |
| **token / 成本预算**（budget） | 累计烧到上限就停 | 烧钱（步数不多但每步巨贵） |
| **时间预算**（timeout，墙钟超时） | 真实时间超过上限就停 | 卡死、外部依赖把整圈拖住 |
| **停下问人**（escalation，升级给人） | 命中高风险/低把握就交还控制权 | 闯祸（删库、花钱、不可逆操作） |
| 完成判定（done check） | 模型不再开工具申请单 = 它认为做完了 | （正常退出，不是异常刹车） |

术语注释：
- **max_steps**：循环允许转的最大圈数上限。撞上它就强制 break，把控制权交还给人。
- **预算（budget）**：给单个任务设的资源天花板，通常同时设 token、钱、时间三种，**任一先触发就停**。
- **升级 / 停下问人（escalation / human-in-the-loop 入口）**：循环主动暂停、把决定权交还人类的机制。它是 LE6 外循环里"人在环"在内循环这一侧的入口。

---

## 2. 原理"为什么"：放权必须配硬边界

LE0 说过，循环给了模型"自主连续行动"的自由。但自由有代价：

- 模型可能**误判任务没完成**，一直觉得"还差一点"，于是无限转下去；
- 也可能陷入**失败死循环**：申请同一个会失败的操作，失败，再申请，再失败；
- 还可能**方向没错但代价失控**：每步都"合理"，但 80 步下来 token 和钱已经烧爆。

所以有一条铁律：

> **永远不要给 agent 无限循环的权力。** 任何上线的循环都必须有"最先触发的那个上限"兜底。

而且单一缰绳不够——只设步数不设成本，可能 10 步就烧掉几十块；只设成本不设"停下问人"，它可能在预算内默默执行了一个不可逆的危险操作。**好的停止策略 = 多重上限并联，谁先触发听谁的，外加一个'高风险就升级给人'的旁路。**

> 原理一句话：**循环的自主性和它的缰绳是一对：放出多少自由，就要预设多少硬边界。缰绳不是限制智能，而是让"放权"这件事变得可以承受。**

## 3. 结构图：每转一圈先过一遍护栏

```
        ┌──────────── 每圈开头：检查所有缰绳 ────────────┐
        │  步数 ≥ max_steps ?  ──┐                       │
        │  花费 ≥ 预算 ?      ──┤                        │
任务 →  │  耗时 ≥ 超时 ?      ──┼─ 任一为真 → break，交还人 │
        │  命中高风险动作 ?    ──┘  ↘ 升级：停下问人        │
        └────────────────────────────┬───────────────────┘
                                      │ 全部为假
                                      ▼
                          模型走一步（想 + 可能开工具单）
                                      │
                       不再开工具单？ ── 是 → 完成，正常退出
                                      │ 否
                                      ▼
                          执行工具 → 结果回填 → 回到圈开头
```

读图要点：缰绳检查在**每一圈的最前面**，是循环的护栏；"完成判定"是正常出口，"撞上限/升级"是保险出口。

## 4. Claude Code 锚点：你早就用过这些缰绳

| 你在 Claude Code 里 | 对应哪根缰绳 |
|---|---|
| 它干了很久、转了很多圈后自己停下来说"我先停在这里" | 撞上 **max_steps / 时间预算** |
| 它要做删除、覆盖、`git push` 等危险操作前停下来征求你同意 | **停下问人（升级）**——高风险动作不自动执行 |
| 你按 **Esc** 打断它 | 你手动拉了一把缰绳（人始终握着最高优先级的刹车） |
| 它判断活干完了、不再调工具、给你总结 | **完成判定**——正常退出 |

观察练习：留意它在什么动作前会停下来问你（通常是不可逆 / 要花钱 / 动外部世界的操作）——那条线就是"停下问人"这根缰绳划的。它体现了一个好原则：**低风险自动做，高风险交还人。**

## 5. 小练习 / 思考题

1. 为什么循环里**必须**有 max_steps？只靠"模型自己判断做完了"会出什么事？
2. 只设步数上限、不设成本上限，可能出什么问题？反过来呢？
3. 列三种典型的"应该停下问人（升级）"的情形。
4. 一句话说清：循环的"自主性"和"缰绳"是什么关系？

<details>
<summary>参考答案</summary>

1. 防死循环 / 防失控。模型可能误判"还没做完"而无限转，或陷入"申请→失败→再申请"的死循环；没有 max_steps，它会无限烧 token、无限运行。它是必备的硬刹车。
2. 只设步数不设成本：可能步数不多但每步巨贵（如每步调一个昂贵工具），10 步就烧爆预算。只设成本不设"停下问人"：它可能在预算内默默执行了一个不可逆的危险操作。所以要多重并联。
3. ①不可逆/高破坏操作（删文件、改生产数据、`git push --force`）；②要花钱/动真实世界（下单、发邮件、转账）；③模型自身把握很低或反复失败时（与其乱试不如交还人判断）。
4. 放出多少自由，就要预设多少硬边界——缰绳让"放权"变得可以承受；自主性和缰绳是同一枚硬币的两面。

</details>

## 一句话带走

> **第二个旋钮是缰绳：max_steps、成本预算、时间预算、停下问人——多重上限并联，谁先触发听谁的。循环的自主性和它的缰绳是一对，放出多少自由就要先设多少硬边界。永远不给 agent 无限循环的权力。**

下一章 **LE3 纠错与反思**：缰绳管住了"别跑太远太久"，但循环转的过程中必然会出错。好的循环不怕错——它能把"失败"变成"下一圈的燃料"。这一章拧的，就是让循环从错误里学习的旋钮。
