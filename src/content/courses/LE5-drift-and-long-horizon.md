# LE5 · 漂移与长程控制

> 本章目标：拧第五个、也是内循环最难的一个旋钮——**让循环连续转几十步还不跑题**。它综合前面所有旋钮，去对抗一个幽灵般的敌人：漂移。这是本课最独特、市面最缺的一章。
> 拧的旋钮：⑤ 长程控制（long-horizon control）。

---

## 0. 先讲一个画面

你雇的工人要刷一整栋楼的墙，颜色是"米白"。前几面，完美。

刷到第 40 面时，出事了——但不是塌方那种显眼的事故。是他**不知不觉**地，把米白刷成了奶黄。你回放监控，发现每一步都"合理"：他对着上一面墙调色，每面只比前一面深一点点，没有任何一步是错的。可 40 面累积下来，已经和最初的米白差了十万八千里。而且他自己浑然不觉，还觉得刷得挺好。

这种**悄悄跑题**，就是 **漂移（drift）**。它是长循环的头号杀手，因为它不报错、不崩溃、每一步都看似正确——你发现时，往往已经偏得很远。

---

## 1. 核心概念：漂移，以及把目标"顶回眼前"的几把手段

| 概念 | 大白话 | 作用 |
|---|---|---|
| **漂移**（drift） | 循环转久了慢慢偏离原目标，每步局部合理但整体跑题 | 这是要对抗的敌人 |
| **中间遗忘**（lost in the middle） | 长上下文里，夹在中段的信息容易被模型忽略 | 漂移的一大成因 |
| **状态摘要**（periodic summary） | 每隔几步，把"目标+已做+待做"压成一小段重新摆到眼前 | 给循环一个"随身进度条" |
| **re-grounding**（重新锚定） | 定期把原始目标/约束原文重念一遍 | 把"我要去哪"顶回最显眼处 |
| **计划重述**（plan restatement） | 让模型每隔几步复述当前计划，发现偏了当场纠 | 早发现、早纠偏 |

术语注释：
- **漂移（drift）**：agent 在长循环中渐进式偏离初始目标的现象。关键特征是"每一步都局部合理，但累积起来整体跑偏"，且通常无报错、不自知。
- **中间遗忘（lost in the middle）**：模型处理长上下文时，对开头和结尾的信息记得清、对夹在**中段**的信息容易忽略的现象（呼应 Harness L4）。任务目标常常被写在最开头，循环转久后它就被埋进了"中段"。
- **re-grounding（重新锚定）**：周期性地把"原始目标、硬约束"重新注入到上下文最显眼的位置，对抗目标被埋没。

---

## 2. 原理"为什么"：漂移从哪来，长程控制凭什么有效

漂移不是模型"变笨"，它有两个结构性成因：

1. **每步只看局部。** 内循环本质是"走一步、看上一步结果、决定下一步"。模型在每个当下都对着**最近的上下文**做决定，而不是对着"最初的总目标"。局部最优一步步叠加，就漂出了全局。
2. **目标被埋进了中段。** 任务目标通常写在 messages 最开头。循环转了几十圈后，开头那段被几十步的过程淹没，正好落进"中间遗忘"的盲区——模型实际上"看不太到"原始目标了。

理解了成因，解药就只有一句话：

> **长程控制的核心手艺 = 周期性地把"你是谁、要去哪、走到哪了"重新顶到上下文最显眼的地方。**

状态摘要、re-grounding、计划重述，本质都是这一件事的不同做法——它们都在对抗"目标下沉、局部主导"。这也回收了前几章：LE2 的缰绳防"跑太久"，LE4 的嵌套把长循环拆短（短循环没机会漂），而它们最终都服务于同一个目的——**别让循环跑得又长又野**。换句话说，本章是前面所有旋钮的"汇流点"。

> 原理一句话：**漂移源于"每步只看局部 + 目标沉入中段"。对抗它，不是让模型更聪明，而是反复地、主动地把目标和进度重新摆回它眼前——长程控制是一门'不断提醒'的工程。**

## 3. 结构图：每隔 N 步插一个锚点

```
任务目标(米白) │
               ▼
  步1 步2 步3 …………… 步N ┃ 📌 锚点 ┃ 步N+1 …… 步2N ┃ 📌 锚点 ┃ ……
  └─局部决策一步步累积─┘    ▲          └──────────────┘    ▲
                           │                              │
                    re-ground / 状态摘要：          再来一次：
                    "目标=米白；已刷39面；          把目标+进度
                     注意别越调越深；待刷…"          重新顶到眼前

  没有锚点：目标沉入中段 → 漂移（奶黄）
  有锚点：  目标周期性回到最显眼处 → 守住米白
```

## 4. Claude Code 锚点：它怎么防自己跑题

| 你在 Claude Code 看到 | 对应哪种长程控制 |
|---|---|
| 长任务里它维护一个 TodoWrite 清单，边做边勾、时不时回看 | **状态摘要 / 进度追踪**——给循环一个随身进度条 |
| 它干到一半复述一遍"我现在的计划是…还差…" | **计划重述**——早发现偏没偏 |
| `CLAUDE.md` 里写的项目目标/约束被反复带进上下文 | **re-grounding**——把硬约束持续顶回眼前 |
| 长任务跑久后它产出的东西开始"跑题"，需要你拉回来 | 你目睹了一次**漂移**——以及为什么需要本章的手段 |

观察练习：给它一个需要很多步的大任务，留意它有没有**周期性地回看清单 / 复述目标**。做得好的长任务，几乎都能看到这种"时不时把自己拉回主线"的动作；而当它开始跑题，往往正是因为目标在长上下文里沉下去了——这时你手动重申一遍目标（相当于帮它 re-ground），它常常立刻回正。

## 5. 小练习 / 思考题

1. 漂移最反直觉的地方是什么？为什么说它"每步都合理，却整体跑偏"？
2. 漂移的两个结构性成因是什么？（一个关于"看哪里"，一个关于"目标在哪"）
3. 状态摘要、re-grounding、计划重述本质上是同一件事——是哪件事？
4. 为什么说本章是"前几章所有旋钮的汇流点"？（提示：LE2 缰绳、LE4 嵌套各自怎么帮着对抗漂移）

<details>
<summary>参考答案</summary>

1. 它不报错、不崩溃、不自知。每一步都对着最近的上下文做了局部合理的决定，没有任何一步显眼地"错"，但局部最优一步步累积就漂出了全局——等你发现时已经偏得很远。
2. ①每步只看局部：模型在每个当下对着最近的上下文决策，而非对着最初总目标；②目标沉入中段：目标写在开头，循环转久后被过程淹没，落入"中间遗忘"盲区。
3. 都是"**周期性地把目标和进度重新顶到上下文最显眼的地方**"。三者只是这件事的不同做法（摘要进度 / 重念目标 / 复述计划）。
4. 因为它们最终都服务于"别让循环又长又野"：LE2 的缰绳直接限制"跑太久"；LE4 的嵌套把长循环拆成短子循环，而短循环根本没机会漂。长程控制是在"必须长跑"时的最后一道防线，把前面的手段汇到一处。

</details>

## 一句话带走

> **第五个旋钮是长程控制：漂移源于"每步只看局部 + 目标沉入中段"，它不报错、不自知、最致命。对抗它不靠更聪明的模型，而靠周期性地把"你是谁、要去哪、走到哪了"重新顶回眼前——状态摘要、re-grounding、计划重述都是这一件事。长程控制是一门"不断提醒"的工程。**
