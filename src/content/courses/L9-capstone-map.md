> 能力进阶式（B 骨架）的好处是叙事顺；代价是知识点散在九层里。这张总图把它们收束成

---

## 1. 一句话回顾整门课

> **裸模型是一个被锁在白房间里、聪明但失忆、只会说话的天才。Harness engineering 就是一件一件地给它装设备——直到它变成一个能行动、能持续、能记忆、能组队、还靠谱、且能交付给百万用户的 agent。所有"AI 会做事"的魔法，都不在模型里，在你能亲手设计的这层外壳里。**

---

## 2. 进化链：从裸模型到生产级 agent

每一层补一个缺陷、加一件设备。竖着读，就是模型"长大成人"的全过程：

```
   裸模型(L0)         一个聪明但失忆、不能动、装不下、会编的"纯函数"
      │
   + 调用协议(L1)     用 messages(system/user/assistant) + token + 窗口 和它对话
      │               └ 补"无状态"的第一块:历史靠 harness 整叠重发
   + 工具(L2)         给它"手":模型开申请单 → harness 真执行 → 结果回填
      │               └ 补"不能行动" ★最关键的一跃
   + 循环(L3)         一个 while:走一步→看结果→再走,直到完成
      │               └ 补"不能持续" ★聊天机器人↗智能体的分水岭
   + 上下文工程(L4)   有限桌面上裁剪/压缩/检索/外部记忆,只放最该放的
      │               └ 补"装不下" + 治"中间遗忘"
   + 记忆(L5)         跨会话的笔记本:写/读/更新/忘,把往事按需捞回上下文
      │               └ 补"无状态"的终极版(其实是 L4 的特例)
   + 子代理(L6)       一个 agent→一支团队:多张干净桌子,隔离+并行
      │               └ 绕过单窗口上限、放大产能
   + 可靠性(L7)       缰绳:验证门/计划-执行分离/复查/人在环路
      │               └ 补"会幻觉/不可靠" ★从"能跑"到"敢托付"
   + 产品化(L8)       算三笔账:延迟、成本、边界
      ▼               └ 从"能交付给我"到"能交付给百万人"
   生产级 Agent
```

## 3. 全景解剖图（横切视角）

L0–L8 是"怎么长出来"的纵向叙事；下面这张是"长成后长什么样"的横向解剖——一个成熟 agent 同时运转的所有部件：

```
   ┌──────────────────────────── 一个成熟 AGENT ────────────────────────────┐
   │                                                                        │
   │   ┌─────────┐   申请单    ┌──────────────── HARNESS(外壳) ───────────┐ │
   │   │  模型    │ ─────────▶ │                                          │ │
   │   │ (大脑)   │ ◀───────── │  • 调用层:组装 messages、采样旋钮 (L1)   │ │
   │   │ 只负责    │   结果      │  • 工具层:定义/执行/回填 + 权限闸 (L2)  │ │
   │   │ "判断"   │            │  • 循环层:while 驱动 + max_steps (L3)    │ │
   │   └─────────┘            │  • 上下文层:裁剪/压缩/检索/外部记忆 (L4) │ │
   │                          │  • 记忆层:跨会话档案 写/读/更新/忘 (L5)  │ │
   │                          │  • 编排层:派子代理、并行/串行 (L6)       │ │
   │                          │  • 可靠层:验证门/复查/计划/人在环路 (L7) │ │
   │                          │  • 产品层:延迟/成本/安全 的权衡 (L8)     │ │
   │                          └──────────────────┬───────────────────────┘ │
   └────────────────────────────────────────────┼────────────────────────────┘
                                                ▼
                               真实世界(文件/终端/网络/知识库/用户)
```

**读图口诀**：模型只做**判断**，外壳负责**确定性**的一切——组装、执行、循环、记忆、编排、兜底、权衡。两者在正确的边界上拼接，就是一个 agent。

## 4. 缺陷 ↔ 解法 对照总表（最该背下来的一张）

整门课其实就是这张表。看任何 agent，都能用它逐格盘问"这一格它怎么做的？"：

| 模型先天缺陷(L0) | 主要由哪层修补 | 一句话解法 |
|---|---|---|
| ① 无状态(健忘) | L1 + L4 + L5 | 历史整叠重发 / 上下文管理 / 跨会话记忆档案 |
| ② 不能行动 | **L2** | 工具调用:模型开申请单、harness 真执行 |
| ③ 不能持续 | **L3** | agent loop:while 循环驱动多步 |
| ④ 容量有限 | **L4**（+L6） | 上下文工程四把刀(+子代理多开几张桌) |
| ⑤ 会幻觉/不可靠 | **L7** | 验证门、复查、计划-执行分离、人在环路 |
| （横切）成本/速度/安全 | L8 | 流式、缓存、模型路由、权限边界、降级 |

## 5. 三套"随身工具":拿去解剖任何 agent

学完这门课，你应该能在看到任意一个 agent 产品时，下意识掏出这三套问题：

**① 逐层盘问（够不够全）**
> 它怎么和模型对话(L1)？挂了哪些工具、权限怎么管(L2)？能自主走几步、怎么停(L3)？上下文怎么管、会不会变笨(L4)？记得跨会话的事吗(L5)？会派子代理吗(L6)？靠什么保证不跑偏(L7)？延迟/成本/安全怎么权衡(L8)？

**② 缺陷对照（治没治本）**
> 拿第 4 节的表，逐个缺陷问"这一格它怎么补的、补得好不好？"

**③ 取舍审视（产品视角）**
> 它在"更强⇄更快省""更自主⇄更可控""更全⇄更准"这几条轴上，分别站在哪、为什么这么选？
