# LE1 · 三级跳：从 Prompt 到 Context 到 Loop

> 本层目标：看清 AI 开发的四层技术栈，搞懂每一层的管辖边界，明确你的定位是如何从“调提示词”一层层往上跳跃的。

---

## 0. 先讲一个画面

这两年 AI 领域诞生了无数打着“XX Engineering”旗号的新词。你可能会觉得这只是一群人在换皮炒作。 But wait，如果我们把这些概念叠起来，你会发现它们并不是互相替代的，而是一个逐层往上盖的“四层栈”：

你最初在写一句话（Prompt），接着你在管理一个窗口（Context），后来你在武装一次运行（Harness），现在你在组装一个自己会跑的循环（Loop）。

每往上一层，你操心的对象就大了一号。认清这个技术栈，你才能明白，当你开始做 Loop 时，你到底在写什么代码。

---

## 1. 四层栈：先摆出来

我们把这四层技术栈的职能和核心问题摆在桌面上：

| 层级 | 管辖范围 | 核心问题 |
|---|---|---|
| **Prompt Engineering** | 写好一次的提示词 | 我这一句该告诉大模型什么？ |
| **Context Engineering** | 这一刻窗口里放什么 | 怎么检索、摘要什么、过滤掉什么噪音？ |
| **Harness Engineering** | 单次运行的武装 | 给哪些工具、允许哪些动作、什么算任务完成？ |
| **Loop Engineering** | 在 Harness 之上调度 | 怎么让它脱离人类，自己一遍遍跑起来？ |

---

## 2. 逐层拆解：我们在往上跳什么？

### 第一层：Prompt，你写给模型的那句话
最底层，也是大家最熟悉的。你斟酌措辞、给例子、调语气。
它的边界很短：**就是这一次，你递给模型的这几个字符。**
它的缺陷很明显：它假设你必须人肉在场。AI 答完一句就停了，等你写下一句。

### 第二层：Context，这一刻窗口里放什么
往上跳一层，问题变了。模型的输入窗口是有上限的，而且“塞入的噪音越多，模型越傻”。
Context Engineering 管的是**大模型的当下视野**。它不关心你用什么词，它关心在这一瞬间，大模型能看到哪些文件、哪些历史聊天、哪些被压缩后的摘要。它管的是“信息流的运行时治理”。

### 第三层：Harness，单次运行的全套装备
再往上，管的是 **Agent 跑一次（Session）需要带什么装备**。
你要给它配置读写文件的接口、运行代码的 Sandbox（沙箱）、决定什么时候强制掐断它的运行（max_steps 缰绳），以及怎么定义“这次运行通过了”。Harness 负责包装出一个能干活的单次 Agent，但它不负责让这个 Agent 自动重来。

### 第四层：Loop，让它自己一遍遍跑
最顶层，就是 Loop Engineering。
你手里有了一个装备齐全的 Agent，但它跑完就歇着了。Loop 的任务是**把“等你按按钮”这件事也自动化掉**。
实现这个飞跃，主要多了三样东西：
* **在定时器上跑**：给它装个闹钟，到点自己醒、自己干活。
* **孵化小帮手**：单次运行只关心一个 Agent，Loop 关心一群 Agent 怎么互相合作、谁当 Maker 写代码，谁当 Checker 审代码。
* **自我喂食（Feedback Loop）**：把上一次运行的输出（如昨天留下未修的 Bug 状态文件）自动读进来，作为下一轮的输入，实现跨对话的持续记忆。

## 3. 小练习 / 思考题

1. 当你在用 Cursor 或 Copilot 时，你在哪些时刻是在做 Prompt，哪些时刻在做 Context？
2. 为什么说“少了‘自己醒、自己接力’，剩下的就只是把 Harness 手动按了很多遍”？
3. 随着你的开发层级从第一层往第四层跳跃，你在项目中的核心价值发生了什么变化？

---

## 一句话带走

> **AI 开发分为四层技术栈：Prompt 管一句话，Context 管一窗户，Harness 管一次跑，Loop 管自己跑下去。Loop Engineering 坐在最顶层，它通过定时器、子代理协作和磁盘状态落盘，把人从人肉触发的循环里解放出来。**
