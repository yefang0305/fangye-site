# CE5 · 外部记忆与跨会话：桌上只留一张便利贴，要看再去读

> 本章目标：磨亮 L4 的**刀四 外部记忆 / 卸载（offloading）**——把信息移出窗口、写进文件，桌上只留一个"去哪取"的指针，要用再读回；并吸收 L4 末尾预告的"记忆"视角，把它升级成**跨会话记忆**：怎么让 agent 跨对话、跨天还记得你的偏好与项目约定。本章深挖 L4「刀四 外部记忆/卸载」，并接住它结尾欠你的那一课——记忆，本质上就是上下文工程的一个特例。
> 拧的旋钮：当"信息细节不能丢、又不必时刻在眼前"，**把它从桌面卸载到外部存储，桌上只留指针**。

---

## 0. 先讲一个画面

上一章 **CE4 检索注入（RAG）**，捞的是一座**静态、共享、海量**的图书馆——产品文档、知识手册，它们一直睡在窗口外的书架上，等你来查。那是别人写好、放在那儿不动的**外部知识**。

这一章的东西不一样：它是 agent **自己跑任务时当场产出**的——这一轮算到哪了、刚才定了哪个方案、上次帮你记下了什么偏好。这些不是图书馆里现成的书，而是 agent **一边干一边长出来**的状态。

来看一个画面。你让 agent 做一个复杂任务，它先想出了一套详细方案——十几步、每步带理由，洋洋洒洒三页纸。

- **笨办法**：把这三页方案一直摊在桌上。接下来它每做一步，桌上都压着这三页；做到第八步时，桌上既有三页方案、又有七步的执行记录、还有各种工具返回——**桌子很快堆满**，关键的"当前这一步"被埋进纸山中段，中间遗忘高发。
- **聪明办法**：把三页方案**写进一个文件 `plan.md`**，桌上只留一张便利贴——"详细方案见 `plan.md`"。然后它该干第几步就干第几步，桌面始终清爽；万一忘了下一步是什么，再照着便利贴**翻开 `plan.md` 读那一段**回来。

> **这就是刀四（外部记忆）的全部直觉：不需要时刻盯着的信息，写到外部文件去；桌上只留一个指针，要用再读回来。** 桌面这张有限的办公桌，因此接上了一块"无限大的硬盘"。

CE4 是把**别人的图书馆**挡在窗外按需取；CE5 是把 **agent 自己的草稿、状态、记忆**卸到窗外按需取。前者捞静态知识，后者管动态状态——这是刀三和刀四最干净的分界，本章第 3 节会专门划清这条线。

## 1. 核心概念：四个把信息"挪出窗口"的零件

刀四听起来朴素，但藏着四个层次分明的零件。一句话说清每个干什么：

| 概念 | 大白话 | 类比（办公桌） |
|---|---|---|
| **外部记忆 / 卸载**（offloading，把信息移出窗口、写进外部存储） | 把暂时不必在眼前的信息**写到文件**，从桌上请下去，腾出窗口 | 把厚资料收进抽屉，桌面留空 |
| **草稿纸**（scratchpad，任务内的临时记事本） | 在**单次任务过程中**，把中间结果、待办、想法随手记到一个外部文件，而不是全堆在对话里 | 手边一张草稿纸，演算过程写它上面，不占正式桌面 |
| **指针**（pointer，窗口里只留的那个"去哪取"的引用） | 桌上不放内容本身，只放一句"内容在哪个文件、哪一节" | 便利贴："详细方案见 `plan.md`" |
| **跨会话记忆**（cross-session memory，跨对话/跨天记住的东西） | 把"该长期记住"的用户偏好、项目约定写进固定文件，**下次开新对话自动读回** | 贴在工位墙上的便签，明天来了第一眼就看见 |

术语再补两句，这两个区别是本章的命门：

- **指针 vs 内容**：指针是"地址"，内容是"东西本身"。卸载的精髓就是**桌上只放地址，东西本身搁在硬盘里**。一个指针可能只占几十个 token，它指向的文件却可能有几千行——这就是为什么卸载能凭空"省"出大片桌面。
- **任务内（草稿纸） vs 跨任务（记忆）**：草稿纸是**一次性**的，任务做完即可丢；跨会话记忆是**长期**的，专门用来跨越"对话结束、窗口清空"这道坎。两者都是卸载到文件，但**寿命**和**用途**完全不同——这正是 L4 把"刀四"和"记忆系统"分开讲、而本章把它们合到一起的原因：它们是同一个动作（写到窗外）的短期版和长期版。

把四个零件串成一句话：**任务进行中，用草稿纸卸载中间状态、桌上留指针按需读回（短期）；任务结束后，把该长期记住的偏好与约定写进记忆文件，下次开新会话自动召回（长期）。**

## 2. 原理"为什么"：把硬盘变成外部记忆，而记忆只是一道检索题

### 为什么要往窗外写？因为窗口有上限，硬盘没有

回到 CE0 钉死的核心矛盾——桌子太空 vs 桌子太满。一个跑了几十步的复杂任务，如果把**全过程**都堆在窗口里，必然走向"太满"：溢出、变慢变贵、中间遗忘三宗罪。

刀四的破法很彻底：**承认窗口永远有限，于是把窗口外那块近乎无限的硬盘，接成 agent 的"外部记忆"。** 桌面只负责"当下这一步要看的东西"，其余全卸到文件里——要用,再凭指针 `Read` 回来。窗口上限这道墙，就这样被绕了过去。

这呼应 CE0 那条原则：**"少而精"常胜"多而杂"**。把方案卸到 `plan.md`、桌上只留一行指针，模型每一步看到的都是干净的当下，而不是被三页方案 + 七步记录淹没。**省下来的不只是 token，更是注意力。**

### 记忆的本质：不是"记住一切"，而是"该把哪条往事捞回桌上"

这是本章最该想通的一层，也是 L4 结尾埋的那个钩子。

新手对"记忆"的想象是：让 agent 把所有往事都记住、都带在身上。但你已经学过 CE0 到 CE4 了——**把一切都带在桌上，恰恰是灾难**：桌子爆满、关键被淹没。

所以真正的记忆系统从不"记住一切"。它做的是另一件事：

> **记忆的本质 = 一道检索题——在浩如烟海的往事里，判断"这一刻该把哪一条捞回桌上"。** 往事全睡在窗外的文件里（写入），用得上时才捞回当前窗口（召回）。这跟 CE4 的 RAG **是同一套心智**：RAG 捞的是"该把哪段知识捞回桌上"，记忆捞的是"该把哪条往事捞回桌上"。

换句话说，**记忆是 RAG 的一个特例**——只不过被检索的对象，从"别人的静态知识库"换成了"agent 自己产出的动态往事"。你在 CE4 学的分块、相似度检索、垃圾进垃圾出，在成熟的记忆系统里照样成立。这就是为什么 CE0 说四把刀里"检索"和"外部记忆"血缘最近：**它们都是"该把窗外的哪一块捞回窗内"的检索问题**，只是捞的东西不同。

### 卸载 vs 压缩：信息还在不在窗口，细节丢不丢

刀四（外部记忆）和刀二（压缩，CE3）都能给桌子省地方，但机制截然不同——这是必须分清的一对，也是 CE0、L4 都反复点的考点：

| | **压缩**（刀二 / CE3） | **外部记忆 / 卸载**（刀四 / 本章） |
|---|---|---|
| 信息去哪了 | **仍在窗口里**，只是被总结成了短摘要 | **离开了窗口**，搬到外部文件，桌上只留指针 |
| 细节 | **丢了**——摘要保大意、弃细节，原文不可逆地没了 | **完整保留**——原文一字不少躺在文件里，随时能 `Read` 回原样 |
| 能不能复原 | 不能，压缩是有损的、单向的 | 能，指针一读，细节原样回桌 |
| 适合什么 | "大意要留、细节可弃"的长对话历史 | "细节不能丢、但不必时刻在眼前"的大块状态/资料 |

> 一句话记牢：**压缩是"把桌上的厚文件缩成一张便签，原件销毁"；卸载是"把厚文件收进抽屉，桌上留张便签写明它在哪，原件完好"。** 怕丢细节，就别压缩、要卸载；细节本就可弃、只要个大意，压缩更省事。

## 3. 工程手艺：四件要亲手做对的事

原理懂了，落地全在这几个动作上。代码只作示意，重点是每件事的时机与取舍。

### 手艺一：任务内用草稿纸——别把演算过程全堆进对话

复杂任务里，agent 会产出大量"中间品"：调研笔记、待办清单、试过的死路。把这些**全留在对话历史里**，是把桌子堆满的最快方式。

> 手艺：开一个**草稿纸文件**（如 `notes.md` / `todo.md`），把中间状态随手写进去，对话里只留一行进度指针。需要回顾时再读相关段落。

```python
# 示意：状态写文件，桌上只留指针
write_file("plan.md", detailed_plan)        # 三页方案卸到文件
context.append("方案已存 plan.md；现在执行第 3 步")  # 桌上只留这一行
# ……几步之后忘了细节……
step = read_section("plan.md", "步骤 3")     # 凭指针把那一段读回桌
```

这正是为什么很多 agent 会**主动给自己建一个 todo 文件**：它不是给你看的报表，而是它的草稿纸——把"还差哪几步"卸到窗外，免得自己在长任务里把窗口堆爆。

### 手艺二：桌上只留指针，按需 Read 回来——别预加载

卸载的核心纪律是**"用到才读"**，而不是"先全读进来备着"。

- **反面教材**：一上来就把 `plan.md`、`notes.md`、十个相关文件全 `Read` 进窗口"以防万一"——你把抽屉里的东西又全搬回了桌上，卸载白做了。
- **正确姿势**：桌上只留指针（文件名 + 大概在哪一节），**真正要用那一段的时候，才 `Read` 那一段**回来；用完这一步，它自然滑出近端、不再占焦点。

> 手艺：指针要**写得够具体**——不是"见某文件"，而是"步骤 3 的实现细节见 `plan.md` 的『执行计划』一节"。指针越精确，读回来时越能只取那一段、而不是把整个大文件又灌满桌子（否则你只是把"窗口太满"换成了"读回来时太满"）。

### 手艺三：跨会话记忆的写入与召回——记什么、何时记、怎么读回

跨会话记忆专治一件事：**对话一结束、窗口一清空，agent 就把你忘得干干净净**。解法是把"该长期记住的"写进一个固定文件，下次开新会话自动读回开头。手艺全在"记什么"和"何时记"：

- **该记的**：**用户偏好**（"回复用中文""代码别加多余注释""我习惯用 pytest"）、**项目约定**（"这个项目的部署命令是 X""数据库连接走 Y""命名遵循 Z"）——这些是**反复用得上、且短期不变**的事实。
- **不该记的**：一次性的、易过期的、属于某个具体任务的细节（"今天这个 bug 的栈追踪"）。把这些写进长期记忆，等于在你的"工位墙便签"上贴满过期通知——下次召回时反而是噪声。
- **召回的位置**：跨会话记忆通常被注入**窗口开头（system 区，高权重位）**——这正是 CE1「位置即权重」的应用：长期约定钉在开头，每一轮都在模型目光焦点里。

> 一句话判据：**问自己"下周、下个对话，这条还用得上吗？"——用得上才写进长期记忆，否则它只是这次任务的草稿纸内容，用完即弃。**

### 手艺四：划清三条边界——记忆 vs RAG、卸载 vs 压缩、长期 vs 短期

刀四最容易和邻居混淆。把三条线钉死，你就不会用错刀：

| 边界 | 这一边 | 那一边 | 怎么选 |
|---|---|---|---|
| **记忆（刀四） vs RAG（刀三）** | agent **自产的动态状态/往事**（方案、进度、你的偏好） | **外部静态共享知识**（产品文档、手册） | 东西是"它自己跑出来的"还是"别人写好放那的"？ |
| **卸载（刀四） vs 压缩（刀二）** | 细节**完整保留**在文件，可原样读回 | 细节**有损丢弃**，只留摘要 | 细节能不能丢？不能丢→卸载；可丢→压缩 |
| **跨会话记忆 vs 任务内草稿纸** | **长期**，跨对话留存（偏好、约定） | **一次性**，任务做完即弃（中间演算） | 下个对话还用得上吗？用得上→长期记忆 |

> 这张表配上 CE4 那张"何时别用 RAG"，你手里就有了一套**选刀的决策树**：小知识直接上桌（CE2 够用）；海量静态知识用 RAG（刀三）；自产动态状态卸到文件（刀四）；长对话历史压成摘要（刀二）。四把刀各司其职，不该抢活。

## 4. 结构图：窗口 ↔ 外部存储的指针往返

```
        上下文窗口（办公桌 · 有 token 上限 · 始终清爽）
   ┌──────────────────────────────────────────────────────┐
   │  ① system 区（开头·高权重）                            │
   │     ← 跨会话记忆在此自动读回：用户偏好 / 项目约定        │
   │       「回复用中文；部署命令是 X；用 pytest」            │
   │  ─────────────────────────────────────────────         │
   │  ② 当前任务区                                          │
   │     桌上只留【指针】，不留内容本体：                    │
   │        · 「详细方案见 plan.md 的『执行计划』一节」        │
   │        · 「调研笔记见 notes.md」                         │
   │     现在执行第 3 步……                                  │
   └──────────────────────────────────────────────────────┘
            │  指针往返（卸载的全部动作）                     ▲
            │                                                │
   写入 ▼ offload（移出窗口）            按需 Read ▲ 召回（捞回窗口）
            │                                                │
═══════════╪════════════════════════════════════════════════╪══════════
            ▼          外部存储（近乎无限的硬盘 · 在窗口外）    │
   ┌──────────────────────────────────────────────────────────┐
   │  plan.md   ← 三页详细方案，一字不少（细节完整保留）          │
   │  notes.md  ← 任务内草稿纸：中间结果、待办、试过的死路        │
   │  memory/   ← 跨会话长期记忆：偏好、项目约定（跨对话留存）     │
   │  CLAUDE.md ← 项目级长期约定，下次开会话自动读回开头          │
   └──────────────────────────────────────────────────────────┘
        关键：桌上永远只有指针 + 当下这一步；
              内容本体睡在窗外，要用才凭指针 Read 回来。
```

读图要点：横线上方是**有限的桌面**，下方是**近乎无限的硬盘**，中间那对上下箭头——**写入（卸载）** 与 **按需读回（召回）**——就是刀四的全部动作。注意两件事：① 桌上从头到尾**只有指针**，内容本体始终在窗外；这与 CE4 那张图"桌上从头到尾没有那几千页"是同一个灵魂。② 跨会话记忆被特意放在**开头的 system 区**（位置即权重，CE1），让长期约定每一轮都在模型焦点里。

## 5. Claude Code 锚点：你天天在用的"按需读、跨会话记"

Claude Code 是刀四的重度用户——它几乎**从不**把整个代码库塞进窗口，而是把"先看指针、用到才读、跨会话记约定"做成了默认习惯。把现象翻译成动作：

| 你看到 / 做的 | 背后的外部记忆动作 | 对应 |
|---|---|---|
| 它**不**把整个项目读进来，而是按需 `Read` 某个文件 | 代码库睡在窗外（硬盘），桌上只留路径指针，**用到才捞** | 卸载 + 按需读回（手艺二） |
| 它给自己建一个 todo / 计划文件，边做边勾 | 把任务状态卸到**草稿纸**，对话里只留进度指针 | 任务内草稿纸（手艺一） |
| `CLAUDE.md` 被注入对话开头，跨会话都生效 | **项目级长期约定**写进固定文件，每次开会话自动读回 system 区 | 跨会话记忆（手艺三）+ 位置即权重（CE1） |
| memory 文件记住"你偏好中文 / 用 pytest" | **用户偏好**作为跨会话记忆长期留存、自动召回 | 跨会话记忆（手艺三） |
| 你把大文档放成文件让它按需读，而不是粘进对话 | 把刀四**用在你自己身上**：内容卸到窗外，桌上留指针 | 卸载（手艺二） |
| 你 `/clear` 后它"忘了"刚才的任务，却仍记得 `CLAUDE.md` 里的约定 | 任务内草稿纸随窗口清空而丢；跨会话记忆因写进文件而留存 | 短期 vs 长期边界（手艺四） |

观察练习：下次看它干活，盯住一个动作——它**先看文件名/目录（指针），再决定 `Read` 哪个、读哪一段**，而不是开局把一堆文件全灌进来。那一步"只读需要的那段"，就是卸载的纪律。再观察一次 `/clear`：它把这次任务忘了，却仍按 `CLAUDE.md` 的约定办事——这就是"任务内草稿纸"与"跨会话记忆"寿命不同的活样本。

## 小练习 / 思考题

1. 用"办公桌 + 抽屉 + 便利贴"的比喻，解释刀四（外部记忆 / 卸载）的全部动作：什么留在桌上、什么收进抽屉、便利贴写什么？
2. **指针为什么能凭空"省"出桌面？** 一个指针和它指向的内容，体量差在哪？为什么"用到才读"是卸载的核心纪律，"先全读进来备着"反而毁掉了卸载？
3. 卸载（刀四）和压缩（刀二）都能给桌子省地方，关键区别是什么？（提示：信息还在不在窗口、细节丢不丢、能不能复原。）各举一个适用场景。
4. 课程说"记忆本质上是一道检索题，是 RAG 的特例"。请解释这句话：记忆和 RAG 在"捞回桌上"这件事上同构在哪？被检索的对象有什么不同？
5. 跨会话记忆里，"用户偏好""项目约定"该记，"今天这个 bug 的栈追踪"不该记——判据是什么？为什么把不该记的写进长期记忆反而是有害的？
6. 衔接思考：CE4 的 RAG 和 CE5 的外部记忆都是"窗口外存储 + 按需捞回"，为什么还要分成两章、两把刀？它们捞的东西本质差别在哪？

<details>
<summary>参考答案</summary>

1. **桌上**只留两样：当下这一步要看的东西 + 一张便利贴（指针）。**抽屉**（外部文件/硬盘）里收着内容本体——三页方案、调研笔记、状态记录，一字不少完整保留。**便利贴**写的是"去哪取"：哪个文件、哪一节（如"详细方案见 `plan.md` 的执行计划一节"）。要用时照便利贴把那一段读回桌，用完它自然滑出焦点。这样桌面始终清爽，又随时够得着完整细节。
2. 一个指针可能只占几十个 token（一句"见某文件某节"），它指向的文件却可能有几千行——体量差几个数量级，所以桌上留指针、内容搁窗外，等于凭空省出大片桌面。"用到才读"是核心纪律，因为卸载的全部价值就在"内容不在窗口里"；一旦"先全读进来备着"，你又把抽屉里的东西全搬回桌上，窗口照样被堆满，卸载白做——只是把"一开始太满"换成了"读回来时太满"。
3. **压缩**：信息**仍在窗口**，被总结成短摘要，细节**有损丢弃、不可复原**，适合"大意要留、细节可弃"的长对话历史。**卸载**：信息**离开窗口**搬到文件，桌上只留指针，细节**完整保留、可原样读回**，适合"细节不能丢、但不必时刻在眼前"的大块状态/资料（如三页执行方案）。一句话：怕丢细节就卸载，细节可弃只要大意就压缩。
4. 同构在：两者都不"把一切都带在桌上"，而是把内容睡在窗外，**判断这一刻该把哪一块捞回当前窗口**——这正是检索。RAG 捞"该把哪段知识捞回桌上"，记忆捞"该把哪条往事捞回桌上"，是同一套写入→召回的心智。不同在被检索的对象：RAG 捞的是**别人写好的、静态共享的外部知识库**；记忆捞的是 **agent 自己跑任务时动态产出的往事/状态**。对象一换，记忆就成了 RAG 的一个特例。
5. 判据：**"下周、下个对话，这条还用得上吗？"**——用得上且短期不变（偏好、项目约定）才写进长期记忆；一次性、易过期、属于某个具体任务的细节（某次 bug 的栈追踪）用完即弃。把不该记的写进长期记忆有害，是因为它会在每次新会话被自动召回到开头的高权重位，**变成长期噪声**——等于在"工位墙便签"上贴满过期通知，挤占焦点、误导后续判断。
6. 因为它们捞的东西本质不同，决定了建法和用法都不同：RAG 捞的是**静态、共享、海量**的外部知识（产品文档），需要分块、embedding、向量库那一整套离线建库；外部记忆管的是 agent **自产的、动态生长**的状态/往事（方案、进度、你的偏好），更多靠写文件 + 指针 + 按需 `Read`。前者是"别人的图书馆按需取阅"，后者是"自己的草稿与记忆卸到窗外按需取回"。心智同源（窗外存储 + 按需捞回），但对象、生命周期、落地手艺都不同，所以各占一把刀。

</details>

## 一句话带走

> **刀四外部记忆（卸载）的全部直觉：窗口永远有限，硬盘近乎无限——把不必时刻在眼前的信息写到外部文件，桌上只留一个指针，要用再 `Read` 回来；细节完整保留、随时可复原（这正是它和"有损压缩"的分界）。任务内用草稿纸卸载中间状态（短期），任务后把偏好与项目约定写进记忆文件、下次开会话自动召回（长期）。而记忆的本质，不是"记住一切"，而是一道检索题——"这一刻该把哪条往事捞回桌上"，它是 CE4 那把 RAG 的同源特例，只是捞的从静态知识换成了 agent 自产的动态往事。**

到这里，L4 介绍的**四把刀全部磨完**了：裁剪（CE2）、压缩（CE3）、检索（CE4）、外部记忆（CE5），加上 CE1 立下的"位置即权重"。下一章 **CE6 上下文失败模式与诊断**：四把刀都用上了，可 agent 还是会**越用越笨、跑偏、串味、自信地答错**——为什么？是窗口太空还是太满？是中间遗忘，还是被压缩弄丢了关键细节，还是卸载后该读回的没读回、桌上被旧任务污染？这一章教你当医生：**从症状反推是桌面的哪个环节坏了**，把前面所有刀法串起来做诊断。
