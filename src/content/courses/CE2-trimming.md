# CE2 · 裁剪与筛选：每个 token 都要挣得它的位置

> 本章目标：把 L4 介绍的**刀一「裁剪 / 过滤」**从"听说过"磨成"用得动"——学会在信息**进桌之前**就当好门禁，只放挣得了位置的那几行。本章深挖 L4 的刀一，承接 CE1「位置即权重」：CE1 教你"既有的纸往桌子哪儿摆"，CE2 教你更靠前的一步——"哪些纸根本不该上桌"。
> 拧的旋钮：进窗口前的"门禁过滤"——回填前先裁，而不是事后再压。

---

## 0. 先讲一个画面

你让 agent 查一个报错，它调了个工具去读日志。工具"哗啦"一下吐回来 **500 行**——启动横幅、版本号、一堆 `INFO`、几十条 `DEBUG`、心跳检测、再加上中间那 3 行真正的 `ERROR`。

现在有两种活法。

**活法一（新手默认）**：把这 500 行**原封不动**拍回上下文。桌子瞬间被一张巨大的、99% 是废话的纸盖满。模型得在这张纸里自己扒拉，把那 3 行报错从噪声里捞出来——而它们偏偏被埋在中段（CE1 说过，那是注意力盲区）。更别提：这 500 行**每一行都要算钱、都要占窗口、下一轮还得再扫一遍**。

**活法二（高手默认）**：在这坨日志**碰到桌子之前**，先过一道门禁——只放报错那 3 行（外加上下两行做上下文），其余 497 行当场拦下。桌子干净，焦点清晰，钱也省了。

> 这两种活法的差别，就是这一章的全部：**裁剪不是"事后收拾乱桌子"，而是"在门口就不让垃圾进来"。** 同一坨信息，进桌前拦掉 vs 进桌后再清理，代价差着十万八千里。

## 1. 核心概念：四个动作 + 一句口号

裁剪不是一个动作，是一小簇互相搭配的动作。先把名字和分工钉清楚（术语首次出现，就地中英注释 + 类比）：

| 动作 | 中英 | 大白话 | 类比（办公桌宇宙） |
|---|---|---|---|
| **裁剪** | trimming | 从一坨信息里**只挑相关的留下** | 一沓资料里抽出有用那几页，其余不上桌 |
| **筛选 / 策展** | curation | 主动**编排**该留什么、按什么结构留——比裁剪更"有设计感" | 不是随手抽页，而是像编辑一样**重新整理成一页提要** |
| **截断** | truncation | 设一个**硬上限**，超了就一刀切掉 | "这张纸最多放 50 行，多的不要" |
| **去噪** | denoising | 把**重复、模板化、无信息量**的内容剔掉 | 删掉每页都印的页眉页脚、版权声明、心跳日志 |

它们的关系：**截断**是最钝的刀（按长度一刀切，不看内容）；**裁剪**进一步（按相关性挑）；**筛选 / 策展**最锋利（不仅挑，还重新组织成结构化提要）；**去噪**则横跨全程，专门对付那些"占地方但零信息"的内容。本章把它们统称为"门禁"。

把这一簇动作浓缩成一句口号，钉在脑子里：

> **每个进入上下文的 token，都要挣得它的位置（every token must earn its place）。**

这句话是裁剪的"宪法"。它把默认值彻底反过来：不是"先全塞进来、有问题再说"，而是"**默认不进，除非你能说出它为什么该占这块桌面**"。桌子是稀缺的(CE0 立的"办公桌"地基)，进桌是一种特权，不是权利。

## 2. 原理"为什么"：门禁在前，比扫地在后划算得多

你可能会问：反正后面还有刀二（压缩）能把长历史缩短，那何必在门口斤斤计较？多塞点进来，回头一起压不就行了？

这是新手最贵的一个误判。关键在于：**裁剪是"进门前的门禁"，压缩是"进门后的扫地"——位置不同，省的钱完全不是一个量级。**

想清楚一坨没裁的垃圾进了桌子之后，会**反复**收你几道税：

- **token 税（钱）**：它进来这一轮要算钱。而且 messages 是累积的——它赖在历史里，**之后每一轮**都跟着被重新计费。早裁一次，省的是后面**全程**的钱。
- **延迟税（慢）**：窗口越长，模型每一轮"扫一遍桌子"越慢。500 行废话让从现在起的每一次响应都拖一点。
- **注意力税（变笨）**：这是最阴险的一道。废话不只是占地方，它**稀释信号**——把那 3 行报错淹进 497 行噪声里，正好喂大了 CE1 讲的"中间遗忘"。桌子越满，模型越抓不住重点。

把这三道税摆在一起，结论就很硬了：

> **同样一坨垃圾，在门口拦下只付一次"过滤"的成本；放它进来再清理，你已经先交了 token、延迟、注意力三道税，而且 token 税还按轮累计。早裁省的是复利，晚清省的是零头。**

所以裁剪和压缩**不是二选一，而是分工**：

- **裁剪（刀一）= 进门前的预防**：信息回填进 messages **之前**就过滤，垃圾根本没进过桌子，没产生过历史成本。
- **压缩（刀二）= 进门后的补救**：当**确实有用**的历史日积月累、还是太长了，再把它总结缩短。压缩是给"该留但太长"的东西用的，**不是给本就该拦在门外的垃圾兜底的**。

一句话记住分工：**能在门口拦的，绝不放进来等扫地。** 这也正是为什么这门课先讲裁剪（CE2）、再讲压缩（CE3）——顺序就是它们在流水线上的先后。

## 3. 工程手艺：门禁的四种拦法

原理立住了，落到手上就是四种具体拦法。注意：下面的代码**只是示意**，帮你看清"在哪一步插一道门"，真实实现千差万别。

### 手艺一：工具输出策展——只留关键行 / 结构化摘要

最高频的场景，就是开场那 500 行日志。门禁应当**在工具结果回填进 messages 的那一步**插进去，而不是让原始输出直通桌面：

```python
# 示意：工具刚跑完，结果还没进 messages，先过一道门
raw = run_tool()                      # 工具吐回 500 行
filtered = keep_relevant(raw)         # 门禁：只留报错那几行 + 上下文
messages.append(filtered)             # 进桌的是策展后的，不是原始的
```

`keep_relevant` 可以是粗暴的"只抓含 `ERROR` 的行"，也可以是讲究的"抽出结构化提要"——比如把一份冗长的 API 返回，策展成"状态：失败；原因：401；关键字段：token 过期"。后者就是**策展（curation）**：你不是在删，你是在**当编辑**，把一坨原始数据重写成模型一眼能用的形态。

> 心法：工具的"原始输出"是给机器看的，模型要的是"提要"。在两者之间永远放一个编辑。

### 手艺二：相关性筛选——按"和当前任务有没有关系"挑

不是所有信息都按行筛。有时进桌的是一批候选（多个文件、多条搜索结果、多段记录），门禁要做的是**按相关性排序、只放前几名**：

```python
# 示意：搜出来 50 条，只有头部几条和当前问题相关
hits = search(query)                  # 50 条候选
top = rank_by_relevance(hits)[:5]     # 门禁：只放最相关的 5 条
```

这其实就是 CE4「检索注入（RAG）」的雏形——RAG 本质上是"超大规模、自动化的相关性筛选"。这里先建立直觉：**相关性是进桌的入场券**。

### 手艺三：设上限截断——给每类输出定一个天花板

有些输出你事先不知道会多长（一次 `cat` 大文件、一段超长 stack trace）。最简单的兜底是**截断（truncation）**：设一个硬上限，超了就切，并留个记号告诉模型"这里截过"：

```python
# 示意：任何工具输出最多保留 N 行，超了截断并标注
def cap(text, n=100):
    lines = text.splitlines()
    if len(lines) <= n:
        return text
    return "\n".join(lines[:n]) + f"\n…（已截断，原文共 {len(lines)} 行）"
```

截断是最钝但最可靠的保险——它不保证留下的是"对的内容"，只保证"不爆桌"。所以它常和手艺一搭配：**先按相关性策展，再用截断兜个底**，防止某次策展失手放进一个超长块。

> 注意那句"…（已截断）"的标注：它本身是一个**给模型的信号**，告诉它"这里还有更多，需要的话可以再去取"。裁剪时别把"被裁过"这件事也藏了——留个指针，是诚实的门禁。

### 手艺四：丢冗余历史——把过期的纸请下桌

门禁不只看新进来的，也要回头清理**已经没用的旧纸**。最典型的是：一个子任务已经做完了，它中间那十几轮工具往返还赖在历史里占地方。

- 任务切换、阶段完成时，**主动清掉**与新阶段无关的旧往返。
- 重复的、被后续结果**覆盖**的中间产物（比如读了三遍同一个文件），只留最后一份。
- 这一步和刀二（压缩）、刀四（外部记忆）会接力：丢不掉但太长的，交给压缩；丢不掉又想留全细节的，卸载到文件（CE5）。

> 裁剪是**持续动作**，不是一次性安检。桌子是流动的，门禁要一直在岗。

## 4. 结构图：信息进窗口前的门禁流水

把上面四种拦法串成一条流水线——任何一坨信息想上桌，都得先过这道门（ASCII 版，阶段二会转成 HTML）：

```
   工具输出 / 检索结果 / 一坨原始信息
   （500 行日志、50 条搜索、超长返回…）
                │
                ▼
   ┌─────────── 门禁：进桌前过滤（刀一 裁剪） ───────────┐
   │                                                      │
   │   ① 去噪    剔掉模板/重复/零信息（页眉、心跳、横幅）   │
   │      │                                               │
   │      ▼                                               │
   │   ② 相关性筛选   和当前任务无关的？拦下               │
   │      │                                               │
   │      ▼                                               │
   │   ③ 策展    把剩下的重写成结构化提要（当编辑）        │
   │      │                                               │
   │      ▼                                               │
   │   ④ 截断兜底    还是太长？设硬上限一刀切 + 留标注      │
   │                                                      │
   └──────────────────────┬───────────────────────────────┘
                          │  挣得了位置的那几行
                          ▼
   ┌──────────────────────────────────────────────────┐
   │  上下文窗口（办公桌）—— 只摊干净、相关、精炼的内容  │
   │  ↑ CE1 再决定这几行摊在桌子的哪个位置（开头/结尾）   │
   └──────────────────────────────────────────────────┘
                          │
              太长但有用？ ▼  交给下游
              ┌──────────────────────────────┐
              │ 刀二 压缩(CE3) / 刀四 外部记忆(CE5) │
              └──────────────────────────────┘
```

读图要点：门禁在**进桌之前**，是一道"准入闸"而非"清扫队"。被它拦下的根本没进过桌、没花过钱；只有挣得了位置的内容才上桌，随后才轮到 CE1 给它**排座位**。门禁拦不掉、却又太长的（确实有用的历史），才往下游交给压缩和外部记忆——这就是四把刀的接力顺序。

## 5. Claude Code 锚点：它一直在帮你把垃圾拦在门外

裁剪是 Claude Code 每一轮都在替你做的事。把日常现象翻译成"门禁动作"，你就能看懂它在拦什么、也能学会主动帮它拦：

| 你看到 / 做的 | 背后的裁剪动作 | 对应手艺 |
|---|---|---|
| 它读了个大文件，却只在回复里**引用关键几行** | 工具输出策展，不把整坨原文塞回 messages | 手艺一（策展） |
| 工具返回超长时，输出里出现"…（truncated）/ 已截断"字样 | **截断**兜底，并留标注告诉模型"还有更多" | 手艺三（截断） |
| 它 `grep`/搜出一堆结果，只挑**最相关的几条**往下用 | **相关性筛选**，无关的拦在门外 | 手艺二（相关性） |
| 你主动 **`/clear`** 开新会话 | 一次性把整张桌子的旧纸**全部请下桌**——你手动行使裁剪 | 手艺四（丢冗余历史） |
| 任务切换时它（或你）开新对话而不在旧会话里硬接 | 不让上一个任务的历史污染下一个——丢过期上下文 | 手艺四（丢冗余历史） |

> 实操贴士：**`/clear` 是你手里最钝也最有效的门禁。** 一个新任务，别在堆满旧任务的桌子上硬接——又慢、又贵、还容易"串味"（旧上下文污染新判断）。换任务就清桌，是你能主动行使的、最高杠杆的一刀裁剪。

## 小练习 / 思考题

1. 用"门禁 vs 扫地"的比喻，解释为什么"回填前先裁剪"比"先全塞进来、回头用压缩清理"更划算。把那三道税说出来。
2. **裁剪、压缩、外部记忆**都能让窗口更短。裁剪和另外两把刀最本质的区别是什么？（提示：信息**有没有进过**桌子。）
3. 截断、相关性筛选、策展，哪个最钝、哪个最锋利？为什么实践中常把"策展 + 截断"搭配使用？
4. 工具吐回 500 行日志、只有 3 行有用。除了"留那 3 行"，为什么通常还要**带上那 3 行的上下两行**、并在截断处**留个"已截断"的标注**？
5. 默写裁剪的那句"宪法"口号，并解释它如何把默认值反了过来。

<details>
<summary>参考答案</summary>

1. 没裁的垃圾一旦进桌，会反复收三道税：**token 税**（进来这轮算钱，且 messages 累积、之后每轮重复计费）、**延迟税**（窗口越长每轮扫得越慢）、**注意力税**（稀释信号、把关键内容淹进噪声，喂大中间遗忘）。在门口拦下只付一次"过滤"成本；放进来再压缩，三道税已先交、token 税还按轮累计。所以门禁在前，省的是复利。
2. **裁剪**是"进门前的门禁"——被拦下的内容**从没进过**上下文，不产生历史成本。**压缩**和**外部记忆**都作用于**已经在/曾在**上下文里的信息：压缩把它总结缩短（仍在桌上、丢细节），外部记忆把它卸载到文件（移出桌面、留指针、细节完整）。一句话：裁剪决定"进不进来"，后两把刀处理"已经进来的"。
3. **截断最钝**（只按长度一刀切，不看内容），**策展最锋利**（不仅挑相关，还重写成结构化提要）。常搭配使用是因为：策展保证"留下的是对的内容"但偶尔会失手放进超长块，截断给它兜底保证"绝不爆桌"——一个管准、一个管稳。
4. 带上下两行是为了给那 3 行报错**保留最小上下文**，否则模型可能看不懂报错发生在什么环节（裁剪不能裁到丢掉可读性）。留"已截断"标注是给模型一个**诚实的信号**：告诉它"这里还有更多、需要可再取"，避免它误以为自己看到了全部——留指针的门禁才是诚实的门禁。
5. 口号：**每个进入上下文的 token，都要挣得它的位置。** 它把默认值从"先全塞进来、有问题再说"反成"默认不进，除非你能说出它为什么该占这块桌面"——进桌从一种"权利"变成了需要被论证的"特权"。

</details>

## 一句话带走

> **刀一裁剪，是上下文流水线最前面的那道门禁：每个想上桌的 token 都得挣得它的位置。靠去噪、相关性筛选、策展、截断四种拦法，在信息回填进窗口之前就把垃圾拦下——因为门口拦一次只付一道过滤成本，放进来再清理却要交 token、延迟、注意力三道税，且 token 税按轮累计。能在门口拦的，绝不放进来等扫地。**

下一章 **CE3 压缩与总结**：门禁拦掉了不该进的垃圾，但有些内容**确实有用、又确实太长**——几十轮真刀真枪的对话历史，裁是裁不掉的。这时就轮到刀二：把这段长历史**总结成短摘要**替换原文。裁剪扔不掉的长历史，就得压缩——而"什么时候压、压时保留什么、丢什么"，又是另一门要走的钢丝。
