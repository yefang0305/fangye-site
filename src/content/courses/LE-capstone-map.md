## 2. 随身对照卡：旋钮 ↔ 不调好会怎么坏 ↔ 怎么调

> 这是全课压成一页的核心。建议默写。

| # | 旋钮（章） | 不调好会怎么坏（失败模式） | 怎么调（工程手艺） |
|---|---|---|---|
| ① | **形态选型** (LE1) | 任务配错骨架：探索任务硬套死计划，或简单任务用 ReAct 瞎试费 token | 按任务**可预测性**选：越可预先拆解越偏 Plan，越探索越偏 ReAct；拿不准从 ReAct 起步 |
| ② | **停止与预算** (LE2) | 死循环 / 烧钱 / 卡死 / 闯祸（执行不可逆危险操作） | **多重上限并联**（步数+成本+时间），谁先触发听谁的；高风险**停下问人** |
| ③ | **纠错与反思** (LE3) | 一错到底；或无效重试同一个会失败的操作 | 被动**错误回灌** + 主动**反思**；让工具吐**好错误信息**（具体可操作） |
| ④ | **嵌套循环** (LE4) | 单循环撑爆上下文窗口、越长越漂；想干的太多塞一个循环里 | **工头-工人**拆成短子循环：子循环独立上下文+独立预算，只回**带证据的结论** |
| ⑤ | **长程控制** (LE5) | 漂移：每步合理但整体越跑越偏题，且不报错、不自知 | 周期性 **re-ground / 状态摘要 / 计划重述**，把目标和进度顶回眼前 |
| ⑥ | **外循环** (LE6) | 盲改（凭感觉优化，越改越差）；老错反复回来、系统不进步 | **评测闭环**量化改进 + **数据飞轮**让失败沉淀成用例 + **人在环**注入判断 |

## 3. 三条主线，把六章串成一个故事

1. **从"一个循环"到"循环的形态"**（LE1）：同一个 `while`，骨架可以是 ReAct 或 Plan——这是第一个、也最大的选择。
2. **给循环装上控制系统**（LE2–LE5）：缰绳防失控（②）、纠错把失败变燃料（③）、嵌套把长循环拆短（④）、长程控制抗漂移（⑤）。这四个旋钮共同回答一个问题：**怎么让一个能自主走很多步的循环，既跑得动又不跑坏。**
3. **再把镜头拉远一个尺度**（LE6）：前面调的是"一个任务内"的发动机；外循环调的是"让发动机一代比一代好"。内外同源——都是用反馈驱动变好。

> 如果只记一句话：**Loop Engineering = 在内（秒级）外（天周级）两个尺度上，把驱动 agent 的循环每一个旋钮都拧好。智能不在模型里，在循环怎么转里。**

## 4. 怎么用这张总图自检

1. **盖住第 2 节的后两列**，只看旋钮名，默写"会怎么坏"和"怎么调"。能默出来，说明这门课吃透了。
2. **拿一个你真实用过的 agent 场景**（比如让 Claude Code 做某个任务），逐个旋钮问自己：它用了哪种形态？缰绳够不够？怎么纠错的？有没有漂移？——把抽象旋钮挂回真实观察。
3. **回到 LE0 的仪表盘图**，确认你现在能解释每个旋钮在发动机上的位置和作用。

## 一句话带走

> **整个 Loop Engineering 就一张图：一个内循环（五个旋钮：形态、缰绳、纠错、嵌套、长程控制）被一个外循环（评测、飞轮、人在环）包着。内循环让任务跑完，外循环让系统变好，二者是同一个"用反馈驱动变好"的思想在两个时间尺度上的复用。把这张图和那页对照卡记住，你就拥有了设计、诊断、改进任何 agent 循环的随身工具。**
