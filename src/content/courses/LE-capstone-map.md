## 1. 四层技术栈全景图 (The Four-Layer Stack)

从 Prompt 到 Loop，大模型时代的工程杠杆正在逐层走高。每往上一层，你所操心的事情和需要安装的“刹车闸口”就大一个量级：

```
┌═══════════════════════════════════════════════════════════════════════┐
║ 🚀 LOOP LAYER (调度与持久化 · 坐在 Harness 上一层)            LE3-LE8  ║
║    核心：定时启动、子代理分工协作、跨会话记忆、自动化发现与隔离执行       ║
├───────────────────────────────────────────────────────────────────────┤
║ 🛠️ HARNESS LAYER (单次运行武装 · 给 Agent 穿上盔甲)         Harness 课  ║
║    核心：准备工具集、圈定操作权限边界、定义单次完成状态与紧急熔断缰绳   ║
├───────────────────────────────────────────────────────────────────────┤
║ 📂 CONTEXT LAYER (当下窗口视野 · 决定大模型看到什么)         Context 课 ║
║    核心：检索 RAG、长文缩写、历史修剪压缩、规避噪音干扰                  ║
├───────────────────────────────────────────────────────────────────────┤
║ 📝 PROMPT LAYER (单次问答交互 · 对话文本调整)                基础问答  ║
║    核心：字句斟酌、设定角色定位、少样本提示(Few-shot)、指令逻辑定义      ║
└═══════════════════════════════════════════════════════════════════════┘
```

## 2. 随身对照卡之一：一个自跑循环的五大动作 (The Five Moves)

任何一个合格的自跑循环，在旋转起来时，都必然由这五个动作咬合构成，缺一不可：

| 动作 | 核心英文 | 它在循环里干什么 | 典型实现手段 |
| :--- | :--- | :--- | :--- |
| **① 发现** | Discovery | 定时醒来，搞清楚“这一圈该干什么”，让 Agent 自己去找活。 | CI 失败分析、Issue 过滤、最近 Commit 分诊 |
| **② 交付** | Handoff | 把任务从“调度脑”分发给具体负责“干活的 Agent”，并做好隔离。 | Git Worktree 物理目录隔离、任务切片派发 |
| **③ 验证** | Verification | 对产出的代码或方案说“不”。写代码的人，绝不能自己给自己打分。 | 独立的 Maker/Checker 双 Agent 机制、运行单元测试 |
| **④ 持久化** | Persistence | 把执行结果和运行状态写入磁盘，让下一次循环醒来时能够续接记忆。 | 更新本地 `loop_status.md` 文件、提 PR、写 Linear |
| **⑤ 调度** | Scheduling | 决定下一次触发的节拍，让循环在时间尺度上连续。 | 本地 `/loop` 进程、GitHub Actions Cron、云端 Routine |

## 3. 随身对照卡之二：自跑循环的六大零件 (The Six Parts)

要把上述动作拼装成一台可以无人值守的机器，你需要为你的系统配置以下六大核心硬件：

```
                ┌─────────────────────────────────┐
                │        1. 自动化调度心跳        │
                │     (Cron / /loop / Trigger)    │
                └────────────────┬────────────────┘
                                 │
  ┌──────────────────────────────┼──────────────────────────────┐
  │                              │                              │
┌─▼──────────────┐       ┌───────▼───────┐       ┌──────────────▼─┐
│  2. 并行隔离   │       │  3. 显式技能  │       │  4. MCP 连接器 │
│  (Worktrees)   │       │  (SKILL.md)   │       │ (Slack/Linear) │
└─┬──────────────┘       └───────┬───────┘       └──────────────┬─┘
  │                              │                              │
  └──────────────────────────────┼──────────────────────────────┘
                                 │
                ┌────────────────┴────────────────┐
                │         5. 状态记忆存储         │
                │        (loop_status.md)         │
                └────────────────┬────────────────┘
                                 │
                ┌────────────────▼────────────────┐
                │         6. Maker/Checker        │
                │        (Sub-agents 阻断)        │
                └─────────────────────────────────┘
```

1. **自动化心跳 (Automation)**：让循环无需人肉敲击回车，能自动被周期性触发。
2. **物理隔离器 (Worktrees)**：让并行的 Agent 分头在干净的沙箱或 worktree 里工作，彻底避免代码合并冲突。
3. **显式技能库 (Skills)**：把项目知识和工具定义封装为固化的 Skill 结构（如 `SKILL.md`），而不是临时拼凑庞大的 Prompt。
4. **外部连接器 (MCP Connectors)**：利用模型上下文协议（MCP），让 Agent 能自由连接 Linear、Slack、数据库和外部 API。
5. **子代理分工 (Sub-agents)**：组建 Agent Teams，必须用一只“挑刺的 Checker 眼睛”去监督“低头写代码的 Maker 眼睛”。
6. **落盘记忆体 (Memory)**：将跨越会话的记忆存盘在 Git 或本地文件系统上，把仓库作为终极单一事实源。

## 4. 警惕隐性债：四大代价与防线 (The Four Defenses)

自跑循环的效率极其恐怖，但也正因如此，它在无人值守时累积风险的速度也是百倍级的。你必须为它们钉好下面四块防雨板：

| 代价 (失败模式) | 典型症状 | 怎么防范 (工程防线) |
| :--- | :--- | :--- |
| **① 验证债 (Verification Debt)** | 自动产出的修复和 PR 堆积如山，没人看也没人验，直到底层架构悄悄腐烂。 | 装上**硬评判器（Evaluator）**，且评判者必须使用干净的新上下文模型。 |
| **② 理解腐烂 (Understanding Decay)** | 代码库飞速膨胀，你作为项目主人，脑子里的地图却停留在原地，逐渐看不懂自己的项目。 | 强制要求 Agent 提 PR 时附带简明解释；**定期肉眼阅读**并口头重述核心逻辑。 |
| **③ 认知投降 (Cognitive Surrender)** | 对 AI 提出的意见和自动做出的合并完全盲从，懒得思考，退化为只负责按确定键的机器人。 | 牢记**“执行可外包，但做决定的判断力不可外包”**。在高风险操作处留人肉卡点。 |
| **④ Token 失控 (Token Runaway)** | 后台循环因为某个死循环 Bug，在你睡觉时空转了一整夜，第二天醒来收到巨额账单。 | 上线前给循环钉死上限：**单次预算、每日最大额度、最大重试次数**，超标即强行熔断。 |

## 5. 终极法则

> **Build the loop. But build it like someone who intends to stay the engineer, not just the person who presses go.**
> **造那个循环。但要像一个打算长期留下来当工程师的人去设计它，而不是一个只负责按下启动键的门卫。**

---

## 6. 如何用这张总图自检

1. **盖住后两列**，看着五大动作（发现、交付、验证、持久化、调度），尝试在终端或脑海中用伪代码默写一个简易 Loop 的实现逻辑。
2. **对照六大零件**，检查你手头现有的 AI 辅助开发方案。哪几个零件你已经用上了？哪几个零件是缺失的，正处于危险的“裸跑”状态？
3. **设置你的熔断阈值**：在你打算今晚运行一个 overnight（通宵）任务前，确认你的最大重试次数和 token 上限已经写在了最外层的调度脚本里。
