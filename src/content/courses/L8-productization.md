# L8 · 做成产品：Harness 的产品化

> 本层目标：把一个"技术上能跑"的 agent，变成"能交付给真实用户、跑在生产里"的产品。
> 这一层不加新机关，而是给前面 L0–L7 算三笔账：**延迟、成本、边界**。
> 学完它，你看任何 agent 产品（Claude Code、Cursor、自建）都能从产品视角评头论足。

---

## 0. 先讲一个画面

L0–L7，我们在实验室里造出了一台能自主干活的机器。但"实验室能跑"和"卖给用户"之间，隔着一条产品工程师天天在过的河：

- 用户按下回车，**等 30 秒才出字**——技术上没错，体验上已经死了（**延迟**）。
- 一个任务背后悄悄烧掉几十次模型调用、几块钱 token——demo 无所谓，**百万用户跑起来就是天文数字**（**成本**）。
- agent 自主性很强，但它能碰用户的什么、不能碰什么？出了错赔不赔得起？（**边界/安全**）

**产品化（productization）就是过这条河：在"能力、体验、成本、安全"之间做权衡，让 agent 不只是能跑，而是能被无数真实用户日复一日地依赖。** 前七层是"造引擎"，这一层是"造一辆能上路、加得起油、刹得住车的车"。

---

## 1. 要解决什么：从"能跑"到"能交付"的三道坎

前七层默认了一个奢侈前提：算力随便用、时间随便花、环境很安全。真实产品里这三条全不成立。

| 坎 | 实验室里 | 产品里的残酷现实 |
|---|---|---|
| **延迟（Latency）** | 等多久都行 | 用户几秒不出反应就走人；agent 多步循环天然慢 |
| **成本（Cost）** | demo 跑几次无所谓 | 每步都是付费 token 调用，乘以百万用户=烧钱黑洞 |
| **边界（Safety/Boundary）** | 自己电脑随便造 | 碰的是真实用户的数据、钱、系统，错一步要担责 |

产品化就是带着这三个约束，回头重新审视 L0–L7 的每个设计——它在生产里够快吗？够省吗？够安全吗？

---

## 2. 这层怎么补：三笔账各自的招数

### 账一：延迟——让它"显得快"和"真的快"

- **流式输出（streaming，L1 见过）**：一个字一个字蹦，用户立刻看到反应，体感快得多（即便总时长没变）。
- **少走几步**：循环（L3）每步都是一次完整模型调用，是延迟主因。能用一步解决就别让它绕三步——好的 prompt 和工具设计能显著减少步数。
- **模型分级路由（model routing）**：简单子任务派给**又快又便宜的小模型**，难任务才上大模型。不是所有活都值得用最强（最慢最贵）的脑子。
- **并行（L6）**：能同时干的子任务并行跑，压缩墙钟时间。

### 账二：成本——token 经济学

每一层的设计都直接换算成钱，这把 L1–L6 的技术全部"价签化"：
- **上下文工程（L4）就是省钱**：每轮少塞无关 token = 每轮少付费。压缩、按需读文件、裁剪，全是成本手段。
- **模型路由**：小模型单价可能是大模型的几十分之一，能用小的地方用小的，账单立省。
- **缓存（caching）**：重复的上下文前缀（比如那段巨大的 system 提示）可以**缓存**，下次不重复计费/重算。Claude Code 那条"prompt 缓存 5 分钟 TTL"的提示就是这个——这也是为什么"频繁打断让它重读全部上下文"会更慢更贵。
- **步数控制**：L3 的 `max_steps` 不只防失控，也是**成本闸**——一个任务最多烧多少调用，得有上限。

> **核心认知：L1–L7 学的每个技术，到了产品层都有一个"价签"。"把 Claude Code 用到极致"很大程度上就是"用更少的 token/步数办成同样的事"——这正是上下文工程在你身上的回报。**

### 账三：边界——安全、权限、人机协作

- **权限边界（L2/L7 的权限闸制度化）**：明确规定 agent 能碰什么、碰之前要不要批准。生产 agent 必须有清晰的"能力围栏"。
- **人在环路（L7）**：高风险、不可逆动作交还人类决定——产品要设计好"在哪些点把方向盘交回用户"。
- **失败优雅降级（fallback）**：模型挂了、工具超时了、子代理失败了，产品不能整个崩。要有**回退策略**：换个模型、重试、或体面地告诉用户"这步没成"。
- **可观测性与审计（L7）**：生产环境出了事要能追责、能复盘，日志和追踪是合规与信任的基础设施。

## 3. 底层原理：产品化是"约束下的权衡艺术"

前七层多在追求"能力上限"；这一层的本质是**在多个互相打架的约束之间找平衡点**，没有标准答案，只有取舍：

- **更强 ⇄ 更快/更省**：上最强模型、让它多想几步、给它更多上下文——更聪明，但更慢更贵。产品工程师天天在这条轴上做选择。
- **更自主 ⇄ 更可控**：放手让 agent 自己干提升效率，但每多一分自主就多一分失控风险（L7）。多少自主、多少请示，是产品决策。
- **更全 ⇄ 更准**：给 agent 更多工具/上下文未必更好（L4 中间遗忘）——有时"少给"反而更稳。

> 一句话原理：**前七层教你"能做到什么"，这一层教你"该做到什么"。一个好的 agent 产品，不是把每个能力都拉满，而是针对具体用户和场景，在延迟、成本、安全、能力之间找到那个恰到好处的平衡——克制，和能力同样重要。**

## 4. Claude Code 锚点 + 真产品横向对比

**Claude Code 身上的产品化决策**，你现在能逐条看懂：
| 产品决策 | 背后是哪笔账 |
|---|---|
| 打字机式流式输出 | 账一 延迟（体感优化）|
| prompt 缓存（5 分钟 TTL）、自动压缩上下文 | 账二 成本（少重算、少重发）|
| 危险命令弹窗批准、权限模式 | 账三 边界（权限闸 + 人在环路）|
| 内置 `max_steps` 上限、可中断（Esc）| 账二/账三（成本闸 + 可控）|
| 不同档模型可选（Opus/Sonnet/Haiku）| 账一/账二（模型路由：按难度选快慢贵贱）|

**三种 agent 形态横向对比**（用你学到的视角看它们的取舍）：

| | **Claude Code**（CLI 编码 agent）| **Cursor**（IDE 编码 agent）| **你自建的 agent** |
|---|---|---|---|
| 定位 | 终端里能自主多步干活的通用编码 agent | 编辑器内、贴着代码上下文的 AI | 针对你自己场景（如内容流水线）定制 |
| 上下文策略(L4) | 按需读文件 + 自动压缩 | 紧贴当前文件/选区，IDE 提供结构 | 你自己设计该喂什么 |
| 自主性(L3/L7) | 高，能长时间自主跑 + 多重缰绳 | 中，更贴近"边写边问" | 由你定 |
| 子代理(L6) | 内置，可派并行子代理 | 较弱 | 看你搭不搭 |
| 你学这门课的意义 | 看懂它每个设计**为什么这么做** | 对比出不同取舍 | **你能自己做一个**——这正是你的目标之一 |

> 看产品的"正确姿势"：拿到任何一个 agent，挨个问——它怎么管上下文(L4)？多自主、有哪些缰绳(L3/L7)？会不会派子代理(L6)？延迟/成本/安全怎么权衡(L8)？你现在有了一整套解剖刀。

## 一句话带走

> **产品化是给前七层的能力算三笔账：延迟、成本、边界。它教的不是"还能加什么能力"，而是"在真实约束下该做到什么"——一个好 agent 产品的标志不是能力拉满，而是克制得恰到好处。学完这一层，你看任何 agent 都能从产品视角说出它的取舍——而你，也具备了自己造一个的全部地图。**
