# LE0 · 导论：循环是 agent 的本质

> 本章目标：建立全课的总心智模型——把"驱动 agent 的循环"看成一台**可调的发动机**，认清它有**内外两个尺度**，并拿到本课要逐个拧的那排**旋钮**全景图。
> 拧的旋钮：暂无——本章只装"仪表盘"，从 LE1 起一个个拧。

---

## 0. 先把这门课摆回它的位置

如果你读过姊妹课 **Harness Engineering（外壳工程）的 L3「Agent Loop」**，你已经知道一件事：agent（智能体）之所以是 agent，核心就是一个 `while` 循环——它把"单次工具调用"接成"一步接一步直到完成"。

那门课告诉你**循环是什么**。

这门课只做一件事：教你**像工程师那样把这个循环设计好、管住、并让它自我改进**。

打个比方：L3 把一台**发动机**的本体交到了你手里——它能转，能驱动 agent 干活。但一台只会"全速空转"的发动机是危险且笨拙的。真正的手艺，在它仪表盘上那排**旋钮**：油门给多大（步数与预算）、方向怎么修（纠错与反思）、变速箱挂几档（循环形态）、跑长途怎么不偏航（漂移控制）……

> **一句话摆位：L3 给了你发动机，本课教你开它——拧好每一个旋钮。**

---

## 1. 一个被大多数人忽略的事实：循环有两个尺度

人们说"agent 的循环"时，其实在指两个**时间尺度完全不同**的循环，混为一谈是后面一切困惑的根源。先一刀切开：

| | 内循环（inner loop） | 外循环（outer loop） |
|---|---|---|
| 学名 | 运行时循环 / agentic loop（智能体循环） | 改进循环 / 开发循环 |
| 时间尺度 | **秒级**，发生在**单个任务之内** | **天/周级**，发生在**许多任务之上** |
| "转一圈"是什么 | 模型走一步 → 执行工具 → 看结果 → 再走一步 | 跑一批任务 → 看哪里不行 → 改 prompt/工具/外壳 → 再跑 |
| 谁在转它 | harness（外壳）的 `while`，自动转 | **你**（工程师），手动或半自动地转 |
| 目标 | 把**这一个**任务自主做完 | 让**整个系统**越跑越好 |
| 本课覆盖 | LE1–LE5（主体，60–70%） | LE6（收尾） |

> 术语对照：**内循环**对应你天天在 Claude Code 里看到的"它自己读文件、改代码、跑测试"的转圈；**外循环**对应你用了它一阵子之后，回头改 `CLAUDE.md`、调提示词、让它下次更顺——那也是一种循环，只是一圈要好几天。

记住这张表。本课的结构就是：**先把内循环的五个旋钮一个个拧好（LE1–LE5），最后拉远镜头看外循环（LE6）。**

---

## 2. 原理："智能"到底藏在哪里

新手最大的错觉是：agent 聪不聪明，取决于模型聪不聪明。

但 L0–L3 那条线已经反复印证了一个反直觉的结论——**"AI 会自主做事"的魔法，几乎都不在模型里**：

- 模型本身只会"想一步、说一句、然后停下"（无状态、动一下就僵）。
- 是 harness 的**循环**，一遍遍把它喊回来继续干。
- 同一个模型，配一个设计粗糙的循环 = 又慢又跑偏又烧钱的废物；配一个设计精良的循环 = 靠谱的 agent。

换句话说：**给定模型之后，agent 好不好用，主要由循环怎么转决定。** 这就是为什么"循环工程"配得上单独一门课——它是给定大脑之后，你唯一能亲手设计、且决定成败的那一层手艺。

> 原理一句话：**智能不在模型里，不在单次调用里，而在"循环怎么转"里。** 模型提供"每一步的判断力"，循环提供"把判断力组织成完成任务的结构"——后者才是工程。

## 4. Claude Code 锚点：你其实天天在看这两个循环

| 你在 Claude Code 看到的 | 是哪个循环 |
|---|---|
| 派个活，它自己读文件、改代码、跑测试、看报错、再改，一步步推进 | **内循环**在转（LE1–LE5 讲的就是这一圈怎么设计好） |
| 它"卡住绕圈"或你按 Esc 打断 | 内循环的**停止/预算**旋钮（LE2）在起作用 |
| 你用了它几周后，回头把 `CLAUDE.md`、提示词、工作流改得更顺手，它下次明显更好用 | **外循环**在转（LE6 讲怎么把这件事做得系统、不靠玄学） |

下次用它干活，试着同时意识到两层：眼前这一圈圈是内循环；你这阵子让它越来越顺手的过程，是你自己在手动跑外循环。本课就是把这两件你已经在做、但凭直觉做的事，变成有旋钮、有套路的工程。

## 5. 小练习 / 思考题

1. 用自己的话说清：内循环和外循环的**时间尺度**和"转一圈做什么"各是什么？
2. 各举一个你在 Claude Code（或任何 agent 产品）里见过的内循环、外循环的例子。
3. 为什么说"给定模型之后，agent 好不好用主要由循环决定"？这对"想做出好 agent 该把精力花在哪"有什么启发？
4. 本课为什么把 80% 篇幅放在内循环、只用一章讲外循环？（提示：从"市面上缺什么资料"和"内循环是地基"两个角度想。）

<details>
<summary>参考答案</summary>

1. 内循环：**秒级**，发生在单个任务**内**，一圈 = 模型走一步→执行工具→看结果→再走一步。外循环：**天/周级**，发生在许多任务**之上**，一圈 = 跑一批任务→看失败→改 prompt/工具/外壳→再跑。
2. 内循环例：让它"加个功能并跑通测试"，它自己读改跑循环推进。外循环例：你发现它总在某类任务上犯同样的错，于是在 `CLAUDE.md` 里加一条规则，下次它就不犯了——这一改一验就是外循环转了一圈。
3. 因为模型本身只会"走一步就停"，是循环把这些步组织成"完成任务"。同一个模型，循环设计的好坏直接决定 agent 又慢又跑偏还是靠谱高效。启发：想做好 agent，**别只盯着换更强的模型，要把精力花在循环设计上**——那是你能亲手掌控、且杠杆最大的一层。
4. 内循环是地基（外循环改进的也是内循环），且市面上把内循环各个旋钮拼成一张进阶图的系统资料几乎没有；外循环虽重要，但概念相对独立、一章能讲清其骨架，故收尾即可。

</details>

## 一句话带走

> **循环是 agent 的本质：模型只提供"每一步的判断力"，是循环把判断力组织成"完成任务"。循环有内（秒级·单任务内）外（天周级·跨任务）两个尺度——本课先把内循环的五个旋钮逐个拧好（LE1–LE5），再拉远镜头看外循环（LE6）。从下一章起，我们开始拧第一个旋钮：循环的形态。**

下一章 **LE1 循环的形态选型**：同一个任务，循环的骨架可以长得很不一样——是"边想边做"还是"先规划后执行"？这是你要拧的第一个、也是最大的一个旋钮。
