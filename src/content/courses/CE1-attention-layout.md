# CE1 · 位置与注意力布局

> 本章目标：磨亮**杠杆①——位置布局**，把 CE0 那张办公桌从"装多少"升级到"怎么摆"。这是 L4 里一笔带过的"**位置即权重**"那段的正式展开：同一份资料，摊在桌子的不同位置，模型"看见"的程度天差地别。本章是你磨任何一把刀之前都要先懂的底层地形。
> 拧的旋钮：① 位置布局（layout）——最廉价、却最被忽视的一把。

---

## 0. 先讲一个画面

CE0 把上下文窗口立成了一张办公桌，还给你看了它的分区图。现在做一个更小、也更扎心的实验。

桌上要摊三样东西：一条**最关键的指令**（"所有金额必须保留两位小数"）、四十页**背景资料**、一段**当前任务**。它们的字一个没变，只是摆放位置换了换：

- **摆法甲**：关键指令钉在桌子最上沿，当前任务摆在离你最近这端，四十页背景压在中间。→ 模型一抬头看见规则，一低头看见任务，干得又准又稳。
- **摆法乙**：关键指令随手夹进了那四十页背景的第十九页。→ 模型把金额写成了三位小数。你回头翻，发现指令明明"给了"——它就躺在桌上，只是躺在了模型的**视觉盲区**里。

一个字都没改，一行信息都没删。变的只是**坐标**。但模型的表现，从"靠谱"滑到了"漏看关键规则"。

> 这就是本章要钉死的事实：**在上下文这张桌子上，位置本身就是一种权重。** 你不只是在决定"给模型看什么"，你同时在决定"它有多大概率真的看见"。而调整位置，是所有上下文手段里**最不花钱的一个**——不删一个 token、不调一次模型，只是换个座位。最廉价，所以也最常被忽视。

## 1. 核心概念：四个词，讲清这张桌子的地形

| 概念 | 一句话 | 办公桌类比 | 你能拿它干嘛 |
|---|---|---|---|
| **位置即权重**（position = weight） | 信息放在哪儿，直接影响模型分给它多少注意力 | 桌上同一张纸，摆在眼皮底下和压在纸堆里，被读到的概率完全不同 | 把"重要"翻译成"放在高权重位"，不靠喊也能让模型重视 |
| **中间遗忘**（lost in the middle） | 模型对窗口**开头和结尾**最敏感，对**中段**容易视而不见 | 读一摞长文档，最后只记得头几页和尾几页，中间糊成一片 | 别把关键信息埋进中段；中段留给"次要、可糊"的内容 |
| **信息排序**（ordering） | 同一批信息，排列顺序会改变模型实际利用它的效果 | 同样几张纸，按"规则在上、任务在下"摆，比乱摞一气好用 | 主动给信息排座位，而不是"来什么塞什么" |
| **稳定前缀**（stable prefix） | 让上下文的**开头那一段固定不变**，能被缓存复用，省钱又省延迟 | 桌子最上沿那块"常驻牌"——每天开工都在那儿，不用重新摆 | 把不变的规则/角色钉死在最前面，别每轮都改动开头 |

这四个词里，前两个讲**地形长什么样**（哪儿是焦点、哪儿是盲区），后两个讲**你怎么利用地形**（怎么排、怎么把开头固定下来省钱）。下面两节分别展开。

> 一句话先记住：**开头和结尾是模型的目光焦点，中段是它的盲区。** 上下文布局的全部手艺，就是围着这条曲线排座位。

---

## 2. 原理"为什么"：模型的注意力是一条 U 形曲线

为什么开头结尾被偏爱、中段被冷落？不用钻进数学，两句话的浅层归因就够你用：

**归因一：注意力机制天生偏爱两端。** 模型读上下文，靠的是**注意力（attention）**——一种"在所有文字之间互相打分、决定谁该多看一眼"的机制。它不是均匀地扫过每个 token，而是把注意力**不均匀地**分配出去。大量观测发现，这种分配呈现一条 **U 形曲线**：开头和结尾分到的注意力高，中段塌陷下去。这就是"位置即权重"最直接的来源——你的信息落在 U 形的哪一段，就大致决定了它能分到多少"目光"。

**归因二：训练分布强化了这个偏好。** 模型见过的海量文本里，**开头**往往是设定、主旨、最重要的交代（文章首段、对话的角色设定），**结尾**往往是结论、最新进展、当下要回应的那句话。于是模型在训练中养成了一个稳固的习惯：**到开头找"总纲"，到结尾找"现在该干嘛"**，而把中段当成可以略读的"填充"。

这两条凑起来，就是 CE0 里那个最阴险的家伙——**中间遗忘**——的根。它阴险在：信息明明"给了"，却被悄无声息地漏看，不像"溢出"那样报错提醒你。

> 类比收口：把模型想成一个**读一摞长文件的人**。他一定认真读了**第一页**（这是讲啥）和**最后一页**（结论 / 现在要我做什么），中间几十页则一目十行。你要让他记住一条铁律，是夹进中间第十九页，还是印在封面和封底上？答案不言而喻。**位置布局，就是替模型决定哪些信息上"封面封底"。**

## 3. 工程手艺：怎么给信息排座位

懂了 U 形曲线，落地就只剩三条可操作的动作。它们都不花钱——不删 token、不换模型，只动坐标。

**手艺一：最重要的指令，放开头（钉进 system）。**
长期、全局、不可违反的规则——角色设定、硬约束、输出格式、工具说明——属于 system 区（系统提示词，对话最开头那一段，模型每轮都先读到它）。这是 U 形左端、最高权重位。"金额保留两位小数"这种铁律，写在这里，远胜于在第十九轮对话里临时说一句。

**手艺二：当前最关键的信息，放最近（贴着结尾）。**
"此刻要解决的问题""刚检索回来的那段事实""用户最新一句话"——这些属于 U 形右端。模型读完会立刻拿它行动，放这儿利用率最高。一个常见反模式：把刚捞回来的关键资料塞在一大段历史的**前面**，结果它沉进了中段盲区——应该贴着结尾放。

**手艺三：次要信息，压进中段（或干脆别放）。**
背景资料、几十轮的旧历史、"可能用得上"的参考——它们注定分不到多少注意力，正好安置在中段这个盲区。但要清醒：**中段是盲区，不是保险箱。** 真正关键的东西放进去等于没放。中段堆得越满，两端的信号被稀释得越厉害——这就接上了 CE2 要讲的裁剪：与其把次要信息硬塞中段，不如先问它"配不配进来"。

**手艺四（省钱专用）：保持前缀稳定，复用缓存。**
模型处理上下文时，会把开头那段算出的中间结果**缓存**起来（即 **KV-cache**，键值缓存——你可以理解为模型为"已经读过的开头"做的一份草稿，下次开头没变就直接拿草稿用，不必重算）。这意味着：**只要你的开头一字不变，这段就能命中缓存——省一大笔重复计算的钱、也省延迟。**

> 由此引出一条反直觉但极值钱的纪律：**不要在每轮里改动上下文的开头。** 哪怕只在 system 顶部插一句"现在是 2026 年 6 月 15 日 14:03"这样的动态信息，都会让它后面的缓存全部失效、整段重算。把不变的钉在最前（稳定前缀），把易变的尽量往后放——这是布局手艺里**唯一直接关乎账单**的一条。

把四条缝成一句口诀：**铁律钉开头，急活贴结尾，杂物压中段，开头别乱动。**

## 4. 结构图：U 形曲线与桌面分区

把 CE0 那张分区图，叠上本章的"注意力权重"这一层，就成了这张图：

   ┌──────────┐    ┌────────────────────────┐  ┌──────────┐
   │①铁律/角色 │    │②次要信息·旧历史·背景    │  │③此刻要紧 │

读图要点：这条 U 形曲线，就是你排座位时脑子里要随时悬着的那张"地形图"。**重要的往两端的高坡上放，次要的往中间的低谷里塞，而最前那一截要焊死不动以复用缓存。** 后面每一把刀（裁剪、压缩、检索、外部记忆）操作的，都是这同一张曲线上的座位。

## 5. Claude Code 锚点：它每一轮都在替你排座位

CE0 教你把日常现象翻译成"哪把刀"。本章再加一层透视——同样这些动作，背后都在利用这条 U 形曲线：

| 你看到 / 做的 | 背后的位置布局动作 | 对应本章概念 |
|---|---|---|
| `CLAUDE.md` / memory 文件被注入对话**最开头** | 把长期规则钉进 **system 区（U 形左端·高权重）** | 位置即权重 / 钉开头 |
| 你的**最新一句话**永远在 messages 末尾 | 当前最要紧的指令贴着 **结尾（U 形右端·高权重）** | 急活贴结尾 |
| 系统提示词、工具定义每轮**一字不变**地出现在开头 | 维持**稳定前缀**，让开头命中 KV-cache，省钱省延迟 | 稳定前缀 / 缓存复用 |
| 它把刚 `Read` 回来的关键文件内容放在**临近你提问处** | 把急用的事实贴近结尾，避免它沉进中段盲区 | 急活贴结尾 |
| 用久了、历史很长后，它对**早期对话里某条约定**像没看见 | 那条约定沉进了**中段盲区**，触发中间遗忘 | 中间遗忘（→ 该 CE3 压缩 / CE5 卸载） |
| 你被建议"把长期约定写进 `CLAUDE.md` 而不是每轮重复说" | 把规则一次性钉上高权重的稳定前缀，而非反复扔进中段 | 钉开头 + 稳定前缀 |

> 透视练习：下次看它干活，盯住两件事——**开头那段是不是每轮都没变**（稳定前缀在省你的钱），以及**它会不会漏看很久以前你说过的某条规则**（中间遗忘在偷偷发生）。看懂了，你就知道为什么"重要的话要么钉进 `CLAUDE.md`、要么在最近重说一遍"，而不是指望它记得三十轮前那句。

## 小练习 / 思考题

1. 用 U 形曲线解释 0 节那个实验：同一条"金额保留两位小数"的指令，为什么夹进背景第十九页就被漏看，钉到桌子上沿就被遵守？
2. "位置即权重"这把刀，为什么说它是**最廉价**的一把？（提示：和裁剪、压缩比，它动了什么、没动什么？）
3. 你刚用工具检索回一段关键事实，准备让模型据此作答。该把它放在上下文的哪一端？放错会怎样？
4. 同事说："我每轮都在 system 提示词顶部自动插一句当前时间戳，挺贴心的。"从**稳定前缀 / 缓存**的角度，这么做有什么隐性代价？怎么改？
5. 中段是模型的注意力盲区。那是不是"凡是不重要的就往中段一塞"就万事大吉了？这个想法有什么风险？（提示：盲区不是保险箱，且它会稀释两端。）

<details>
<summary>参考答案</summary>

1. 模型的注意力呈 U 形：开头、结尾高，中段塌陷。第十九页正落在中段盲区，分到的注意力极低，于是被"视而不见"（中间遗忘）；钉到上沿则落在 system 区、U 形左端的高权重位，模型每轮先读到、稳稳遵守。一个字没改，变的只是它在曲线上的坐标。
2. 因为它**不删任何信息、也不换模型**——裁剪要扔掉 token、压缩要承担丢细节的代价、换模型更是动不了，而位置布局只是把同一批 token 换个座位（坐标）。零信息损失、零额外算力，纯靠"摆放"就改变了模型的利用率，所以最廉价；也正因为太朴素，最常被忽视。
3. 放在**最近、贴着结尾**（U 形右端高权重位），模型读完会立刻拿它行动，利用率最高。若放错——塞在一大段历史的前面——它会沉进中段盲区被漏看，等于检索白做。
4. 隐性代价：时间戳每轮都变，它一变，它**后面的所有缓存全部失效**，整段开头被迫重算——多花钱、多花延迟，稳定前缀的好处全丢了。改法：把不变的规则钉在最前保持一字不变（稳定前缀），把这种动态信息挪到上下文**靠后**的位置（贴近结尾），既不破坏前缀缓存，又因为靠近结尾反而权重更高。
5. 不能万事大吉，有两个风险：① **盲区不是保险箱**——一旦你误判，把其实关键的东西塞了进去，它就被悄悄漏看且不报错；② **中段堆得越满，越稀释两端**——大量"不重要但也没扔"的内容会拉低整体信噪比、增加成本。所以正解不是"次要的随便塞中段"，而是先问它"配不配进上下文"——这正是下一章 CE2 裁剪要解决的事。

## 一句话带走

> **位置即权重：模型的注意力是一条 U 形曲线——开头和结尾是目光焦点，中段是盲区（中间遗忘）。所以铁律钉开头（system）、急活贴结尾（最近消息）、杂物压中段、开头焊死别动（稳定前缀，复用缓存省钱省延迟）。这是所有上下文手段里最廉价的一把——不删一个 token、不换一次模型，只换座位——也因此最常被忽视。**

下一章 **CE2 裁剪与筛选**：位置布局解决了"既然信息进来了，摆在哪儿最被看见"。但它有个前提没回答——**这些信息一开始就配进桌子吗？** 既然桌面寸土寸金、每个座位都有权重成本，你得先当一次门卫：进入上下文的每个 token，都要挣得它的位置。这就是第一把真正的刀。
