# LE3 · 六个零件：搭一个 Loop 需要什么

> 本层目标：把五个动作落地到具体的代码和工程中，你需要准备好这六样基本零件。少哪一样，循环都会在某个地方瘸掉。

---

## 0. 先讲一个画面

五个动作描述的是“转一圈发生了什么”，而六个零件描述的则是“你手里得攥着哪些具体的材料，才能把这台自动运转的机器组装起来”。

这就像是拼装一台汽车：你需要发动机提供动力、需要独立车轮防止摩擦、需要说明书固定规则、需要各种接口接电。

我们直接看这六个旧零件，以及它们是如何在新框架下换装组合的。

---

## 1. 六个零件详解

### 零件一：Automations（自动化/调度）
* **是什么**：让 Loop 自己动起来的触发开关。
* **为什么需要**：没有调度，你的系统就只是一次普通的一次性运行，而不是 Loop。它是发动机的点火按钮。
* **开发原则**：在定时任务里，AI 触发的应当是一个**有名字的 Skill 脚本**，而不是贴一整面墙的 Prompt 指令。Skill 容易维护，Prompt 墙不能。

### 零件二：Worktrees（Git 工作区隔离）
* **是什么**：Git 仓库的多目录并行机制。
* **为什么需要**：当你的自跑循环决定同时去修 5 个 Bug 时，如果没有 Worktree 隔离，5 个 Agent 会同时读写同一个目录，发生极其恶劣的文件覆盖冲突。Worktree 让 Agent 独立在自己的分支下改代码，做到“并行且干净”。

### 零件三：Skills（用 SKILL.md 复用项目知识）
* **是什么**：把项目知识、构建命令、踩坑经验固化成一个 `SKILL.md`。
* **为什么需要**：如果不做固化，你每次运行都得重新在上下文里长篇大论地告诉 Agent 这个项目的规矩。这种反复交代的成本，叫做**意图债（Intent Debt）**。Skill 就是用来帮 AI “还这笔债”，每次直接读取即可。

### 零件四：Plugins & Connectors（MCP 连接器）
* **是什么**：基于 MCP（模型上下文协议）连接外部世界的接口。
* **为什么需要**：**“一个只能看见文件系统的循环，是一个极小的循环。”** 它得能查 Jira 工单、能去 staging 环境查数据库、能自动提交 PR、能在 Slack 里给你发消息，这才是真正在做业务。

### 零件五：Sub-agents（生成者与评判者分开）
* **是什么**：把“写东西的”和“评判东西的”拆成两个独立的 Agent。
* **为什么需要**：**“写代码的模型，给自己批作业态度太宽容了。”**（The model that wrote the code is way too nice grading its own homework.） 独立的评判者（Checker）没参与写代码，它没有先入为主的“自我说服”包袱，抓 Bug 容易得多。

### 零件六：Memory（磁盘持久化状态）
* **是什么**：活在单次对话之外的记忆文件（如 `TODO.md` 或任务看板）。
* **为什么需要**：大模型每次会话都会失忆。Memory 必须写在磁盘上，跨轮、跨天、跨整个会话生命周期都存在。有了它，AI 每天清晨开局醒来才不会像失忆一样，而是能接着昨天的进度跑。

---

## 2. 零件与动作对应表

六个零件齐了，一个自跑循环就有了骨架：

| 零件 | 是什么 | 对应动作 | 一句话原话 |
|---|---|---|---|
| **Automations** | 挂在时间表上的触发器 | 调度 | make a loop an actual loop |
| **Worktrees** | 隔离并行的工作目录 | 交付 | same headache as two engineers |
| **Skills** | 固化项目知识，还意图债 | 发现 | fire $skill-name, not a wall of instructions |
| **Connectors** | MCP 外部连接器 | 发现 / 持久化 | only see the filesystem is a tiny loop |
| **Sub-agents** | 生成与验证角色分离 | 验证 | too nice grading its own homework |
| **Memory** | 磁盘上的持久化状态文件 | 持久化 | the agent forgets, the repo doesn't |

---

## 3. 小练习 / 思考题

1. 在开发中，你遇到过哪些因为反复交代背景规则而欠下的“意图债”？写一个 `SKILL.md` 能解决它吗？
2. 为什么说“Memory（持久化记忆）”不是“Context（上下文）”？它们有何本质区别？
3. MCP（Model Context Protocol）连接器是如何决定你的 Loop 它的“视野半径”的？

---

## 一句话带走

> **一个能自动转的 Loop 依靠六个零件组装而成：Automation 负责启动，Worktree 负责并行防打架，Skill 负责复用规矩还意图债，Connector 负责扩宽视野接通外部，Sub-agents 负责角色分离揪错，Memory 状态文件则充当它跨运行不失忆的磁盘脊柱。**
