# L5 · 跨会话记得你：记忆系统

> 本层目标：让 agent 拥有"跨会话、跨天"的长期记忆——记得你是谁、你的偏好、上次进行到哪。
> 对应修补缺陷：**① 无状态（健忘）的终极版**。你会看到：记忆不是模型的新能力，
> 而是上下文工程（L4）的一个特例——"该把哪条往事，在对的时刻捞回桌上"。

---

## 0. 先讲一个画面

L4 我们把上下文比作一张办公桌——但桌子有个致命问题：**下班就清空。** 你今天和 agent 深聊三小时定下一套方案，明天开新会话，它一脸茫然："你是谁？我们聊过吗？"（L0 缺陷①的原形毕露）。

人类靠什么跨越"今天的桌子"和"明天的桌子"？靠一本**笔记本**：重要的事记下来，第二天上班先翻一翻，把相关的几条**重新抄到今天的桌上**。

**记忆系统（memory）就是给 agent 配的这本笔记本 + 那个"翻笔记、抄回桌上"的习惯。** 模型本身依旧失忆——是 harness 在它每次"上班"时，悄悄把该记得的往事捞回上下文。

---

## 1. 模型缺了什么：会话一结束，一切归零

L1 讲过，"记忆"其实是 harness 把 messages 列表重发造成的假象。但这个假象有个硬边界：**会话结束、列表清空，假象就破灭。** 下次开新会话，messages 从空白开始，前面所有积累荡然无存。

L4 的四把刀都只在**单次会话/任务内**经营桌面，管不到"跨会话"。于是需要一种**会话之外、持久存在**的存储，以及一套"何时写、何时读"的机制。这就是记忆系统要补的洞——把"一次性的桌面"升级成"有长期档案支撑的工作台"。

---

## 2. 这层怎么补：先分清三种"记得"

"记忆"是个被滥用的词。先用两个维度把它切清楚，否则后面全是糊涂账。

**维度一：能存多久？**
| 类型 | 范围 | 例子 | 本质 |
|---|---|---|---|
| **短期记忆** | 单次会话内 | 当前对话历史、本次任务的中间结论 | 就是 L1 的 messages 列表 + L4 的上下文管理 |
| **长期记忆** | 跨会话、持久 | 你的名字、长期偏好、过往项目结论 | 存在窗口**外面**的持久存储，本层重点 |

**维度二：记的是什么内容？**（长期记忆常再分两类）
| 类型 | 记什么 | 例子 |
|---|---|---|
| **事实/语义记忆** | 关于你和世界的稳定事实 | "用户是产品经理""用户偏好中文、简洁" |
| **情景记忆** | 发生过的事件 | "上次我们把方案改成了 B""3 月那个 bug 是这样修的" |

> 把这张表记住，你听任何关于"AI 记忆"的讨论都不会被绕晕——先问"它说的是短期还是长期？事实还是情景？"

### 长期记忆的工作闭环（四个动作）

记忆系统就是围绕一份**外部存储**（一个文件、一个数据库、一个向量库）做四件事：

```
   写入(Write) ──→ 把值得记的事提炼成条目，存进外部档案
   检索(Retrieve) ─→ 新会话开始/需要时，捞出相关条目，注入上下文(回到 L4!)
   更新(Update) ──→ 事实变了就改写旧条目(别让"过期记忆"误导)
   遗忘(Forget) ──→ 删掉过时/错误/无关的，别让档案无限膨胀变噪声
```

**关键点①——"写什么"是门取舍。** 不能把每句话都记成长期记忆（那等于没重点）。好系统只记"未来会反复用到、且无法从别处推出"的东西：稳定偏好、关键决定、踩过的坑。**这正是你刚装的 Superpowers/Claude Code memory 里那套规则在做的事**——只记"非显而易见、跨会话有用"的事实。

**关键点②——"检索回上下文"就是 L4。** 记忆的"读"这一步，本质是 RAG/检索注入：从外部档案里捞出与当前最相关的几条，塞进 messages。**所以记忆不是独立魔法，是 L4 上下文工程在"跨会话往事"上的应用。** 看穿这点，你就真懂了。

---

## 3. 底层原理：记忆 vs 上下文 vs RAG，一次厘清

这三个词最容易混。一张图钉死它们的关系：

```
            ┌──────────── 上下文窗口(L4 的办公桌，模型唯一能看见的地方) ──────────┐
            │  system  │  最近对话  │  ←这里临时摊着的，才是模型"当下看得见"的  │
            └────────────────────────────────────────────────────────────────────┘
                          ▲                         ▲
              "捞相关往事回来"               "捞相关知识回来"
                          │                         │
            ┌─────────────┴──────┐      ┌───────────┴────────────┐
            │  记忆(Memory)       │      │  知识库(RAG 的来源)      │
            │  关于"你/历史"的档案 │      │  关于"领域知识"的文档库   │
            │  例:用户偏好、过往决定│      │  例:产品手册、公司文档    │
            └────────────────────┘      └────────────────────────┘
                外部持久存储，窗口装不下的都放这儿，用到才捞回上面
```

- **上下文（L4）**：模型当下唯一能看见的那张桌子。临时、有限、会清空。
- **记忆（L5）**：关于**"用户与历史"**的持久档案，按需捞回上下文。
- **RAG**：技术手段（按需检索注入），既服务于知识库，也服务于记忆——**记忆在实现上常常就是"对一个记忆库做 RAG"**。

> 一句话原理：**唯一真正"被模型看见"的永远只有上下文这张桌子。记忆和 RAG 都只是不同的"抽屉"，靠检索这个动作把内容搬上桌。** 模型从头到尾没长出新记性——是 harness 的"档案管理 + 按需调取"在制造"它记得我"的体验。

**一个常被忽略的代价：记忆会"骗"你。** 存下的事实会过期（你换了工作，旧档案还写着老职位），错误的记忆比没有记忆更危险——它会自信地误导。所以"更新"和"遗忘"不是可选项，是记忆系统的必备保养。

## 4. Claude Code 锚点：你刚刚就在用记忆系统

这一层你有最鲜活的实物——**这次会话里你装 Superpowers、定课程骨架，背后那套 memory 机制正是教科书级的长期记忆**：

| Claude Code / Superpowers 的记忆设计 | 对应本层概念 |
|---|---|
| `~/.claude/.../memory/` 下一个个 `.md` 文件，每个存一条事实 | 长期记忆的**外部持久存储**（笔记本本体）|
| `MEMORY.md` 索引，每条一行摘要 | 记忆的**目录/检索入口**——先看目录决定捞哪条 |
| 每条记忆有 `type: user/feedback/project/reference` | 给记忆**分类**（≈事实记忆 vs 情景记忆的工程化）|
| 新会话开始时相关记忆被注入（你看到的 `<system-reminder>` 里那些） | **检索 → 注入上下文**（就是 L4/RAG 那一步）|
| 规则强调"只记非显而易见、跨会话有用的，别记代码里已有的" | **"写什么"的取舍**——避免把档案塞成噪声 |
| 提示"记忆反映写入时的情况，引用的文件/函数要先核实还在不在" | 直面**记忆会过期**的代价，对应"更新/遗忘" |

下次你对 Claude Code 说"记住我喜欢简洁的回答"，你现在能完整说出背后发生了什么：harness 把这条提炼成一个记忆文件（写入），在 `MEMORY.md` 加一行（更新索引），未来新会话开始时把它检索注入上下文（读取）——于是"它记得你"。模型一如既往地失忆，是这套档案系统在替它记。

## 5. 小练习 / 思考题

1. 你和 agent 今天定了个方案，明天开新会话它却忘了。请用 L1 的"messages 重发"机制解释它**为什么**会忘，再说明记忆系统从哪一步切入来补救。
2. 用两个维度给下面四条信息归类（短期/长期；事实/情景）：(a) 本次对话第 3 轮的结论；(b) "用户是产品经理"；(c) "上次我们选了方案 B"；(d) 当前正在改的文件路径。
3. 一句话说清"记忆"和"RAG"的关系——它们是对立的两种东西，还是有包含/复用关系？
4. 为什么说"错误的长期记忆比没有记忆更危险"？这对应记忆闭环里哪两个必须做的动作？
5. 自检：默写长期记忆的四个动作（写/读/更新/忘），并指出"读"这一步其实就是前面哪一层的技术。

<details>
<summary>参考答案</summary>

1. 忘的原因：新会话的 messages 列表从空白重建，昨天那串历史没被重发，模型（本就无状态）自然什么都不知道。记忆系统从**"写入"**切入——昨天把关键结论存进外部文件；再在今天新会话的**"检索注入"**步把它捞回上下文，模型才"记得"。
2. (a) 短期·情景；(b) 长期·事实；(c) 长期·情景；(d) 短期·事实。
3. 有**复用关系**，不对立。记忆在实现上常常就是"对一个记忆库做 RAG（检索注入）"——RAG 是手段，记忆是这个手段服务的对象之一（另一个是领域知识库）。
4. 因为模型会**自信地**采用上下文里的信息，过期/错误的记忆会被当成事实来误导决策，比"没有、于是会去问/查"更糟。对应必须做的**更新（Update）**和**遗忘（Forget）**两个动作。
5. 写入、检索（读）、更新、遗忘。"读/检索"这一步本质就是 **L4 的上下文工程 / RAG**——从外部存储捞相关条目注入上下文窗口。

</details>

## 一句话带走

> **记忆不是模型长了记性，而是 harness 给它配了一本笔记本，并养成"上班先翻笔记、把相关几条抄回桌上"的习惯。看穿这点你就懂了：记忆 = 持久外部档案 + 在对的时刻把对的往事检索回上下文（L4）。模型永远失忆，记性在外壳里。**

下一层 **L6 子代理与编排**：到这儿我们的 agent 已经能行动(L2)、能持续(L3)、能装载(L4)、能记忆(L5)——但它始终是**一个** agent。当任务大到一个脑子的桌子摊不下，怎么办？答案是：把一个 agent 变成一支会分工协作的团队。
