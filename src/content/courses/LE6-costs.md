# LE6 · 代价：验证债、理解腐烂与 Token 失控

> 本层目标：直面自跑循环背后的残酷代价。天下没有免费的午餐，一个没有人看着的循环，也是一个没有人看着在犯错的循环。这门课将为你算清这四笔账。

---

## 0. 先讲一个画面

你搭好了一个顺滑的 Loop，每天晚上它自己悄悄开工。
第二天早上你醒来，发现测试全绿，它自动改了 20 个文件，并自动把代码提交合并了。你感觉自己像是一个拥有了百人团队的 CEO，喝着咖啡享受着极速开发的爽感。

然而，在这个看似完美的画面背后，有一些隐秘的债务正在悄悄积累。
直到某个上线的清晨，所有平时没测出来的死角一起崩溃，你火急火燎地打开代码文件，却发现里面的实现对你来说就像天书一样，而你的 API 账户里刚收到一张数千美元的透支账单。

这就是**无节制防线的自跑循环**必然会送给你的四笔账单。

---

## 1. 自动化的四笔账单

### 账单一：验证债（Verification Debt）
* **症状**：产出堆着没人验，错误安静地积累。
* **起因**：你让循环自己改代码、自己合并。每一步看似省下了你的时间，但其实并没有真的消失，它变成了一堆“还没被人类验证过”的产出堆在那里。
* **名言**：**“The hard part of a loop is not the loop. It is putting something inside it that can say no.”**（循环的难点不在循环本身。难的是往里面放一个能说‘不’的东西。）
* **防范**：必须强行引入 Maker/Checker 隔离机制，不要让干活的模型自己签字结业。

### 账单二：理解腐烂（Comprehension Decay）
* **症状**：代码在不断增长，但你脑子里的项目地图停留在三个月前。
* **起因**：**“The faster the loop ships code you did not write, the bigger the gap between what exists and what you actually get.”**（循环交付你没写的代码越快，实际存在的东西和你真正理解的东西之间的缺口就越大。）
* 由于写代码无聊的部分全被 AI 包了，人自然就懒得一行行去读了。时间一长，你对自己的项目已经变成了一个外人。
* **防范**：强迫自己定期去阅读循环产生的 PR，别看单元测试过了就直接闭眼合。挑几个改动，自己跟自己讲一遍它改了什么。如果讲不出来，说明你的大脑地图已经腐烂了。

### 账单三：认知投降（Cognitive Surrender）
* **症状**：循环给啥就收啥，懒得有自己的意见。
* **起因**：**“When the loop runs itself its very tempting to stop having an opinion and just take whatever it gives back.”**
* 持续判断是很累的。每个 PR 都要自己想一遍对不对，比直接点“Merge”累多了。AI 越可靠，你就越倾向于直接相信它。这种自我麻痹会逐渐剥夺你的架构师判断力。
* **防范**：保住一条底线——**执行可以外包，但拿主意绝对不行**。

### 账单四：Token 失控（Token Runaway）
* **症状**：用量剧烈波动，账单不可预测。
* **起因**：自跑循环会自己起子代理、自己重试。一旦代码里出现一个死循环的 Bug，或者在深夜里逻辑死锁，它会毫无疲倦地在后台转上几万圈，一夜之间把你的 API 限额彻底烧光。
* **防范**：上线前必须订死硬天花板——**单次预算限额、每日消费额度、最大重试次数**。宁可让它报错熄火，也不能让它把房子烧光。

---

## 2. 四笔账单防范对照表

这四笔账都有一个共同点：它们在循环跑的当下绝不会报警。

| 代价 | 核心症状 | 一句话防它 |
|---|---|---|
| **验证债** | 产出堆着没人验，潜在错误悄悄积累 | 装一个与干活的不是同个模型的独立评判者 |
| **理解腐烂** | 代码不断长大，你对项目感到陌生 | 定期精读产出的 Diff，能讲清它是怎么改的 |
| **认知投降** | 失去判断，AI 吐出什么就闭眼合 | 谨记：执行可以外包，主意绝对不行 |
| **Token 失控** | 用量剧烈震荡，深夜空转账单爆表 | 上线前在 Harness 里订死每日预算和重试上限 |

## 3. 小练习 / 思考题

1. 当 AI 每天替你自动开 10 个 PR 时，你该如何安排你自己的“代码精读”节奏，防范“理解腐烂”？
2. 为什么说“认知投降”是一个会自我加速的滑坡？我们怎么在制度上给自己留一扇门？
3. 在你的 Loop 中，如果因为单元测试没写好导致 AI 在半夜死循环修改代码，你该设定哪些硬指标防范 Token 烧光？

---

## 一句话带走

> **无人看管的自跑循环等于无人看管地犯错。它会悄悄累积未经验证的“验证债”，拉大代码量与你脑中理解力的“理解腐烂”缺口，并诱惑你走向放弃思考的“认知投降”，甚至在深夜死循环烧光 Token。省下的时间，必须花一部分在替自己守住这四道关卡上。**
