## 一、执行摘要

`video_tool` 是一个 PyQt5 桌面工作台应用（"掌镜使 · 批量短视频自动生产工具" v1.1.0），集成了 **8 个主要功能页面**，通过侧边栏导航切换。此外还有 **4 个独立/半独立的子项目文件夹**（`image create`、`文案提取工具`、`video cut design`、`auto`）。

核心功能链路为：**文案输入 → TTS语音合成 → 智能分段 → 视频混剪 → 字幕叠加 → 批量发布**。几乎所有功能都依赖 FFmpeg、火山引擎 API（TTS/ASR）和 PyQt5 桌面框架。

本报告识别出 **12 个候选工具**，其中 **3 个已为独立子项目**，**5 个推荐拆分为 web 工具或独立项目**，**4 个不推荐当前拆分**（桌面/GUI 重度耦合）。

#### 优先级 P0：低风险、网站友好、已有独立基础

##### 1. 文案提取工具

- **推荐形态**: `already separate candidate`
- **目标目录**: `J:\MagicTool\个人网站\tools\抖音文案提取`
- **源文件**: `文案提取工具/`（完整独立项目）

- **建议操作**: 直接将 `文案提取工具/` 内容迁移到目标目录，考虑将 UI 从 PyQt6 改为 Web（Flask/FastAPI + 前端）以适合网站工具集。

## 八、风险与后续步骤

### 已知风险

1. **抖音 API 反爬**: 链接采集和下载依赖 cookie 认证，抖音反爬策略变化可能导致功能失效。
2. **pyautogui 脆弱性**: 自动发布使用硬编码屏幕坐标，任何分辨率/软件版本变化都会导致失败。
3. **火山引擎 API 费用**: TTS 和 ASR 是按量付费的云服务，Web 化后需考虑用量控制和计费。
4. **FFmpeg 依赖**: Web 化后的视频处理需要服务端安装 FFmpeg，增加部署复杂度。
5. **PyQt → Web 迁移成本**: 大部分 UI 是 PyQt5/PyQt6，迁移到 Web 需要重写所有前端代码。
6. **faster-whisper 部署**: 对标采集的本地 ASR 需要 GPU 环境，不适合轻量 Web 部署。

### 推荐后续步骤

1. **确认目标架构**: 确定"个人网站工具集"的技术栈（纯前端/Flask/FastAPI/Electron），这会决定拆分策略。
2. **优先迁移已有独立项目**: `文案提取工具` 和 `image create` 两个子项目可以最快出成果。
3. **制定 Web 化方案**: 对于需要 Web 化的功能（视频下载、链接采集），先设计 API 接口再迁移代码。
4. **评估 API 成本**: 联系火山引擎确认 TTS/ASR/视觉 API 的费率和配额。
5. **重构 video_composer.py**: 49KB 的单文件混合了视频合成、字幕、BGM、任务队列等多种职责，建议先重构再拆分。
6. **替代 pyautogui**: 研究易媒助手或抖音开放平台的官方 API，取代脆弱的屏幕自动化方案。
